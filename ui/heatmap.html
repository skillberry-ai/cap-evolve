parsec — per-task heatmap

Optimization target: the parsec aap2 sub-agent's SKILL.md (capabilities: [system-prompt]). Agent: Sonnet-4. Harness: Harbor tasks against a kaegis simulated AAP2/GitHub/Babylon/provisions-db fixture set. Two independent benchmark generations are shown, and they are not comparable to each other — different tasks, different scoring schema, different trial counts:
v1 — 30 tasks extracted from real prod0 AAP2 job traces; reward = gate · (0.5·trajectory + 0.5·assertions); 2 of the 30 went through cap-evolve. v2 — 10 hand-authored tasks with per-task answer contracts (schema bench/v2); reward = gate · (wtc·tool_calls + wans·answer) with weights that vary per task; all 10 went through cap-evolve.
Click any task name for its report — what changed, what worked, what didn't, what we can (or can't) learn. See reports/README.md.

Read the v2 section with this in front of you. The seed SKILL.md is byte-identical across all nine runs on this page, so every seed measurement below is a measurement of the same artifact. On v2's ten tasks it measured 0.910 · 0.876 · 0.749 · 0.662 · 0.643 depending on trial count and run — a spread of 0.267, against a headline accepted improvement of +0.086. v1 reached the same conclusion first and wrote it down ("N=10 is not enough") after seeing its own seed move 0.203 between two n=10 measurements. v2 then ran at n=9 with the significance gate loosened from gate_k_se: 1.0 to 0.2. The v2 improvement is inside its own baseline's noise band. Full derivation: results/v2/summary.md, and the ladder table at the bottom of this page.

The seed ladder — every measurement of the same byte-identical skill

seed/SKILL.md is identical in all nine runs (sha256 ed6e8920…7411, 484 lines). Each row below is therefore a measurement of the same artifact. Rows are grouped by experiment and ordered as the runs happened. The spread row is the max−min within each (experiment, split) group — read it against the accepted Δ for that experiment.

conv — which denominator reproduces cap-evolve's own reported figure from the raw per-trial rewards: valid = errored trials dropped, all = errored trials counted as 0.0, either = nothing errored so the cell cannot distinguish them. Both valid and all appear in this table, in different runs, for the same kind of aggregate — v1's headline val/seed drops 16 errored trials from the denominator, v2's headline train/seed_train counts 8 of them as zeros. That is an open question about cap-evolve, not a diagnosis; see results/README.md.
superseded-measurement — a later evaluation in the same run reused this split+tag and overwrote its rollouts, so the reported number is real but cannot be re-derived from what is committed. empty-split — a mean over zero tasks.
