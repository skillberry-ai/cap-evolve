# FRAMEWORK-IMPROVEMENTS — suggestions for cap-evolve itself (cross-run)

NOT about this capability or this run's result — about what cap-evolve the FRAMEWORK should change so FUTURE runs (any capability, any project) go better: a confusing prompt section, a missing tool, a file you wished existed, a gate that felt wrong. Optional most iterations; add an entry whenever something about the framework itself (not the task) got in your way or surprised you.

- The rejection record for cand_0001 gives no cause ("paired Δ̄=-0.6751") — when a candidate scores 0.000 on EVERY task including previously-perfect ones, the framework should distinguish "validation/lint failure" (mechanical, no rollouts) from "behavioral regression" in the RESULT line; the optimizer otherwise cannot tell which edit to drop. Also, prior_iterations/<id>/diff.patch is stored truncated ("...(truncated)"), so the rejected edit cannot be fully reconstructed.
- The surface contract says scripts "cannot be run as a CLI: there is no __main__" while the skill-package guidance requires a `--self-check` entry point "because validation RUNS it" — these two statements conflict; a single authoritative statement about what the validator executes would prevent a candidate-zeroing guess.

## Iteration cand_0003
- Two consecutive candidates were REJECTED at val=0.000 with every task broken, but the gate output names only the tasks — it never says WHY the candidate scored zero (lint failure? smoke failure? placeholder break? package validation?). The optimizer is left guessing at the mechanical cause and must spend an iteration on a controlled experiment. A rejection reason string (e.g. "helper lint failed: script X, rule Y") in rejected.jsonl / the RESULT line would save whole iterations.
- The copied prior_iterations/<id>/diff.patch files are truncated mid-file with a literal "... (truncated)" marker (cand_0002: 58 of presumably hundreds of lines), so the exact edits of rejected candidates cannot be audited. Full diffs (or a size cap raised) would make "keep the edits that did NOT break a task" actually executable.

## Iteration cand_0005
- prior_iterations/cand_0004/diff.patch is 30 lines, contains ONLY the DIAGNOSIS.json hunk, and is cut off mid-line — it does not record the prompt.md/script edits its JOURNAL entry describes. Either the candidate's capability files were never written where the snapshot looked for them (which would ALSO explain a val=0.000 whole-set wipeout: the scored capability may have been empty/invalid), or the snapshot itself is buggy. Worth auditing: the diff recorded for a rejected candidate should cover every capability file the optimizer edited, else the "keep the edits that did not break anything" instruction is impossible to follow.
- The task-list section of the iteration brief truncates the always-failing/flaky lists (said 20, showed 10). Recovering the true list required a script over trajectories; embedding the full list (or a path to a per-task score file) would save every iteration that diagnosis time.
