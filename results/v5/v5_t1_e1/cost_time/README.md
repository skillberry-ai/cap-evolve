# results/v5/v5_t1_e1/cost_time/ — v5_t1_e1's per-task cost and time

The cost/token/wall-clock accounting for **v5_t1_e1** (T1, the original unmodified
PARSEC skill, zero-shot, 5 trials/task, no optimization step), covering all 68 v5
tasks.

Unlike v4's `v4_t_e1/cost_time/` (which vendors a table produced upstream by a
script in the intake worktree, since parsed back into `results.json`), v5 has
no such upstream script. There is one table here,
[`v5_t1_e1_results_table.md`](v5_t1_e1_results_table.md), generated by
[`scripts/build_v5_t1_cost_time_table.py`](../../../../scripts/build_v5_t1_cost_time_table.py)
**from** `../results.json` — a human-readable rendering, not an input to
anything. `results.json` itself is built straight from the vendored
`../source_v5_t1_e1.json` by
[`scripts/build_v5_t1_results_json.py`](../../../../scripts/build_v5_t1_results_json.py).

## What's in the `.md`

One table, one row per task: 5 trial rewards, mean reward + stderr, errored-trial
count, a `saturated`/`ok` headroom tag (reward ≥ 0.95), and that task's total
cost/tokens/wall-clock seconds.

## Where the numbers end up

- `results/v5/v5_t1_e1/results.json` — `task_ledger[].cost_usd` / `tokens` /
  `seconds`, same values, same source.
- `results/v5/v5_t1_e1/summary.md` — the cost + wall-clock narrative section.
- `ui/heatmap_v5_t1_e1.html` — the `reward`/`headroom` columns.
- `reports/v5/v5_t1_e1/*.md` — each task's auto block.

## Caveat this table carries forward

Every row's `cost_usd`/`tokens`/`seconds` is a **sum across the task's 5 trials**,
run at CCC/LSF concurrency 5→10→13 (see
[`../../../../recipes/v5/v5_t1_e1/README.md`](../../../../recipes/v5/v5_t1_e1/README.md)),
so the summed "Wall time" at the top of the table is far larger than the sweep's
actual elapsed wall-clock — it is a cost/budget figure, not a schedule figure.
