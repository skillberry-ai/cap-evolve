## The one-line result

**Mean reward 0.8323**, up **+0.0210** from `v5_b1_e1`'s 0.8114 — but no group (overall or by
origin/task-set/category) clears the **~0.09 per-task noise floor** `v5_b1_e1` measured for this
suite. Read this as **no significant change at the aggregate level**, despite real movement
underneath: 22 of 136 tasks moved up beyond noise, 9 moved down, 105 were flat.

## What this arm is, and isn't

`cand_0004` is v4's accepted G2-arm champion (`best_id_overall` in
[`../../v4/v4_g_e1/results.json`](../../v4/v4_g_e1/results.json)) — one shared 8-file bundle
(orchestrator + 6 domain agents + shared_context) optimized once across all 34 of v4's tasks at
once. This arm installs it on all 136 v5 tasks **unchanged**, with no v5-specific optimization
step, to see whether a skill tuned on a different (smaller, older) task set generalizes to the
rebuilt v5 benchmark before spending any optimizer budget on v5 itself.

**Verified byte-identical** to
[`artifacts/v4/v4_g_e1/best`](https://github.com/skillberry-ai/cap-evolve/tree/parsec-history/artifacts/v4/v4_g_e1/best)
on this branch, via `git hash-object` against that ref's blobs — not vendored again under
`artifacts/v5/`, since the bytes and the path are already here.

## Data quality: audited, with 4 tasks pooled across attempts

Same per-trial audit discipline as `v5_b1_e1`: cap-evolve counts only exceptions it catches
itself, so a gateway hang before the agent's first tool call (`AgentTimeoutError`, 0 tool calls)
reaches the raw ledger as a clean 0.0. Every one of the 680 trials behind this arm's final ledger
was checked against its on-disk harbor record and agent transcript before being counted.

Where `v5_b1_e1` cleared its stragglers by re-running them to a fresh 5-trial batch, 4 tasks here
never produced 5 clean trials in **any single run**, across repeated resubmission — a recurring
gateway-hang pattern, not an artifact of this skill specifically (both arms share the same gateway):

| task | pool size (all attempts) | used |
|---|--:|--:|
| `platform-034-rate-limit-not-an-outage` | 19 | 5 (random) |
| `platform-111-recycled-sandbox-swallowed-teardown` | 12 | 5 (random) |
| `platform-112-exec-pool-disk-not-the-bastion` | 15 | 5 (random) |
| `platform-114-ee-nightly-float-not-a-commit` | 14 | 5 (random) |

For these 4, every individually-audited, error-free trial across **every** attempt on disk for the
task — the live run plus every prior `.dead-*` run — was pooled, and exactly 5 were drawn at
random (fixed seed 20261014,
`scripts/parsec/v5/_pool_valid_trials.py` in the intake worktree) and averaged, rather than
requiring 5-in-one-run or declaring the task a failure. See `source_v5_g2_e1.json`'s `audit` block
for the exact pool composition. **0 of the final 680 trials carry an unresolved infra problem.**
