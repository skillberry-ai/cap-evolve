# results/v5/v5_g2_e1/cost_time/ — the G2-arm reuse's per-task cost and time

Cost/token/wall-clock accounting for **`v5_g2_e1`** (v4's accepted G2-arm champion `cand_0004`,
reused as-is, zero-shot, 5 trials/task, no further optimization) across all 136 v5 tasks.

Same convention as [`../../v5_b1_e1/cost_time/`](../../v5_b1_e1/cost_time/): `../results.json` is
the single source of truth, and
[`v5_g2_e1_results_table.md`](v5_g2_e1_results_table.md) is a human-readable rendering of it,
generated by
[`scripts/build_v5_g2_cost_time_table.py`](../../../../scripts/build_v5_g2_cost_time_table.py).
The dependency runs one way only, so the table cannot drift from the ledger.

## What's in the `.md`

One row per task: its task set and origin, the individual valid trial rewards (all 5, for every
task — 4 tasks' 5 are pooled across repeated attempts rather than from one run, see
`../summary.md`), mean and stderr, `sd`, a `v5_b1` column (that task's reward in the baseline
arm) and `Δ vs b1`, a `move` tag (`up`/`down`/`flat` against the ~0.09 per-task noise floor), and
that task's total cost/tokens/seconds.

## Where the numbers end up

- `../results.json` — `task_ledger[].cost_usd` / `tokens` / `seconds`, same values, same source.
- `../summary.md` — the headline and comparison sections.
- `../../../../ui/heatmap_v5_g2_e1.html` and `../../../../ui/trials_v5_g2_e1.html`.
- `../../../../reports/v5/v5_g2_e1/*.md` — each task's auto block.

## Caveat this table carries forward

Each row's cost/tokens/seconds is a **sum across that task's 5 trials**, and the sweep ran at
10- to 15-way concurrency on CCC/LSF. The summed "task time" at the top is therefore a
cost/budget figure, not a schedule figure. For the 4 pooled tasks, cost/tokens/seconds are summed
over the 5 trials actually used (drawn from across attempts), not every trial run for that task.
