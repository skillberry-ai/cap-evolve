Harbor on OpenShift

End-to-end guide: set up Harbor's OpenShift environment, serve models with vLLM on-cluster, and run cap-evolve optimizations — all on your OpenShift cluster with no external dependencies.

Prerequisites

  • oc CLI logged into your cluster
  • A namespace with GPU nodes (for vLLM) or access to an external model API
  • Harbor CLI (≥ 0.20): uv tool install harbor

Step 1 — Deploy vLLM model server

Skip this step if you're using an external model API (Anthropic, OpenAI, Vertex AI).

# Create the namespace
oc new-project cap-evolve

# Deploy vLLM (example: Qwen 2.5 14B on 2 GPUs)
oc apply -f openshift/manifests/vllm-serving.yaml

# Wait for the model to load (5-15 min on first deploy)
oc get pods -l component=vllm -w

# Verify the endpoint
oc exec deploy/cap-evolve-runner -- \
  curl -s http://vllm-svc:8000/v1/models | python3 -m json.tool

See OpenShift deployment for the full vLLM setup including GPU sizing, model swapping, and the HuggingFace token secret.

Step 2 — Set up RBAC for Harbor

Harbor needs two ServiceAccounts with specific permissions.

Task SA — runs agent containers

Needs a custom SCC that allows runAsUser: 0 and Linux capabilities (CHOWN, SETUID, SETGID, FOWNER, etc.) that agents require inside their containers.

# Apply the task SA + SCC
oc apply -f openshift/manifests/service-account.yaml

# Bind the SCC
oc adm policy add-scc-to-user harbor-task-scc -z harbor-task

Orchestrator SA — manages task pods

Needs RBAC to create/delete pods, builds, image streams, and jobs.

# Apply the orchestrator SA + Role + RoleBinding
oc apply -f openshift/manifests/harbor-orchestrator-sa.yaml

# Also bind the task SCC (orchestrator creates pods that use it)
oc adm policy add-scc-to-user harbor-task-scc -z harbor-orchestrator

Step 3 — Verify Harbor works on the cluster

Run a quick smoke test with the oracle agent (no model needed).

harbor run -d terminal-bench@2.0 -a oracle -e openshift -l 1

You should see Harbor create a BuildConfig, build the task image, run a task pod, and report a reward. If the pod fails with an SCC error, check that Step 2 was completed.

Step 4 — Run Harbor with your agent

The general pattern — works with any agent, any dataset, any model backend.

harbor run \
  -d <dataset> \
  -a <agent> \
  -m <model> \
  -e openshift \
  -n <parallel> \
  --ae <KEY>=<VALUE> ...

With on-cluster vLLM

No external API keys needed — the agent connects to vLLM via the in-cluster Service DNS.

harbor run -d <dataset> -a claude-code -m <model-name> -e openshift -n 5 \
  --ae ANTHROPIC_BASE_URL=http://<vllm-svc>.<namespace>.svc:8000 \
  --ae ANTHROPIC_API_KEY=dummy \
  --ae ANTHROPIC_MODEL=<model-name> \
  --ae ANTHROPIC_DEFAULT_SONNET_MODEL=<model-name> \
  --ae ANTHROPIC_DEFAULT_HAIKU_MODEL=<model-name> \
  --ae ANTHROPIC_DEFAULT_OPUS_MODEL=<model-name>

With Vertex AI

Bind-mount GCP credentials into each task pod.

harbor run -d <dataset> -a claude-code -m claude-sonnet-4-6 -e openshift -n 5 \
  --ae CLAUDE_CODE_USE_VERTEX=1 \
  --ae CLOUD_ML_REGION=<region> \
  --ae ANTHROPIC_VERTEX_PROJECT_ID=<gcp-project> \
  --ae ANTHROPIC_MODEL=claude-sonnet-4-6 \
  --ae GOOGLE_APPLICATION_CREDENTIALS=/app/.config/gcloud/adc.json \
  --mounts-json '[{"type":"bind","source":"~/.config/gcloud/application_default_credentials.json","target":"/app/.config/gcloud/adc.json"}]'

With an Anthropic API key

harbor run -d <dataset> -a claude-code -m claude-sonnet-4-6 -e openshift -n 5 \
  --ae ANTHROPIC_API_KEY=sk-ant-...

With OpenAI / Codex

harbor run -d <dataset> -a codex -m <model> -e openshift -n 5 \
  --ae OPENAI_API_KEY=sk-...

With any OpenAI-compatible endpoint

harbor run -d <dataset> -a opencode -m <model> -e openshift -n 5 \
  --ae OPENAI_BASE_URL=http://<endpoint> \
  --ae OPENAI_API_KEY=...

Step 5 — Run the cap-evolve optimization loop

Once Harbor runs successfully, wire it into cap-evolve's optimization loop via the Harbor adapter.

# Install cap-evolve + Harbor adapter
pip install ./core ./capevolve_harbor

# Set up the project
cap-evolve init
cp -r templates/adapters/harbor/* .capevolve/project/adapters/

# Configure
export HARBOR_DATASET=<org/dataset>
export HARBOR_AGENT=<agent>
export HARBOR_MODEL=<model>
export HARBOR_TASK_IDS=<task1,task2,...>
export HARBOR_TASK_PREFIX=<dataset-org>
export HARBOR_EXTRA_FLAGS="-e openshift -n 5 --ae KEY=VALUE ..."

# Run the optimization
cap-evolve check .capevolve/project
cap-evolve run --spec .capevolve/project/capevolve.yaml

cap-evolve will iterate: evaluate via harbor run → diagnose failures → optimizer edits the skill → re-evaluate → gate → repeat.

Debugging

# Keep task pods alive after the trial for inspection
harbor run ... --no-delete

# List Harbor's task pods
oc get pods | grep ^hb-

# Check a task pod's logs
oc logs <pod-name> -c main

# Shell into a running task pod
oc exec -it <pod-name> -- /bin/sh

# Check build status
oc get builds

Harbor captures full transcripts in the job output directory:

jobs/<job-name>/<trial>/
  agent/trajectory.json      # agent execution trace (ATIF format)
  agent/claude-code.txt      # raw agent stream
  verifier/reward.json       # verifier score
  verifier/test-stdout.txt   # verifier output
  verifier/test-stderr.txt   # verifier errors

Troubleshooting

ProblemFix
unable to validate against any security context constraintRun oc adm policy add-scc-to-user harbor-task-scc -z harbor-task and for the orchestrator SA too
Build pod failsCheck oc logs <build-pod> — usually a Dockerfile issue or missing base image
Task pod: ImagePullBackOffThe built image wasn't pushed to the internal registry — check oc get is
Agent timeout / RuntimeErrorModel context too small for the task. Use a larger model or filter with -i <task>
Vertex AI auth fails in task podEnsure --mounts-json bind-mounts the GCP credentials file and --ae GOOGLE_APPLICATION_CREDENTIALS=<path> points to it
vLLM endpoint not reachable from task podTask pods run in the same namespace — use the full Service DNS: http://<svc>.<namespace>.svc:8000
No task matched the filterHarbor prefixes task names with the dataset org. Use -i <org>/<task>
Pod evicted / OOMKilledIncrease memory with --override-memory-mb 4096
