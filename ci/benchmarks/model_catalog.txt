# model_catalog.txt — which provider serves each model, and in what order CI tries them.
#
# A benchmark dispatch may name a model in two ways:
#   * a PLAIN name from this file (e.g. "claude-opus-5"). ci_setup.sh's preflight tries the
#     providers in `order`, skips one that has no entry for the model or no secrets, and keeps
#     the first provider that serves the model and has budget. The whole run uses that one.
#   * a PREFIXED id (e.g. "ibm-ete/aws/claude-opus-5"). It pins that provider: no fallback.
#
# Why this order: RITS has no budget, so it is always the cheapest place to run. ibm-ete-int is
# the team's main gateway. ibm-ete is the second gateway, used only when ibm-ete-int cannot
# serve the model or is over its budget (as on 2026-09-30, run 36711181652).
#
# RULES FOR EDITING (see ci/benchmarks/README.md, "Model providers"):
#   * List two ids under one name ONLY when they are the same model. The same name is NOT
#     enough. ibm-ete-int's "rits/google/gemma-4-31B" is the BASE Gemma model, while RITS's
#     "google/gemma-4-31B-it" is the instruction-tuned one the SpreadsheetBench results use, so
#     they are not merged. Two ete gateways serving the same wire id are the same deployment
#     type and may be merged; GPT-5.5 was checked on both (#538: test 38.6 on each).
#   * A different serving stack can change scores. RITS's "openai/gpt-oss-120b-a100" and
#     ibm-ete-int's "aws/gpt-oss-120b" share weights but are kept apart, so the default agent
#     keeps its benchmark history. Merge them only after a side-by-side run.
#   * sync_models.py checks every id here against the gateways' /models listings and reports
#     ids that are no longer served. It never edits this file.
#
# Format: `order <provider> ...` once, then one `model <plain-name> <ci-id> [<ci-id> ...]` per
# model. The order of ids on a line does not matter; `order` decides.

order ibm-rits ibm-ete-int ibm-ete
