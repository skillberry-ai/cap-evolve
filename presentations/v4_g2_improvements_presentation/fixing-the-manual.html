cloud-024-guid-to-account

Seed20% → cand_0004100%
The test request — the entire message, verbatim

“jbfsq”

Nothing else attached. No verb, no question mark.

The problem

Unchanged from the T2 audit: a raw provision GUID arrives on its own, the coordinator has no rule for that shape of message, and it falls back on generic manners — asking what the user would like to investigate instead of looking the ID up.

What G2 wrote instead

The global optimizer reached the same conclusion independently, and went further than T2 did: as well as the rule, it added a shape‑to‑tool table covering six identifier forms, and an explicit statement of what a correct answer must contain — sandbox name, owner, account id.

orchestrator.md — new section
+### A bare identifier is NOT ambiguous —
+resolve it, never ask what it means
+
+A message that consists only of an identifier
+(no verb, no question) is a request to identify
+that thing. Look it up FIRST. Never answer a bare
+identifier with a clarifying question or a menu of
+things you could investigate.
Followed by a six‑row table mapping each ID shape — 5‑char GUID, sandboxNNNN, pool‑XX‑NNN, 12‑digit AWS id, email, hostname — to the tool that resolves it.
orchestrator.md — and what counts as an answer
+Report the identity facts the lookup returned —
+the sandbox name, the owner, and the account id.
+A bare identifier can only be read as "what is
+this?", so identifying it *is* the answer.
Also added: “Pick the row by exact field match, never the first row returned” — neighbouring sandboxes have adjacent account ids.

platform-007-directory-path-fetch

The request — this task’s question shape

“The workload roles live under ansible/roles_ocp_workloads — find the task file for the ocp4_workload_pipelines_operator role and report its retry settings.”

You’re told the tree, not the file. That gap is what the agent guessed its way through.

The problem

Unchanged: the tool reads exactly one file, but its description advertised “files and directories,” so the agent opened folders like documents.

What G2 wrote instead

Rather than only correcting the prose, G2 wrote the tool’s literal return contract — including its exact error string — into both specialist files, and added a shared rule making search_github_repo mandatory and first whenever the question names a tree.

aap2_agent.md + babylon_agent.md — I/O contract
−Fetch file or directory contents from a GitHub repo
+**fetch_github_file** — {path, content, type}.
+Files ONLY. A directory path returns
+{"error": "No such file or directory at the
+specified ref."} — it does not return a listing.
Written identically into both files, because either specialist can be the one holding the question.
shared_context.md — new section
+### GitHub Paths: Search for the Tree,
+Fetch Only the Leaf
+
+Only ever pass fetch_github_file a path you have
+seen returned verbatim by search_github_repo …
+never probe your way down a tree one level at a
+time — every probe fails.
+When the question names a tree … search_github_repo
+is mandatory and must come FIRST.

Four rules, one contradiction

platform-004-events-then-config

Seed79% → cand_0004100%
The request — a question with its own step order

“Find how many events failed, read one job’s log, then read the config.”

The question states an order. The manual’s own shortcuts quietly overrode it whenever a job ID was supplied.

The problem

A supplied job ID triggered a “go straight to the log” shortcut, which reordered the user’s own list of steps — so the breadth‑first step was deferred past the round budget and never answered.

What G2 wrote instead

Two complementary rules: the question’s stated order is binding, and stop as soon as every asked‑for fact is in hand. Together they fix the under‑answer without creating an over‑investigation in its place.

shared_context.md — new section
+### Follow the order the question gives you
+
+Breadth-first steps — how many failed, what else
+was affected — come BEFORE the narrow ones
+whenever the question lists them first. Do not defer
+a listed step because the earlier answer already
+looked complete: a step deferred past your budget is
+worth nothing.
aap2_agent.md — closing the shortcut
+A supplied job ID does NOT reorder the question's
+own list of steps.
Paired with “Answer as soon as the asked‑for facts are in hand” in shared_context.md — the brake that keeps the order rule from turning into endless investigation.

Long doesn’t mean timeout — and G2 never said so

platform-008-log-does-not-say

Seed96% → cand_0004100%
The request — this task’s question shape

“Why did this job fail?”

Job 90408 on the west controller. The log simply stops — no error line, no PLAY RECAP, zero failed events. There is nothing in the evidence to name as a cause.

The finding that changed

T2 fixed this by deleting the false rule: Short = auth/config error. Long = timeout. G2 scored 100% here too — but it never touched that line. It is still in aap2_agent.md, word for word, at line 366 of the shipped bundle.

What G2 did instead

It built a reporting contract around the defect: a long, explicit set of rules on partitioning what evidence does and does not establish, and on never nominating a “most likely cause” after saying you cannot establish one. The guess is caught on the way out rather than prevented at the source.

aap2_agent.md:366 — unchanged from seed
·5. **Timing** — how long did the failing
! operation take? Short = auth/config error.
! Long = timeout.
Present in the seed, present in cand_0004, deleted by T2 and by the T4 merge. G2 is the only one of the three optimized bundles that still ships it.
shared_context.md — the compensating contract
+Partition what the absence does and does not
+establish — and write the second half.
+"The log does not establish a root cause."
+
+If the evidence does not establish a cause, do not
+then nominate a "most likely cause" as a
+consolation prize — it contradicts your own answer.
Recommendation

Delete aap2_agent.md:366 regardless. A perfect score here does not mean the instruction became true — only that a later rule usually catches its consequence.
