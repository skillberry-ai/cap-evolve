# skillbench_history

This is an **orphan branch** (no shared history with `main`) holding hand-authored
evidence, results, and insights from optimizing SkillsBench-facing skills with
cap-evolve. It is checked out into its own worktree, never switched-into in place — see
"Working on this branch" below.

## Why this branch exists

cap-evolve work here splits into two kinds of contribution:

1. **Contributions to cap-evolve itself** — the library: features, CI/CCC infra, core
   docs. These land on `main` via normal PRs.
2. **Contributions to SkillsBench optimization** — where cap-evolve is merely the tool
   we used. Results tables, evolved skills, insight write-ups, ideas, proposals. These
   have no natural home on `main` (that tree is the library, not a lab notebook) and
   don't belong on `benchmark-history` either — that branch is machine-written
   (regenerated by `ci/benchmarks/lib/record.py aggregate`) and periodically pruned by
   `.github/workflows/benchmark-history-prune.yml`. Hand-authored content placed there
   would eventually be deleted.

`skillbench_history` is the home for kind 2. Dashboard **metrics** (the numbers behind
the live results table) still go through the normal `benchmark-history` pipeline — see
`ci/benchmarks/PUBLISHING.md` — since `skillsbench` is already a first-class `bench`
value there. This branch is for everything a metrics record can't hold: the narrative,
the code that got evolved, the reasoning.

## Layout

- `results/` — result tables and ledgers, one subdir per sweep/experiment.
  `results/results.json` is the canonical results ledger.
- `insights/` — write-ups: investigations, comparisons, reports.
- `evidence/` — concrete proof bundles for specific claims (e.g. "cap-evolve evolves
  real code, not just prose"), each with its own README, the actual before/after
  artifacts, and diffs.
- `handoffs/` — session-to-session handoff docs for in-progress experiment lines.
- `proposals/` — design docs for experiments not yet (fully) run.
- `ui/` — standalone browsable HTML artifacts (charts, heatmaps). Open directly in a
  browser from a checkout — no build step, no server.

## Working on this branch

Always via a dedicated worktree, never `git switch skillbench_history` in an existing
checkout of `main` or another branch:

```bash
git worktree add ../cap-evolve-worktrees/skillbench_history skillbench_history
```

Before every commit, run `git status` and review it — this branch has no `.gitignore`
inherited from `main`, so double-check no `.env`, `.cache/`, or `__pycache__/` content
is staged.
