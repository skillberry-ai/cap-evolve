# spreadsheet-helpers

Helper scripts for spreadsheet manipulation. Each script is general, offline and
deterministic, takes its inputs as arguments, and writes only to the path it is given.
Import them inside the kernel exactly as shown.

## When to call each helper

- `from skills.spreadsheet_helpers import helpers_2`
  - `helpers_2.sheet_grid(path, sheet=None, max_rows=None, max_cols=None)` — returns
    `(sheet_title, list_of_rows)` covering the sheet's real non-empty extent. Call this
    when you need the raw grid programmatically (finding headers, extents, label rows)
    rather than just printing.
  - `helpers_2.print_grid(path, sheet=None, max_rows=60, max_cols=30)` — prints a
    sheet's full grid with row numbers and A1 coordinates. Call it in the FIRST round
    on every sheet involved in the task, and again after saving to verify. Always
    print the full extent, not just the preview rows: the real data often extends far
    beyond what the task preview shows.
  - `helpers_2.parse_filter_expr(text)` — parses a boolean filter string into
    `{key: [values]}`. Call when an instruction describes row selection conditions.
  - `helpers_2.strip_leading_zeros(value)` — converts '03'-style numeric strings to int
    and passes other types through. Call before comparing IDs or codes read as text.
  - `helpers_2.cartesian_expand(row, parsed, keys)` — expands one input row into a list
    of dict rows, one per combination of filter-key values. Call when one source row
    must be replicated across several output rows.
  - `helpers_2.write_table_to_range(path, out_path, sheet, start_row, start_col, header, rows, end_row=None, end_col=None)` —
    writes a header + data rows into `sheet` starting at start_row/start_col, bounded
    by end_row/end_col. Call instead of hand-rolling the openpyxl write loop; it keeps
    every write inside the target range.
  - `helpers_2.verify_range(path, sheet, min_row, min_col, max_row, max_col, expected=None)` —
    re-opens the saved workbook and checks every cell in the target range (optionally
    against `expected`, a dict of `(row, col) -> value`). Call it in the FINAL round on
    the exact answer_position bounds; it reports both value mismatches and MISSING
    (empty) cells that should hold a value.

## Judgment rules the helpers cannot decide for you

1. COVERAGE IS THE #1 FAILURE MODE. Every cell in answer_position must receive a value
   unless the instruction explicitly says to blank it. When you are transferring,
   rearranging or looking up data into a target range (e.g. an INDEX/MATCH-style
   cross-table copy), a missing or empty source cell is NOT a reason to leave the
   target cell empty — the expected answer almost always fills the whole target block,
   typically with `0` for numeric source grids (write `0`, not `None`, not `''`).
   After writing, call `verify_range` and confirm the non-empty cell count equals the
   range size. If your output only fills the cells where the source happened to have
   data, you have under-filled and will score zero.

2. Map the real layout before computing. Read the grid with `print_grid`/`sheet_grid`
   and locate the actual header row, label column, and both tables' extents. Source
   and target tables in the same sheet often have DIFFERENT row/column orders (e.g.
   reversed category orders) and different label lists — build explicit
   label -> row/col maps from the real grid rather than assuming aligned positions.

3. Instructions phrased as "how can I write a formula that..." are usually graded on
   the VALUES the formula would produce, unless the instruction explicitly demands a
   live formula ("I need an Excel formula", "populate automatically"). Compute the
   result in Python and write literal values; if the row-level rule references other
   rows sharing a key (e.g. all rows for the same ID), aggregate over ALL rows with
   that key, not just the current row.

4. Never modify cells outside answer_position, and never rewrite the workbook with
   pandas `to_excel`. Copy the input file to output_path, edit with openpyxl, save,
   then verify.
