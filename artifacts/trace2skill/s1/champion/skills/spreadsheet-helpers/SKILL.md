# spreadsheet-helpers

Each script is general, offline and deterministic, takes its inputs as arguments, and writes only to the path it is given. Import with `from skills.spreadsheet_helpers import <module>`.

## Reply format and round discipline (critical)

- Every reply must contain exactly ONE plain ```python fenced code block of runnable code — no prose, XML or custom tool-call wrappers outside it. Anything else is discarded, nothing executes, and the round is wasted. If feedback says "No python code block was found" or "NOTHING was executed", fix the format first before touching task logic.
- Never resubmit a failing reply unchanged — read the stated error and change format, code or approach. No silent exception swallowing: print full tracebacks; "no output" means your main logic never ran.
- Write the output workbook to the given output path EARLY, even with a partial solution; use remaining rounds to verify and refine. Once verified, stop.

## Helper scripts

- `range_tools` — [`skills.spreadsheet_helpers.range_tools` (helper script)](`skills.spreadsheet_helpers.range_tools` (helper script)): `write_range(path, sheet, ref, values)` writes a 2D list into an A1-style range of the existing workbook in place, preserving all other cells and formatting (use instead of pandas `to_excel`); `read_range` reads the range back after saving; `check_duplicate_keys(df, key_col)` — call before any merge-based lookup.
- `inspect_sheet` — [`skills.spreadsheet_helpers.inspect_sheet` (helper script)](`skills.spreadsheet_helpers.inspect_sheet` (helper script)): `dump_region(ws)` prints raw cell values — call it FIRST on any unexamined sheet and ALWAYS when a lookup returns empty; `find_header_row(ws, required_terms)` locates the header row; `find_name_rows(ws, name)` finds all rows matching a name, resolving merged cells; `is_uniform(grid, 0)` detects implausible all-zero output.
- `verify_output` — [`skills.spreadsheet_helpers.verify_output` (helper script)](`skills.spreadsheet_helpers.verify_output` (helper script)): call after EVERY save. `read_range` reads the full answer range; `check_order` verifies required first-occurrence ordering; `check_no_blanks` / `check_no_header_text` catch blanks and header leakage; `check_extent(path, sheet, allowed_range)` confirms the final data extent fits the answer range.
- `count_by_key` — [`skills.spreadsheet_helpers.count_by_key` (helper script)](`skills.spreadsheet_helpers.count_by_key` (helper script)): `group_and_count(df, key_col, value_cols, codes)` counts code occurrences in raw data columns per key, forward-filling merged/blank key cells. Never count from pre-existing summary columns.
- `time_extract` — [`skills.spreadsheet_helpers.time_extract` (helper script)](`skills.spreadsheet_helpers.time_extract` (helper script)): `write_time_only(ws, src_col, dst_col, start_row, end_row)` writes the time component (a `datetime.time`) as the underlying value when cells must display only the time; `verify_time_only` confirms no date component.
- `cellvalues` — [`skills.spreadsheet_helpers.cellvalues` (helper script)](`skills.spreadsheet_helpers.cellvalues` (helper script)): `load_values(path)` (data_only=True) reads cached formula results for aggregation; `load_for_writing(path)` is the view you save — NEVER save a data_only load (it strips formulas); `find_row(ws, col, key)` matches keys by `str()` so 2012 never mismatches "2012".
- `date_window` — [`skills.spreadsheet_helpers.date_window` (helper script)](`skills.spreadsheet_helpers.date_window` (helper script)): `workday_window_dates`, `count_in_window`, `sum_in_window` for conditions like "last N workdays before D": the window is `>= WORKDAY(D, -N)` and `< D` (or `<= D` if D counts). Enumerate the concrete dates and confirm the count equals exactly N.
- `sum_dedupe` — [`skills.spreadsheet_helpers.sum_dedupe` (helper script)](`skills.spreadsheet_helpers.sum_dedupe` (helper script)): `sum_dedupe(df, key_cols, sum_cols)` collapses duplicate keys to one row per key, preserving original row order — use instead of `groupby().agg()`, which reorders rows.
- `subsetsum` — [`skills.spreadsheet_helpers.subsetsum` (helper script)](`skills.spreadsheet_helpers.subsetsum` (helper script)): `find_combination(values, target, tolerance)` returns a tuple summing to the target, for "find values that sum to X" tasks with ~20 or fewer candidates.

## Rules that prevent known failure modes

1. **Edit in place; write only within answer_position.** Load the original workbook with openpyxl and write ONLY the cells inside the task's answer range. Do NOT rewrite sheets with pandas `ExcelWriter`/`to_excel` — it coerces types (100 → 100.0), drops formatting and touches cells outside the permitted range. If the instruction names specific output columns but the range is wider, write only those columns. Use `range_tools.write_range` and run `verify_output.check_extent` before finishing.
2. **Inspect before assuming structure.** Print the actual workbook structure and full column contents (key cells, source values, embedded header-like rows, blanks) before committing to column indices or layout. Read the FULL extent, not truncated previews; referenced values often live in other sheets or label cells. Names are often merged cells where only the top-left holds the value — use `inspect_sheet.find_name_rows` or forward-fill the key column. Match rows by key values, never by row order; normalize strings before equality comparisons; filter embedded header rows explicitly.
3. **Pandas index vs openpyxl row.** With `header=None`, pandas index i is openpyxl row i+1; with a row-1 header, index i is row i+2. Never use a pandas index directly as a write row; confirm target cells via openpyxl first. pandas columns are 0-based (D = columns[3]), openpyxl columns 1-based (D = 4).
4. **Compute from raw data, not summary columns.** Count/aggregate from the raw data columns the task points at; pre-existing summary/derived columns may be empty, stale or blank formula results. Recompute defined metrics from their base columns; never use a similarly named column without checking its sign/direction.
5. **Derive mapping literally from worked examples.** Treat each stated example as a test case and check your interpretation against every example before coding; never substitute a plausible alternative algorithm. Pre-filled target values are a specification signal — compute them with your logic and investigate mismatches. Decode the target cell's row/column against headers and labels before computing.
6. **Blank vs zero vs #N/A.** Rules like "empty cells show a hyphen instead of zero" apply only to cells that would otherwise be BLANK (missing source value, NaN); computed numeric zeros stay numeric — track emptiness with `pd.isna`. When a task says "leave blank", write `None`, never `""`. openpyxl reads Excel `#N/A` as the literal string `'#N/A'`, not None — test missingness explicitly. An all-zero or mostly-empty output where the input shows data is a hard failure: the lookup is broken — dump the raw source region and re-diagnose; never blank answer cells as a fallback for unmatched lookups.
7. **Verify the entire range, independently.** After saving, re-open the file and check the FULL answer range (blanks, header leakage, ordering, type coercion, extent) — never verify with only `df.head()`. Re-derive expected values from the ORIGINAL input using a different method than the solution code (e.g. re-find each target row by key in the source sheet). If a secondary sentence contradicts the primary ordering, do NOT layer an extra sort on top — re-check the data. Include all matching rows; never truncate.
8. **Never resubmit identical failing code.** If an observation returns no new information or shows an anomaly, change the approach — add diagnostics (counts, samples, matched rows, dumps). Check merge keys with `range_tools.check_duplicate_keys`; duplicate keys silently multiply rows. When matching across sheets by multiple fields, match on the full composite tuple, never a single field.
9. **Literal values, not live formulas or formats.** Compute in Python and write literals; openpyxl does not evaluate formulas (`_xlfn.` prefixes, `#NAME?`, unevaluated strings). When exact decimal places are specified, write the literal rounded number — graders read the stored value, not `number_format`. When a task says cells should "display only X", write X as the stored value (e.g. `datetime.time`). Mixed types: `pd.to_datetime` raises on `datetime.time` — branch on `isinstance` before converting.
10. **Never overwrite completed regions.** When a task says to preserve existing rows and complete missing ones, inspect pre-filled rows for their pattern and do not recompute them; pass `None` for cells you must not touch. Decide boundary cases ("before X" / "after X", `<` vs `<=`) explicitly, not silently.
