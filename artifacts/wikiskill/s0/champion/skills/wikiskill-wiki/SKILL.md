# Wiki index

- [preserve-untouched-cells-openpyxl](wiki/patterns/preserve-untouched-cells-openpyxl.md): Sheet-Level tasks fail because full-sheet pandas rewrites alter cells the instruction never asked to change (ints→floats, lost formatting, 'CHANGED although expected value is the original input'); fix by editing only answer_position cells in-place with openpyxl load_workbook/save, never df.to_excel.
- [boundary-semantics-off-by-one](wiki/patterns/boundary-semantics-off-by-one.md): Near-miss failures ('1 cell empty where value expected') stem from guessing inclusive vs exclusive cutoffs (before/after 09:45, 365-day window) and over-applying 'leave blank if 0'; fix by testing candidate interpretations against pre-filled example values before filling the range.
- [use-sample-rows-as-oracle](wiki/patterns/use-sample-rows-as-oracle.md): Whole-range mismatches happen when agents ignore user-provided example outputs; fix by reading those cells first and validating logic reproduces them — check ALL example cells, never overwrite cells the user already filled, and treat any diff on a pre-filled cell as stop-and-fix (194-19 failed in it2, it3, AND it6; 58484 failed again in it6).
- [evaluate-example-formulas-as-oracle](wiki/patterns/evaluate-example-formulas-as-oracle.md): When pre-filled example cells hold FORMULAS (=AVERAGE(B24:B69)), reading the text and guessing semantics fails every cell (56786 it4+it5: 197/197 wrong); fix by loading with data_only=True (or evaluating in Python) and requiring your computed values to reproduce ALL evaluated examples exactly before writing the range.
- [verify-write-values-not-assumptions](wiki/patterns/verify-write-values-not-assumptions.md): Verification that only prints aggregate booleans passes while output is wrong; fix with per-cell read-back verification, treat mostly-empty/all-zero read-back as hard failure, and reproduce any user-quoted check value (e.g. 'expected 699') in Python before writing.
- [write-formulas-for-formula-questions](wiki/patterns/write-formulas-for-formula-questions.md): 'How can I...' formula questions expect a live Excel formula in the target cell, not Python-computed literals; fix by reading the user's existing anchor formula, fixing its actual bug, and writing the corrected formula with proper $-anchoring — and never write CSE-array-dependent formulas (48365 it6 failed this way; see avoid-cse-array-formulas-written-by-openpyxl).
- [write-typed-time-values-not-strings](wiki/patterns/write-typed-time-values-not-strings.md): Scorer fails with 'str where time was expected' when formatted time strings (strftime '06:08:00 PM') are written; fix by writing a real datetime.time value (or =MOD(I2,1)) and setting number_format='hh:mm:ss AM/PM' — never text for typed values.
- [excel-vs-pandas-coordinates-off-by-one](wiki/patterns/excel-vs-pandas-coordinates-off-by-one.md): Mostly-empty target ranges come from mixing pandas iloc indices/Unnamed headers with Excel coordinates and mislabeled header rows; fix by confirming header/label rows with openpyxl cell reads before writing formulas that reference them.
- [recompute-dependent-columns-after-edit](wiki/patterns/recompute-dependent-columns-after-edit.md): 'N cells LOWER than expected' after changing an input column (e.g. Bill Rate 100→180) happens because derived columns (Bill = hours x rate, Profit) are copied unchanged; fix by recomputing all arithmetic-dependent columns of the edited rows from the new values before writing.
- [no-pandas-writer-fallback-when-openpyxl-fails](wiki/patterns/no-pandas-writer-fallback-when-openpyxl-fails.md): When openpyxl load errors, falling back to pd.ExcelWriter/to_excel silently drops other sheets, shifts columns via 'Unnamed' headers, and yields UNCHANGED/CHANGED-original scorer verdicts; fix by retrying openpyxl (read_only/data_only) or shutil.copy + openpyxl patch, never to_excel on graded output — and never substitute a 'similar' sheet as proxy data or rebuild the workbook from scratch.
- [never-finish-with-unexplained-in-range-diffs](wiki/patterns/never-finish-with-unexplained-in-range-diffs.md): Agents finish after diff_report prints hundreds of IN-RANGE diffs (overwritten examples, systematically shifted column) because only OUT-OF-RANGE counts feel fatal; fix by treating any diff on a pre-filled cell and any systematic shift pattern as stop-and-fix before finishing.
- [float-roundtrip-diff-noise](wiki/patterns/float-roundtrip-diff-noise.md): Diffs reporting many OUT-OF-RANGE changes like 10.833333333721384 vs 10.83333333372138 are openpyxl save round-trip artifacts, not damage; fix by comparing numerics with math.isclose(rel_tol=1e-9) and ignoring untouched-cell noise — chasing it hides the real semantics failure.
- [match-fill-count-to-expected-answer](wiki/patterns/match-fill-count-to-expected-answer.md): Fill-count mismatches in BOTH directions — sparse source lookups left blank, formulas written into all cells when examples mark fewer, one summary value where examples show per-run counts (58484 it6 again: 1 written vs 9 expected); fix by reading pre-filled example cells first: their count and placement is the expected fill pattern, source blanks usually become 0, and verify non-empty counts before vs after saving.
- [avoid-cse-array-formulas-written-by-openpyxl](wiki/patterns/avoid-cse-array-formulas-written-by-openpyxl.md): SUM(SUMIFS(...,range-as-criteria)) and similar array formulas written as plain openpyxl formulas evaluate to error strings the scorer reads as '#N/A text where int expected'; fix by using non-array structures (sum of separate SUMIFS, SUMPRODUCT, MATCH(1,INDEX((..)*(..),0),0)) or openpyxl ArrayFormula, and verify the cell evaluates to a number.
- [count-days-not-half-day-row-pairs](wiki/patterns/count-days-not-half-day-row-pairs.md): Near-miss 'N cells HIGHER than expected' on attendance counts when the source has two rows per person (first/second half of workday) — a raw occurrence count counts half-days, not days; fix
