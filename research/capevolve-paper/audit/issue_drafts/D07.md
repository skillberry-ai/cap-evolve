# finalize: the held-out test seal is per run directory; --reuse-baseline resets it, so a campaign reuses the same test split without any warning

_Draft for `skillberry-ai/cap-evolve`. Base SHA `e3cb513`. Defect id D07 (campaign audit, parent #743/#744)._

## Problem
`test_used` is a flag in one run's `splits.json`. `reuse_baseline` copies the prior frozen split, forces `test_used=False` and carries the seed's test result forward. `make_splits(seed)` is deterministic. There is no cross-run record of which test ids have already been scored.

## Code locations
- `core/cap_evolve/splits.py:26-60`
- `core/cap_evolve/rundir.py:428-477`
- `core/cap_evolve/harness.py:861-933` (`reuse_baseline`), `4417-4497` (`finalize`)
- Related open: #361, closed #335

## Reproduction
Run `baseline` twice with the same `--seed` into two run dirs: both `splits.json` carry identical `test` and `test_used=false`; finalize in both succeeds.

## Impact
A paper comparing many arms/configs/seeds on one test split and selecting or ranking on test consumes the held-out set repeatedly; the 'scored exactly once' guarantee does not hold at campaign level.

## Proposed correction
Add a campaign-level test ledger (hash(sorted test ids) -> run, arm, time) that warns on reuse and records `test_reuse_count` in `final.json`; support per-arm disjoint test partitions.

## Acceptance test
- Second finalize on the same test-id hash from a different run dir emits `test_reuse` warning and sets `test_reuse_count: 1` in `final.json`.
