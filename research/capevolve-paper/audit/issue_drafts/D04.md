# gate: coverage is checked on the candidate alone, and errored candidate trials are silently dropped from the pair

_Draft for `skillberry-ai/cap-evolve`. Base SHA `e3cb513`. Defect id D04 (campaign audit, parent #743/#744)._

## Problem
`min_coverage=0.6` is a hard-coded default of `gate.decide` (no CLI/spec key). `run_step` passes the candidate's marginal coverage; `gate_check` passes `min(cand, ref)` of marginal coverage. Neither checks the joint (paired) coverage. Errored trials are removed from means and pairs, and `trials.run_trials_pool` converts any exception in `run_one` into an error rollout, so a candidate whose own code raises inside an in-process adapter is treated as missing data, not a failure.

## Code locations
- `core/cap_evolve/gate.py:397-406`
- `core/cap_evolve/harness.py:1058-1070` (`_paired_deltas`), `3019-3024`
- `core/cap_evolve/loop.py` (`has_valid_trials`, `aggregate_scores`, `SplitResult.coverage`)
- `core/cap_evolve/trials.py` (`_one`)
- `skills/algorithms/agent-optimize/scripts/gate_check.py:239-247`
- `core/cap_evolve/adapter.py:94` (contract: error is for infrastructure only)

## Reproduction
`python3.12 -I audit/repro/r2_coverage.py`:
```
parent val=0.733 candidate val=0.833 cand coverage=0.80
paired n=24 accept=True  (Δ̄=+0.1667 > 1·SE=0.0777) # candidate crashes on 6 tasks the parent passes
marginals 0.70/0.70 (>=0.6) but joint paired n=12/30=0.40; indecisive=False
```

## Impact
Candidate-induced failures labelled as errors inflate val and acceptance; coverage statistics reported per run understate dropped pairs. Reliability of any adapter that raises on bad candidate code is untested.

## Proposed correction
Gate on joint paired coverage; expose `gate_min_coverage` in the spec; require adapters to tag infra errors (`error_kind: infra`) and score other exceptions as reward 0; report `n_dropped_pairs` in the step record and `final.json`.

## Acceptance test

- Test: an exception in `run_one` with `error_kind` unset scores 0.0, not missing.
