# agent-optimize: documented engine needs active_eval, which is OFF by default; 'sequentially valid' posterior is not the default accept rule

_Draft for `skillberry-ai/cap-evolve`. Base SHA `e3cb513`. Defect id D10 (campaign audit, parent #743/#744)._

## Problem
`optimizer_config.DEFAULTS` has `active_eval=False`; `SKILL.md` says the loop 'REQUIRES' the new engine and tells users to turn it on. With stock defaults, `probe --auto` silently runs full val and `promote` uses `reward_gated` (cost_gating=True) rather than the posterior rule that `posterior.py`/`act.judge` describe as sequentially valid. Local simulation supports a low null false-accept rate for the posterior on a single fixed pair (1.6-3.6%, N=250), but the guarantee does not extend to multiple candidates, merges, adaptive proposals or generalization.

## Code locations
- `core/cap_evolve/optimizer_config.py:34`
- `skills/algorithms/agent-optimize/SKILL.md:17-28`

## Reproduction
`python3.12 -I audit/repro/r4_posterior.py` (about 4 min).

## Impact
Results labelled 'agent-optimize' are different algorithms depending on the ablation vector; the paper must publish the vector and not attribute posterior-validity to default runs.

## Proposed correction
Record the resolved ablation vector in `final.json`; make the SKILL's required switches the defaults (or refuse to start otherwise); qualify the 'sequentially valid' wording.

## Acceptance test
- `final.json` has `optimizer.ablation` resolved values.
- `act.py` refuses (or warns loudly) when `new_engine()` is false.
