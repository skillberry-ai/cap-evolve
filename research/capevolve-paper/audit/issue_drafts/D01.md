# gate: causal-footprint masking (default ON) can accept a net-negative candidate

_Draft for `skillberry-ai/cap-evolve`. Base SHA `e3cb513`. Defect id D01 (campaign audit, parent #743/#744)._

## Problem
`harness.run_step` builds a footprint (tasks whose rollouts mention a symbol named on the diff's changed lines) and `_paired_deltas` replaces every out-of-footprint paired delta by exactly 0.0 before the `mean > k_se*SE` test. `footprint_gate=True` is the default and neither `cap-evolve run`, `hill-climb`, `skillopt` nor `gepa` run scripts can turn it off. The footprint only sees named code surfaces (`def`/`class`/`call(`/`"name":`); a prose rule, policy sentence or prompt change in the same diff names nothing, so tasks it breaks are zeroed. The veto that would catch this (`gate_max_broke`, `--no-regression`) is off by default and is not forwarded by the CLI.

## Code locations
- `core/cap_evolve/harness.py:1024-1070` (`_paired_deltas`), `2837` (`footprint_gate: bool = True`), `2984-3006` (footprint built from the candidate's own val rollouts, then masked)
- `core/cap_evolve/footprint.py:115-261`
- `core/cap_evolve/gate.py:282-294` (`gate_max_broke` default None)
- `skills/algorithms/agent-optimize/scripts/gate_check.py:232-248` (on unless `--no-footprint`; not used by the reward_gated path)

## Reproduction
`python3.12 -I audit/repro/r1_footprint.py` (30 val tasks; tool edit `refund_order` fixes 4 tasks, a prose rule in `prompt.md` breaks 6 others):
```
footprint: ['t01','t02','t03','t04']
full vector          mean_delta=-0.0667 accept=False  (SE=0.1065)
footprint (default)  mean_delta=+0.1333 accept=True   (SE=0.0631)
true full-split delta = -0.0667 ; n_broke = 6
```

## Impact
The statistic used to accept differs from the one reported in the val curve and `LEDGER.md`; a candidate can become champion while its val mean is lower than its parent's. Accept counts and 'improvement per accept' are not comparable across arms with and without masking. A paper using hill-climb/skillopt results must report an arm with `footprint_gate=False`.

## Proposed correction
1. Add `footprint_gate` to the spec (`gate_footprint`) and to every algorithm `run.py`; default OFF for benchmark/paper runs, or ON only with a mandatory full-split resolved-regression veto.
2. Always log both statistics (full-vector and masked) in the step record.
3. Treat any diff hunk that touches a file with no extractable surface (prose, JSON without `"name"`) as 'unlocalizable' and fall back to the full vector.

## Acceptance test
- A test reproducing r1 (prose rule + tool edit) asserts the step is rejected (or footprint abandoned) with default settings.
- `cap-evolve run` with `gate_footprint: false` yields a vector byte-identical to `footprint=None`.
- Step events carry `delta_full` and `delta_masked`.
