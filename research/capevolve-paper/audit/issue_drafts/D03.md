# hill-climb / agent-optimize use val as both the proposer's feedback and the acceptance split; train is never used for proposal

_Draft for `skillberry-ai/cap-evolve`. Base SHA `e3cb513`. Defect id D03 (campaign audit, parent #743/#744)._

## Problem
Both algorithms hand the proposer the parent's per-task val results and full val trajectories (hill-climb: `_inject_optimizer_context(split='val')`, LEDGER/JOURNAL with val ids; agent-optimize: `diagnose --split val`, exemplar val traces) and then accept on the same val split. Train is evaluated only at baseline/finalize for the bookend report. The only unadaptive data is the sealed test split. GEPA is the exception (minibatch reflection on train).

## Code locations
- `core/cap_evolve/harness.py:2454-2514`, `3853-3890`, `4313` (focus order from `read_splits().val`), `2818-2850` (`eval_split='val'`)
- `skills/algorithms/hill-climb/SKILL.md` ('only per-task data the loop holds')
- `skills/algorithms/agent-optimize/SKILL.md:53` (`--split val`)

## Reproduction
`grep -n "split=eval_split\|read_splits().val" core/cap_evolve/harness.py`; read `hill_climb_loop`. No run needed.

## Impact
val reward of the incumbent, `best_val`, `stop_at_reward`, the val curve, and acceptance statistics are selection-biased (adaptive data analysis / winner's curse). Only test deltas are clean. This also confounds comparison against GEPA, whose proposer does not see val.

## Proposed correction
Provide a train-reflection mode (proposer sees train trajectories; val used only for the gate), make it the default for paper runs or report both, and add val-minus-test gap to `final.json`.

## Acceptance test
- With `proposer_split: train`, no file under `./trajectories/` or the prompt contains a val task id (test asserts).
- `final.json` reports `val_test_gap`.
