# stats.combined_stderr double-counts within-task trial variance and does not shrink with trials

_Draft for `skillberry-ai/cap-evolve`. Base SHA `e3cb513`. Defect id D11 (campaign audit, parent #743/#744)._

## Problem
`combined_stderr = sqrt(var_between/n + Σ se_i²/n²)`. The between-task variance of per-task means already contains the within-task trial noise, so the second term double counts it for n_trials>1.

## Code locations
- `core/cap_evolve/stats.py:42-60`; consumers: `loop.aggregate_scores`, `gate._verdict` significant mode, `convergence`, reports

## Reproduction
`python3.12 -I audit/repro/r7_stderr.py`: fixed-val re-measurement sd 0.054/0.034/0.027/0.019 vs mean combined_stderr 0.080/0.069/0.065/0.057 at 1/3/5/10 trials (1.5x-3.0x).

## Impact
Reported 'val ± se', final.json, `significant` mode and noise comparisons are inflated and nearly insensitive to extra trials. Not used by the default paired gate.

## Proposed correction
State the estimand and implement it: fixed-task SE `sqrt(Σ se_i²)/n`, or population SE from between-task variance only.

## Acceptance test
- Test: for a fixed task set the estimator is within 10% of the empirical re-measurement sd at 1,3,10 trials.
