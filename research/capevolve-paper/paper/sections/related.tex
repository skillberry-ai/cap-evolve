\section{Related Work}
\label{sec:related}

Prompt optimizers edit one string, while CapEvolve edits a file set. OPRO conditions a model on past (solution, score) pairs \citep{opro}, ProTeGi turns minibatch errors into textual gradients \citep{protegi}, and MIPROv2 tunes the instructions and demonstrations of each program module \citep{miprov2-dspy}. GEPA reflects on rollout traces, keeps a per-task Pareto set, and merges candidates that share an ancestor \citep{gepa}. We run MIPROv2 and GEPA from public code.

Skill and context methods store procedure in text that the frozen agent reads. ACE grows a playbook by incremental deltas \citep{ace}. EvoSkill diagnoses failures and keeps a frontier of skill-augmented programs \citep{evoskill}. SkillOpt edits one skill document and accepts an edit only if it strictly improves a held-out selection score \citep{skillopt}. Trace2Skill consolidates many trajectories into one skill directory \citep{trace2skill}, and WikiSkill adds a persistent wiki \citep{wikiskill}. Each paper reports its gain on its own benchmark, split and budget, and the tables of GEPA and SkillOpt print one score per cell without an interval. We run these methods under one optimizer model and one rollout budget and report intervals. WikiSkill has no official code, so we run a community port.

Harness and agent search overlaps most with CapEvolve, and we do not claim its ideas as new. ADAS and AFlow search over agent code and code-represented workflows \citep{adas,aflow}. The Darwin G\"odel Machine lets a coding agent edit itself and screens children on 10, then 60, then 200 tasks \citep{dgm}. Meta-Harness gives a coding-agent proposer a filesystem with every earlier candidate's code, scores and traces \citep{meta-harness}. HarnessLens verifies a candidate only on tasks relevant to its change \citep{xu2026harnesslens}, and DarwinX admits a variant only if it extends the solved set without regressions \citep{darwinx}. CapEvolve's candidate DAG, merge verification and agent-driven controller resemble these designs. We ask whether they help when every arm has the same optimizer, budget and final set.

Acceptance rules decide which edit survives, and several carry guarantees that our rule P lacks. CAPO races candidates \citep{capo}, BudgetAPO sizes evaluation slices from measured noise \citep{liu2026budgetapo}, SAGE runs a one-sided paired test on shared items \citep{wang2026sage}, and PACE controls false commits under repeated testing with an anytime-valid e-process \citep{shawn2026pace}. Rule P (Section~\ref{sec:method:P}) is simpler: a paired screen, then confirmation on fresh trials, tuned by simulation.

Evaluation hygiene is the oldest problem here. Reusing a holdout set adaptively turns it into a training set \citep{adaptive-data-analysis-holdout-reuse}. Agent optimizers inherit the problem. Harness evolution on Terminal-Bench 2.1 does not beat simple test-time scaling under matched feedback and inference budgets, and earlier work searched on the tasks it reported \citep{rethinkharness}. Meta-Harness states that it searches and scores on the same 89 TerminalBench-2 tasks \citep{meta-harness}. Removing held-out selection from a recursive self-evolving agent gives a perfect in-sample score and a 33-point drop on test \citep{nguyen2026rsea}. Single-lineage prompt optimization is reported to match or beat GEPA with fewer rollouts \citep{naiveprompt}, and one analysis pass of a coding agent over stored trajectories to beat SkillOpt on all four benchmarks tried \citep{codingagentsopt}. These reports motivate our seed and one-shot controls. Our protocol adds a scorer audit, gold files hidden from the optimizer, fresh final sets and matched budgets.
