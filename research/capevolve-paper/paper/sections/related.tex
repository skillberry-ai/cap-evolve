Prompt and context optimizers edit text. MIPROv2 tunes instructions and demonstrations \citep{miprov2-dspy}, GEPA reflects on traces and keeps a Pareto set \citep{gepa}, and ACE grows a playbook by deltas \citep{ace}. Skill methods edit procedure that the frozen agent reads: SkillOpt edits one document \citep{skillopt}, EvoSkill and Trace2Skill write skill folders \citep{evoskill,trace2skill}, and WikiSkill adds a persistent wiki \citep{wikiskill}. Harness methods edit agent code, from workflows \citep{adas,aflow} to a coding agent's own tools \citep{dgm,meta-harness}. DRAFT rewrites tool documentation from trial feedback \citep{qu2025draft}, and EvoTool evolves the prompts of four tool-use policy modules \citep{evotool}. We found no paper that edits the descriptions an MCP server exposes inside a gated loop. CapEvolve treats the surface as a parameter of one loop, with an edit policy for each of prompts, tool code, tool descriptions and skills. DarwinX and the Darwin G\"odel Machine search over similar candidate trees, which we do not claim as new.

Several methods also keep a record of earlier edits. ACE counts how often each playbook bullet was helpful or harmful, SkillOpt retains rejected edits as negative feedback, EvoSkill logs prior proposals with their score deltas, and Meta-Harness shows its proposer the code, scores and traces of every earlier candidate. DarwinX stores per-task scores for each archive node and bounds regression. CapEvolve's fixed/broke history lists, for each earlier candidate, the tasks it fixed and broke, plus the passing tasks to protect. Its proposer reads trajectories of the current best candidate only.

Acceptance rules range from none to a statistical test. CAPO races candidates \citep{capo}, BudgetAPO sizes evaluation slices from measured noise \citep{liu2026budgetapo}, SAGE runs a one-sided paired test on shared items \citep{wang2026sage}, and PACE controls false commits under repeated testing with an anytime-valid e-process \citep{shawn2026pace}. DarwinX already confirms promoted children with repeated trials, so a screen followed by a confirmation is not new. In DarwinX a verifier agent reads the evidence and returns promote or revert. Rule P (Section~\ref{sec:v2:evaluation}) is a fixed test that runs in core code the proposer cannot edit, next to a sealed final set and gold isolation. It is simpler than PACE or SAGE and carries no formal guarantee.

Concurrent work measures optimizers without proposing one. Piao et al.\ run five skill optimizers and a one-shot skill with one model, agent and split on six benchmarks, and find that only 5 of 21 improving skills keep all of their training gain on test tasks \citep{piao2026skillsgeneralize}. Another study finds that harness evolution on Terminal-Bench 2.1 does not beat simple test-time scaling under matched budgets \citep{rethinkharness}. Single-lineage prompt optimization (NPO) and one analysis pass of a coding agent (CASD) are reported to rival GEPA and SkillOpt \citep{naiveprompt,codingagentsopt}. Neither paper links released code that we found, and our budget, fixed in advance, did not cover reimplementing them, so we cite them and do not run them. The one-shot control, which exists on the $\tau^2$ suites only, is the closest check we run. We compare against adapted official code under a matched rollout checkpoint (Section~\ref{sec:v2:setup}).
