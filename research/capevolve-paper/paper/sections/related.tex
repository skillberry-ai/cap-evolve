Prompt and context optimizers edit text. MIPROv2 tunes instructions and demonstrations \citep{miprov2-dspy}, GEPA reflects on traces and keeps a Pareto set \citep{gepa}, and ACE grows a playbook by deltas \citep{ace}. Skill methods edit procedure that the frozen agent reads: SkillOpt edits one document \citep{skillopt}, EvoSkill and Trace2Skill write skill folders \citep{evoskill,trace2skill}, and WikiSkill adds a persistent wiki \citep{wikiskill}. Harness methods edit agent code, from workflows \citep{adas,aflow} to a coding agent's own tools \citep{dgm,meta-harness}. In the papers we read, none reports editing the descriptions an MCP server exposes. CapEvolve treats the surface as a parameter of one loop, with an edit policy for each of prompts, tool code, tool descriptions and skills. DarwinX and the Darwin G\"odel Machine use search structures similar to CapEvolve's candidate DAG, which we do not claim as new. Several methods also keep a record of earlier edits: ACE counts how often each playbook bullet was helpful or harmful, SkillOpt retains rejected edits as negative feedback, EvoSkill logs prior proposals with their score deltas, and DarwinX stores per-task scores for each archive node and admits a child only if regression stays bounded. CapEvolve records which tasks each candidate fixed and broke, and gives the proposer the set of passing tasks to protect.

Acceptance rules range from none to a statistical test. CAPO races candidates \citep{capo}, BudgetAPO sizes evaluation slices from measured noise \citep{liu2026budgetapo}, SAGE runs a one-sided paired test on shared items \citep{wang2026sage}, and PACE controls false commits under repeated testing with an anytime-valid e-process \citep{shawn2026pace}. These papers contribute the statistics. Our contribution is where the rule runs: in core code that the optimizer cannot edit, next to a sealed final set and gold isolation, so that the proposer cannot influence what it is scored on. Rule P is simpler and carries no formal guarantee.

Concurrent work measures optimizers without proposing one. Piao et al.\ run five skill optimizers and a one-shot skill with one model, agent and split on six benchmarks, and find that only 5 of 21 improving skills keep all of their training gain on test tasks \citep{piao2026skillsgeneralize}. Another study reports that harness evolution on Terminal-Bench 2.1 does not beat simple test-time scaling under matched budgets \citep{rethinkharness}. Single-lineage prompt optimization and one analysis pass of a coding agent are reported to rival GEPA and SkillOpt \citep{naiveprompt,codingagentsopt}. We therefore include seed and one-shot controls and compare against official code under a matched rollout checkpoint (Section~\ref{sec:v2:setup}).
