\section{Related Work}
\label{sec:related}

Prompt optimizers edit one string, while CapEvolve edits a file set: system prompt, tool code, MCP tool descriptions and skill packages. OPRO conditions a model on past (solution, score) pairs \citep{opro}, ProTeGi turns minibatch errors into textual gradients \citep{protegi}, and TextGrad passes textual feedback back through a compound system \citep{textgrad}. MIPROv2 tunes the instructions and few-shot demonstrations of each program module \citep{miprov2-dspy}. GEPA reflects on rollout traces, keeps a per-task Pareto set of prompts, and merges candidates that share an ancestor \citep{gepa}. We run both from public code.

Skill and context methods store procedure in text that the frozen agent reads. ACE grows a playbook through incremental delta updates instead of rewriting it \citep{ace}. EvoSkill diagnoses failures, writes skill folders, and keeps a frontier of programs that score well on validation tasks \citep{evoskill}. SkillOpt applies bounded edits to one skill document and accepts an edit only if it strictly improves a held-out selection score \citep{skillopt}. Trace2Skill consolidates many trajectories in parallel into one skill directory \citep{trace2skill}, and WikiSkill co-evolves skills with a persistent wiki \citep{wikiskill}. Each paper reports its gain on its own benchmark, split and budget, and the tables of GEPA and SkillOpt print one score per cell without an interval. We run these methods under one optimizer model and one rollout budget and report intervals. WikiSkill has no official code, so we run a community port.

Harness and agent search overlaps most with CapEvolve, and we do not claim its ideas as new. ADAS has a meta agent write new agents in code from an archive of earlier ones \citep{adas}. AFlow searches code-represented workflows with Monte Carlo tree search \citep{aflow}, and AlphaEvolve evolves programs against an automated evaluator \citep{alphaevolve}. The Darwin G\"odel Machine lets a coding agent edit its own code and screens children on 10, then 60, then 200 tasks \citep{dgm}; the Huxley-G\"odel Machine guides expansion by an estimate of how well an agent's descendants perform \citep{hgm}. Meta-Harness gives a coding-agent proposer a filesystem with the code, scores and traces of every earlier candidate \citep{meta-harness}. HarnessLens verifies a candidate only on tasks relevant to its change \citep{xu2026harnesslens}, and DarwinX admits a variant only if it extends the solved set without regressions \citep{darwinx}. CapEvolve's candidate DAG, merge verification and agent-driven controller resemble these designs. We ask whether they help when every arm has the same optimizer, budget and final set.

Acceptance rules decide which edit survives, and several carry guarantees that our rule P lacks. CAPO races candidates and drops weak ones early \citep{capo}, and TRIPLE casts prompt selection as fixed-budget best arm identification \citep{triple}. BudgetAPO sizes evaluation slices from measured task noise \citep{liu2026budgetapo}. SAGE compares candidate and incumbent on the same items with a one-sided paired test \citep{wang2026sage}. PACE controls false commits under repeated testing with an anytime-valid e-process \citep{shawn2026pace}, and a further paper asks when a self-evolving system should stop \citep{yin2026enough}. Rule P (Section~\ref{sec:method:P}) is simpler: a paired screen, then confirmation on fresh trials, tuned by simulation. It charges the confirmation cost to the search budget.

Evaluation hygiene is the oldest problem here. Reusing a holdout set adaptively turns it into a training set \citep{adaptive-data-analysis-holdout-reuse}, and the Ladder limits what a leaderboard reveals for the same reason \citep{ladder}. Agent optimizers inherit the problem. Wang et al.\ report that harness evolution on Terminal-Bench 2.1 does not beat simple test-time scaling under matched feedback and inference budgets, and that earlier work searched on the tasks it reported \citep{rethinkharness}. Meta-Harness states that it searches and scores on the same 89 TerminalBench-2 tasks \citep{meta-harness}. Removing held-out selection from a recursive self-evolving agent gives a perfect in-sample score and a 33-point drop on test \citep{nguyen2026rsea}. Single-lineage prompt optimization is reported to match or beat GEPA with fewer rollouts \citep{naiveprompt}, and one analysis pass of a coding agent over stored trajectories to beat SkillOpt on all four benchmarks tried \citep{codingagentsopt}. SkillsBench compares matched conditions with and without skills \citep{skillsbench}. Our protocol adds a scorer audit, gold files hidden from the optimizer, fresh final sets, matched budgets, and one-shot and seed controls.
