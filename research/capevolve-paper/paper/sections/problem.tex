\subsection{Scorer compliance}

The historical SpreadsheetBench scorer loads cell values with \texttt{openpyxl} in cached-value mode and does not recalculate. A formula written through \texttt{openpyxl} has no cached value, so it reads as empty and fails. In the verified-400 gold, \histFormulaGoldTasks{} of 400 tasks (\histFormulaGoldPct{}\%) have formula cells in the answer range. Correct formula outputs without cached values passed 0 of 30 checks under the as-saved scorer and 29 to 30 of 30 under LibreOffice recalculation (Appendix~\ref{app:scorer}).

Both metrics were recorded from the same output workbook, so the comparison within a scorer is fair. The headline is not. Gemma-4-31B moved from \histGemmaBaseSaved{} to 76.5 as saved (+\histGemmaDeltaSaved{}) but from \histGemmaBaseRecalc{} to a recalculated 75.4 to 78.6 (+\histGemmaDeltaRecalc{}). GPT-5.5 moved from \histGptBaseSaved{} as saved (+\histGptDeltaSaved{}) but started at \histGptBaseRecalc{} under recalculation and gained \histGptDeltaRecalc{}. Roughly \histGemmaCompliancePts{} and \histGptCompliancePts{} points of the two headline gains were formula-to-literal compliance. The recalculating scorer is not free of error either: with LibreOffice 25.8, 19 of 400 official gold files fail as outputs, and 4 tasks are unscorable under any path, so the ceiling on the 280-task test split is 98.6\%.

\subsection{Split reuse and gold visibility}

The historical SpreadsheetBench test-280 was scored in development runs and parts of it served for selection, and the airline test-20 and all 87 SkillsBench tasks were exposed in the same way (exposure ledger, 17 rows). A one-iteration run from an empty seed reached 85.6 on the same 280 tasks where an eight-round agent-optimize run reached 76.4; the earlier draft listed the second run only as a 62.9 no-capability control. Both are single runs with different seeds, so the point is not that one algorithm is better. It is that nobody could tell from the draft.

Gold answers sat in the directory bind-mounted into the agent container. We found no gold read in 2{,}049 retained agent rollouts, which is an absence of evidence: the retained rollouts are validation-split only, and the agents were never told about gold. The optimizer side is worse. In at least \goldOptimizerRuns{} Claude Code optimizer sessions the notes quote gold values or formulas, and distilled rules appear in champion prompts. One GPT-5.5 session read a prior run's sealed-test evaluation, 280 per-task results, and clustered failures by 55 test ids; its champion text is byte-identical to the earlier run's first candidate.

\subsection{Gate strictness and statistics}

The hill-climb gate accepts a candidate whose paired mean gain exceeds one standard error, after dropping tasks inside a candidate's edit footprint. We replayed \replayDecisions{} recorded decisions from \replayRuns{} runs. The recorded rule accepted \replayRecorded{}; an unmasked one-SE gate would have accepted \replayUnmasked{} and changed \replayFlipsUnmasked{} decisions, and it would have blocked the champion path in \replayBlockedRuns{} of \replayPathRuns{} runs whose champions later gained on the (exposed) test split. All four recorded-versus-unmasked mismatches in hill-climb runs were a dropped task, not footprint masking, so the footprint concern rests on code and simulation. The replay is descriptive: the runs are replicates, and no artifact re-measures a candidate on fresh trials, so a two-stage rule cannot be replayed.

On the statistics side, the shared helper for standard errors adds within-task noise to a variance that already contains it. In simulation its variance is 12 to 33\% too large for a new-task estimand and 1.2 to 8.6 times too large for a fixed-task one (Appendix~\ref{app:sim}). We do not report it. Section~\ref{sec:setup:stats} gives the replacement.
