\section{Introduction}
\label{sec:intro}

Agent optimizers edit the files around a frozen model, such as the system prompt, tool code and skill packages \citep{agent_skills_docs}, and report large gains \citep{skillopt,meta-harness}. Published methods span prompt and pipeline optimization \citep{dspy,miprov2-dspy,gepa}, skills \citep{skillopt,evoskill,trace2skill,wikiskill}, context playbooks \citep{ace} and harness search \citep{meta-harness,xu2026harnesslens}. Each paper uses its own benchmark, split, scorer, budget and optimizer model, so the numbers cannot be compared. We ask a measurement question: measured on tasks the search never used for design, at a matched rollout budget, with gold isolated and one error classifier, how much do frozen-weight agent optimizers gain, and what does the acceptance gate cost or buy?

The question is not idle. We audited the history of \capevolve{}, the optimizer we also run here, and its reported gains were inflated. An earlier draft reported a Gemma-4-31B gain of \histGemmaDeltaSaved{} points on SpreadsheetBench. Recomputed from the run artifacts, the same outputs gain \histGemmaDeltaRecalc{} points once formulas are recalculated, because the original scorer reads cached cell values and so rewards literals over formulas. Scorer compliance accounts for \histGemmaComplianceShare{}\% of the Gemma gain and \histGptComplianceShare{}\% of the GPT-5.5 gain (Section~\ref{sec:problem}). The test split had also been scored in development runs, and optimizer sessions had read gold workbooks.

We make four contributions, in the order the paper presents them.
\begin{enumerate}[leftmargin=*,nosep]
\item An audit of historical gains that separates scorer compliance, development reuse, gold access and gate strictness (Section~\ref{sec:problem}).
\item A measurement protocol (Figure~\ref{fig:pipeline}, Section~\ref{sec:setup}): a recalculating scorer, gold isolation, one error classifier, a matched rollout checkpoint, pre-specified paired contrasts with an equivalence rule, and final sets whose exposure we state exactly.
\item A matched comparison of \capevolve{} with nine other optimizers and two controls on three suites, run from official code where it exists, with configurations, costs and incidents reported (Section~\ref{sec:results}, Appendices~\ref{app:config} and~\ref{app:incidents}). \needs{Headline findings after the final evaluation.}
\item The gate trade-off as a finding. Our promotion rule is deliberately conservative: in a null search of about ten candidates it falsely promotes in \simPFalseB{} to \simPFalseC{} of searches, against \simKoneFalseB{} to \simKoneFalseA{} for a one-standard-error gate, and it promotes a true 8-point gain in \simPPowerEightB{} (Suite B) of searches. Stock-gate runs on Suites A and C show what the gate buys and costs (Sections~\ref{sec:method:P} and~\ref{sec:discussion}).
\end{enumerate}
Section~\ref{sec:method} describes \capevolve{}, whose editable surface is a parameter of one loop with two search algorithms, and Section~\ref{sec:related} places the study against prior work.
