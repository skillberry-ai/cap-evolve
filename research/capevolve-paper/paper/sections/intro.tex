\section{Introduction}
\label{sec:intro}

Agent optimizers edit the files around a frozen model, such as the system prompt, tool code and skill packages \citep{agent_skills_docs}, and report large gains \citep{skillopt,meta-harness}. Published methods span prompt and pipeline optimization \citep{dspy,miprov2-dspy,gepa}, skills \citep{skillopt,evoskill,trace2skill,wikiskill}, context playbooks \citep{ace} and harness search \citep{meta-harness,xu2026harnesslens}. Each paper uses its own benchmark, split, scorer, budget and optimizer model, so the numbers cannot be compared.

One optimizer's own history shows how a gain can mislead. An earlier \capevolve{} draft reported a Gemma-4-31B gain of \histGemmaDeltaSaved{} points on SpreadsheetBench. Recomputed from the run artifacts, the same outputs gain \histGemmaDeltaRecalc{} points once formulas are recalculated, because the original scorer reads cached cell values and so rewards literals over formulas (Section~\ref{sec:problem}). The held-out split had also been scored in earlier development runs, and optimizer sessions had read gold workbooks from a directory mounted beside the task inputs.

We therefore ask which optimizer finds the best artifact under a protocol fixed before any final-set score is seen. The protocol has five parts. A functional scorer is reported next to the legacy one. Gold isolation is checked by a negative test for every agentic proposer. One promotion rule, chosen by simulation, governs both \capevolve{} algorithms (Section~\ref{sec:method:P}). Arms are compared at a matched rollout checkpoint rather than a nominal budget (Section~\ref{sec:setup}). Final tasks are not used by search, scored once, and analysed with paired, family-clustered statistics (Section~\ref{sec:setup:stats}). Figure~\ref{fig:pipeline} shows the pipeline.

Within this protocol we compare \capevolve{}, whose editable surface is a parameter of one loop with two search algorithms (Section~\ref{sec:method}), against nine competing methods run from official code (a community port for WikiSkill) and two controls, an unoptimized seed artifact and a one-shot repair. The suites are SpreadsheetBench (Suite A, Gemma-4-31B target) and $\tau^2$-bench retail (Suite B) and airline (Suite C); the two $\tau^2$ suites are descriptive because their final sets are small. Claude Sonnet 5.5 is the optimizer for every matched arm. If a control or a simpler method wins, that is the main result.

We make three contributions.
\begin{enumerate}[leftmargin=*,nosep]
\item An audit of historical results. Scorer compliance explains \histGemmaCompliancePts{} of \histGemmaDeltaSaved{} and \histGptCompliancePts{} of \histGptDeltaSaved{} reported points, and a stricter gate would change \replayFlipsUnmasked{} of \replayDecisions{} recorded decisions (Section~\ref{sec:problem}).
\item A measurement protocol with stated operating characteristics: its promotion rule is underpowered by design, promoting a true $+0.08$ gain with probability \simPPowerEightB{} on Suite B (\simPPowerEightC{} on C and \simPPowerEightA{} on A) (Section~\ref{sec:method:P}, Appendix~\ref{app:sim}).
\item A matched-checkpoint comparison with full configurations, costs and incidents (Section~\ref{sec:results}, Appendices~\ref{app:config} and~\ref{app:incidents}). Section~\ref{sec:discussion} discusses the results and Section~\ref{sec:related} places them against prior work. \needs{Headline findings paragraph after the final evaluation.}
\end{enumerate}
