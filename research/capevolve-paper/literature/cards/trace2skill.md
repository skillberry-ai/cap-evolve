- Editable surface: a skill directory S=(SKILL.md root + references/ scripts/ assets) [Sec 2.1]; patches converted to diff-style edits with guardrails (reject edits to missing files, withhold line-range conflicts, format validation). Starts from human-written skill (deepening) or LLM draft (creation).
- Search method: NOT an iterative search -- one-shot distillation. Stage 1: roll out frozen agent with S0 on evolve set; Stage 2: 128 parallel analyst sub-agents, one patch per trajectory (error analyst = ReAct agent that inspects artifacts, compares to ground truth, validates candidate fix; unexplained failures dropped; success analyst = single pass); Stage 3: hierarchical LLM merge, B_merge=32, ceil(log) levels, dedupe/resolve conflicts/prefer recurrent patterns; apply ALL patches. Optional selective aggregation: greedy top-1 and Bayesian-optimisation over patch-inclusion vectors, scored on a 32-task validation subset of the evolve set (Sec 4.3, App E). No archive, no cross-iteration memory.
- Feedback signal: binary correctness + traces + ground-truth answers/artifacts for error analyst.
- Task splits / held-out [Sec 3.1, App A p.13]: SpreadsheetBench-Verified 400 = 200 evolve (0:200) / 200 held-out test (200:400), "no held-out sample used during skill evolution". Caveat (App G): evolve slice mixes 125 sheet-level + 75 cell-level tasks, test slice is cell-only (distribution shift). Also full SpreadsheetBench Soft/Hard on 2,529 (evolve problems removed), OOD WikiTQ 2,810 and HiTab 1,585 converted to spreadsheet tasks. Math: skills from 400 DAPO q, test 100 disjoint DAPO + AIME 2026 (avg@8, 30 problems). DocVQA: 50 for evolution, 5,299 test. Results averaged over 3 seeds (41,42,43), SDs in Table 7. Test not used for selection in default path; BO/greedy use evolve-set val (32 tasks). Not tuned on test as far as stated.
- Benchmarks and models: SpreadsheetBench-Verified/full, WikiTQ, HiTab, DAPO-Math, AIME 2026, DocVQA, VRDU->VAREX, TSBench, OfficeBench-DOCX. Qwen3.5-122B-A10B and 35B-A3B (author and user, self-evolution), Gemma-4-31B-it and GPT-5.5-high (cross-family, Fig 3). Head-to-head baselines reproduced by authors (App G). No OfficeQA, no SkillsBench.
- Metrics: SpreadsheetBench Vrf (verified instance accuracy), Soft, Hard; accuracy; ANLS; avg@8; Avg = (ID+OOD)/2.
- Budget / cost reporting: ~20,000 A100 GPU-hours for all experiments (App A p.13); skill-generation wall-clock Parallel ~3 min vs Seq-B=4 ~15 min vs Seq-B=1 ~60 min (Table 4, App B.1). No tokens/$; no matched-budget comparison against EvoSkill (App G reproductions are not budget-matched; EvoSkill used 8 iterations Claude Code / 5 iterations ReAct).
- Reported limitations: BO selection is costly and needs a large representative validation set (32 tasks used) (Limitations p.10).
- Key quantitative results: Table 1 (p.4), user 122B SpreadsheetBench-Vrf: No Skill 27.67, Human-Written (Anthropic xlsx) 48.33; 122B-authored Deepening +Combined +21.50 (=69.83, consistent with Table 5). Same table: official xlsx skill HURTS the 35B user (Vrf 19.00 -> 9.67). WikiTQ +57.65 (35B-authored Creation +Error on 122B user, delta vs Parametric 23.73) -- the review's "large transfer gain". Table 4 (122B Vrf, +Error): Parallel 65.83 vs Seq-B=4 59.00 vs Seq-B=1 61.83. Table 5: ReasoningBank 56.00 vs ours 69.83 (122B Vrf). Table 6: all patches 65.83 vs BO-selected 69.83 (Vrf). Fig 7 / App G (122B, test 200:400, Vrf): No Skill 27.7, Human 48.3, XSkill 23.0, SkillGen 27.5, EvoSkill Claude-Code harness 33.5, EvoSkill ReAct harness 59.5, Trace2Skill +Error 65.8, +Combined 69.8. Broader (p.9): PDF 76.9->85.3, PPTX 72.5->88.8, DOCX 79.7->87.5.
- Candidate-evaluation allocation: none by default (all patches applied); BO/greedy evaluate each subset on 32-task val (costly).
- Task selection / curriculum: all evolve-set trajectories analysed; failures causally unexplained are excluded.
- Merge/composition: central: hierarchical LLM merge of many patches; merge is not verified per patch by default (finding: patch value is combinatorial; greedy selection plateaus below full aggregation, Fig 5).
- Optimizer self-modification: none; same frozen model is trajectory generator, analyst and merger.
- Overlap with CapEvolve: medium. It is the cheap "trace-to-one-skill" control: our hill-climb's "one large multi-part edit from failure clusters + trajectories" is conceptually this plus a gate. Merging/patch-combinatorics findings relevant to our branch-merge.
- What it means for our claims: need a Trace2Skill-style single-pass distillation arm at matched token budget to show iterative search is worth its cost; do not claim novelty for parallel/clustered failure consolidation. Its SpreadsheetBench split (0:200 / 200:400, Vrf) is a usable disjoint protocol; note slice shift.
