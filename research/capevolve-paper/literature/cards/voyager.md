- Citation count: unavailable (Semantic Scholar 429)
- Editable surface: an ever-growing library of executable JavaScript skills (code), indexed by embeddings of GPT-3.5-written descriptions; plus an automatic task curriculum (prompted) -- the "agent" is code actions over Mineflayer APIs (Sec 2.2, p.4).
- Search method: no optimization over candidates. Loop: curriculum (GPT-4) proposes next task from state + completed/failed tasks; top-5 skills retrieved; iterative prompting (env feedback, execution errors, GPT-4 self-verification critic) up to 4 rounds; verified program is added to skill library (Sec 2.1-2.3, p.3-6). Memory = skill library + completed/failed task lists. No archive selection, no pruning.
- Feedback signal: environment text feedback (bot.chat), interpreter errors, and an LLM self-verifier success/critique (no ground-truth labels) (p.5).
- Task splits / held-out protocol: no train/val/test; exploration is open-ended. "Held-out" = zero-shot generalization to 4 unseen tasks in a freshly instantiated world with cleared inventory using the learned library (Sec 3.3, Table 2, p.8). 3 runs per setting.
- Benchmarks and models: Minecraft via MineDojo + Mineflayer; GPT-4-0314 (code/curriculum/verifier), GPT-3.5-turbo-0301 (descriptions, questions), text-embedding-ada-002 (p.6). Baselines re-interpreted: ReAct, Reflexion, AutoGPT (p.6-7).
- Metrics: unique items discovered, tech-tree milestone speed (prompting iterations), distance travelled, zero-shot task success.
- Budget / cost reporting: budgets counted in prompting iterations (160 for exploration/tech tree; 50 for zero-shot) -- iterations, not tokens/$ (Tables 1-2). Limitation notes GPT-4 is 15x more expensive than GPT-3.5; no $ totals reported in main text.
- Reported limitations: API cost; agent can still get stuck; verifier occasionally wrong (e.g., spider string); curriculum/code hallucinations (Sec 4, p.10).
- Key quantitative results: 63 unique items in 160 iterations, 3.3x prior SOTA (text p.7); tech tree iterations to unlock (Table 1 p.7): wooden 6+-2, stone 11+-2, iron 21+-7 (3/3 each), diamond 102 (1/3); AutoGPT iron 135+-103, ReAct/Reflexion 0/3 at all levels. Zero-shot (Table 2 p.8): Voyager 19/18/21/18 iterations (3/3 each) vs Voyager w/o skill library 36 (2/3) /30/27/26; AutoGPT+our library 39 (1/3), 30 (1/3), N/A, 30 (2/3); ReAct/Reflexion/AutoGPT 0/3. Ablations (Fig 9, p.8-9): random curriculum -93% items, no self-verification -73%, GPT-3.5 for code gives 5.7x fewer items than GPT-4 (text p.8-9; plot values UNVERIFIED).
- Candidate-evaluation allocation: n/a (no candidate set); only self-verification gate decides whether a skill enters the library.
- Task selection / curriculum: yes -- automatic bottom-up curriculum via GPT-4 conditioned on agent state and success/fail history; ablation shows it is crucial (p.8). Retry limit of 4 code rounds then ask curriculum for another task.
- Merge/composition: skills compose by calling earlier skills (compositional programs); no branch merging; composed-skill correctness only checked by the same self-verifier.
- Optimizer self-modification: none (prompts fixed); human-in-the-loop variants shown (Fig 10).
- Overlap with CapEvolve: reusable executable skill library with retrieval, self-verification before commit, and curriculum over tasks -- historical ancestor of "skill package" surfaces and of task selection by capability frontier. Different regime: lifelong online learning in one stream, no held-out score.
- What it means for our claims: cannot claim first "skills as executable code accumulated by agent with verifier-gated commit". Only fair to compare mechanism-level; no direct benchmark overlap. Our contrast is held-out measurement, paired gating and budget accounting that Voyager lacks (3 seeds, no CIs, iteration-count budget). Reproduction feasibility: low (Minecraft stack, GPT-4-0314 API retired/unavailable; repo inactive since 2024).
