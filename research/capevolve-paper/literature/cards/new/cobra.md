- Citation count: unavailable
- Editable surface: a single textual skill (Markdown skill injected into agent context); target model frozen. No tool code / MCP / multi-file packages (p3, p17 A.2 "only the textual skill is modified").
- Search method: population of K=10 skills; each round LinUCB-style priority U_t(s)=f_theta(z_s)+nu*sqrt(z^T A^-1 z) over Qwen3-Embedding-4B embeddings (2560-d) with 2560->64->1 MLP reward predictor refit on all history (p5, Eq.2-4, Alg.1 p4). Highest-U skill is evaluated on the full 50-example optimization set. On a logarithmic schedule (d=3, eta=0.35) the m=3 lowest-priority skills are pruned and replaced by regeneration (from no-skill trajectories), rollout mutation (8 trajectories of the just-evaluated skill), or crossover (backbone + 1 positive strong skill + 2 negative weak skills; ratio 2:1:0 then 1:1:1) (p5, p16). Archive = bounded population (10) + full evaluation history H_t and trajectory archive. Selection: arm pick by UCB; final output = skill with highest mean observed reward in H_T (Alg.1 l.18; Table 5 p17 "Highest mean online reward"). Memory: history H_t feeds reward model; no explicit failed-edit memory (negative evidence = low-scoring skills used as crossover negatives).
- Feedback signal: binary accuracy per benchmark (SocialMaze soft 0/0.5/1) from target-agent execution plus trajectories; teacher GPT-5.5 (medium) writes skills from trajectories.
- Task splits / held-out protocol: fixed 50-example optimization set D_opt per benchmark (used for BOTH candidate scoring and final selection; no separate val split for COBRA); held-out test = 100 examples, "never used for trajectory analysis, skill construction, or candidate selection" (p16 A.2). Baselines SkillOpt/Trace2Skill get 2-3x larger pools (120-170 examples, SkillOpt split e.g. 100/50). 3 independent runs, mean +/- SE.
- Benchmarks and models: SearchQA, SpreadsheetBench, DocVQA, LiveMathematicianBench, SocialMaze (HRD), ALFWorld; targets Qwen3.6-35B-A3B, GPT-5.4-Nano, Gemma-4-26B-A4B-it; also Claude Code and Codex harnesses with Qwen3.6 (Table 3 p7); self-teaching variant (Sec 5.2).
- Metrics: accuracy (%) per benchmark and average; optimization cost USD and cost per point of improvement (Table 2 p6).
- Budget/cost reporting: yes; teacher/target tokens (M) and USD at fixed per-M-token prices (Table 6, App B.1). COBRA vs SkillOpt: cost $54.10 vs $121.02 (Qwen), $58.46 vs $133.59 (GPT-Nano), $38.98 vs $92.14 (Gemma) (Table 2 p6). Unclear whether failed/ablation runs or test evaluation are in cost (UNVERIFIED).
- Reported limitations: no dedicated limitations section found in text (UNVERIFIED by search for "Limitation").
- Key quantitative results: Avg test Qwen 73.5+/-1.0 vs SkillOpt 69.6+/-0.6, no-skill 60.4 (Table 1 p6); GPT-Nano 56.9 vs 53.7 vs 30.0; Gemma 68.9 vs 67.6 vs 46.4. Ablation on Qwen (Table 4 p10): Best-of-30 71.0, w/o Evolution 71.1, w/o Bandit 71.3, full 73.5 (each ~-2.2 to -2.5, SE up to 1.5, n=3 runs -> differences are about 1-2 SE). Claim: 55-58% lower cost than SkillOpt (p8).
- Candidate-evaluation allocation: one candidate per round, always evaluated on all 50 examples (full-set); allocation is across candidates (arm selection), not across tasks. Neural predictor + LinUCB bonus on skill embeddings; no per-task posterior, no cheap-subset triage.
- Task selection/curriculum: none; fixed 50-example set composition-matched to benchmark.
- Merge/composition (verified?): crossover = LLM rewrite of a backbone skill using strong/weak skills as evidence ("without directly concatenating"); the child is NOT gated on creation, it re-enters the bandit with no inherited reward and is evaluated like any candidate (p2, p5). Verification is therefore indirect (later full evaluation), not a paired gate vs parent.
- Optimizer self-modification: none (SkillOpt-style meta-skill memory only in the baseline).
- Overlap with CapEvolve: direct overlap on claim (a) budget-aware allocation of evaluation across candidates (bandit/UCB over embeddings) and on candidate-DAG-like populations with merges (b, weakly). Not on (c) heterogeneous surfaces, (d), (e), (f).
- What it means for our claims: (a) "adaptive allocation across candidates" is NOT novel; narrow claim must be per-task posterior/triage under a paired gate, not arm-level UCB. (b) "merging" prior art exists (crossover) but is unvalidated before entering search; our verified merge remains distinct. Required comparison: COBRA-style UCB allocation vs ours on equal teacher+target spend, with separate val and sealed test. Reproduction feasibility: high (Apache-2.0 code, YAML configs).
- Notes on evidence quality: 3 seeds, SE reported; final selection on the same 50 examples used for scoring all 30 rounds (winner's curse, no independent val) while baselines use a separate selection split and larger pools (cost of unequal data budgets, p17-18); baselines re-implemented/adapted under custom budgets; test n=100 per benchmark so avg SE is coarse; ablation margins small relative to SE.
