# SkillCommit (slug: skillcommit)
- Exact title: SkillCommit: Evolving Agent Skills through Behaviorally Validated Scope Expansion
- Authors: Yu He, Weikai Yang (2; Nanjing U., HKUST-GZ)
- arXiv id + version read: 2608.15165v1

- Code URL + license: none stated (no github string in text) -> unverified. OpenAI-compatible: unverified.
- Citation count: unavailable
- Editable surface: a hierarchical library of text skills (instance-level patches -> higher-level skills with when / repair / avoid_when fields); not tools/prompts/MCP.
- Search method: online, per failed task: (1) feedback-guided patch induction: teacher sees failed trajectory + ground truth, writes a patch (no answer leakage), validated by replaying the source instance with the frozen executor, up to K=3 attempts (88.0% of failures yield a validated patch; p3); (2) behavioral compatibility grouping: embedding retrieval (top R=4 active skills), cross-instance replay score C(p,q)=(rho(p,x_t)+sum rho(q,x_j))/(1+|W(p)|) >= gamma plus an LLM mechanism check; (3) source-preserving consolidation: a pattern author (blind to answers) abstracts a group or expands a skill; candidate is committed only if it replays successfully on EVERY source instance in its scope (refine up to L attempts), else SPLIT to the replay-supported subset (>= m=2/3 sources, revalidated) or REJECT (p3-4). Archive = growing hierarchical library with versioned skills; no incumbent/gate against a parent score; all candidate versions with replay outcomes are retained for audit.
- Merge/composition (verified?): YES, merging/abstraction of patches into a higher-level skill is gated by full-scope source replay (and cross-instance replay for grouping): this is behaviorally VERIFIED consolidation (p3-4). Verification is on the same induction instances that produced the patches (not held-out), pass/fail on every source, not statistical.
- Feedback signal: benchmark verifier (strict accuracy or macro-F1) on replays; teacher with privileged ground truth during patch induction.
- Task splits / held-out protocol: induction vs held-out test splits per dataset: RuleArena Airline 100/100, NBA 170/45; OpenExempt EC and EV 210 induction/105 test each; KOR-Bench Logic and Cipher 175/75 each; test only for evaluation (p5). No separate validation split; commit decisions use replay on induction sources. Seeds/repeats not stated (grep found no 'seed'); appendices with budgets/hyperparameters not included in this PDF version (9 pages) -> UNVERIFIED.
- Benchmarks and models: RuleArena (Airline, NBA), OpenExempt (EC, EV), KOR-Bench (Logic, Cipher); executors DeepSeek-V4-Flash and Qwen3.6-35B-A3B (matched author=user), Qwen3.5-9B as user with Qwen3.6-35B-A3B or GPT-5.4 as skill author (p5-6).
- Metrics: strict accuracy; macro-F1 for OpenExempt; help/hurt counts vs No Skill (Fig 3).
- Budget/cost reporting: none found in main text (words 'cost' only motivation; 'budgets' deferred to an appendix not in PDF). Replay/teacher token cost not reported.
- Reported limitations: none found (no Limitations section).
- Key quantitative results: Table 1 p6: DeepSeek-V4-Flash avg 87.57 vs No Skill 68.24 (ExpeL 73.09, ReasoningBank 62.82, ACE 63.89, Trace2Skill 63.34); Qwen3.6-35B-A3B 77.27 vs 47.25; Qwen3.5-9B user also in Table 1. Mean over all 18 pairs 50.80 -> 78.15 (p5). 31 of 72 competing-method results fall below No Skill. Fig 3 p5: Airline SkillCommit +24 help, ExpeL +16 net etc. Ablation (RuleArena NBA, 45 test cases): full 71.11; w/o patch induction 53.33; w/o grouping 66.67; w/o consolidation 66.67; patch induction only 64.44; grouping only 60.00; consolidation only 57.78 (p6-7, Table 2).
- Candidate-evaluation allocation: no allocation policy; every candidate fully replayed on all sources in its scope (cost grows with scope size).
- Task selection/curriculum: online stream; only failures trigger patches; no curriculum.
- Optimizer self-modification: none.
- Overlap with CapEvolve: HIGH on (b): merging/abstraction of candidate units validated by behavior replay on all constituents (a strict no-regression-on-sources criterion) with split/reject fallback. Not on (a),(c),(d),(e),(f) (replay feedback to the author is like iterated critique; rejected patches/trajectories are fed back to the author during refinement, a local failed-edit memory).
- What it means for our claims: (b) "verified merging" is not novel in the skill-library setting; our claim must be restricted to merging of whole candidate lineages in a DAG under a paired statistical gate on held-out validation with sealed test, and to heterogeneous surfaces. Required comparison: SkillCommit-style all-source replay vs our merge gate (compute/regression trade-off). Reproduction feasibility: low-medium (no code, appendix missing, many components).
- Notes on evidence quality: strong gains reported but no seeds/CIs, small test sets (45-105 cases; one NBA case = 2.2 pts), baselines (ExpeL, ReasoningBank, ACE, Trace2Skill) adapted by authors to the same interface (p5) and frequently below No Skill, which may reflect weak adaptation; teacher uses privileged ground truth during induction (benchmarks with verifiable answers); consolidation validated on induction instances (in-sample).
