- Editable surface: theta=(prompt, tool, middleware) (Eq.1 p4): system prompts/rules, tool code (new tool, arg mods, implementation fix), TOOL DESCRIPTIONS (docstrings), PreToolUse hooks, agent-loop logic, infra config (Table 1 p6). Skill/memory curation explicitly excluded (p4). Coding-agent editing of harness source; edits restricted to functional-logic files, eval/benchmark code not exposed (p5).
- Search method: offline mini-batch loop: eval H_n on train mini-batch -> Diagnosis-Patch agent (structured patch in Prompt/Tool/Middleware taxonomy; Capability vs Steering patches, phased schedule capability first, then steering) -> verify on same mini-batch -> if improved evaluate on dev set -> Reflection agent (fixed/regressed/still-failing/still-passing) -> store in EvoDAG -> Evolution agent proposes H_{n+1} possibly composing elements from ANY subset of previously explored harnesses (p6). Three agents implemented with Claude Agent SDK, Claude Opus 4.6.
- Archive / selection / merge / memory: EvoDAG = DAG of explored harnesses with lessons and scores; edges are diffs; cherry-pick merges, rebases, reverts of harmful changes (App. J, p25-26: rebase to I13 after I20 collapse to 33.8%; I46 merged 8 cherry-picked hooks/rules -> -12.3pp, I47 pruned to 4). Final selection: highest dev score among candidates evaluated on dev within rollout budget K (p4).
- Feedback signal: pass/fail per task from gold outcomes; per-task before/after transition categories; traces.
- Task splits / held-out: train/dev/test by disjoint task group (GAIA2 Universe 29 (75 tasks) / Universe 30 (65) / test Universes 21,22,27 (107+112+81); SBP train qutebrowser 79, dev Vuls+NodeBB 40+40, test Ansible 96, Flipt 85, Element-web 56; TB2 random 30 train/19 dev/40 test) (Table 6, p20). "selected harness evaluated once on the held-out test set and is not further modified using test feedback" (p5). One optimization run per method; 3 repeated TEST evaluations (p7). Meta-Harness given train+dev union (fn 4 p8).
- Benchmarks and models: GAIA2 (ReAct base), SWE-Bench Pro (SWE-agent base), Terminal-Bench 2.0 (Terminus 2 base); Claude Opus 4.6 for optimizer and task agent; transfer to Haiku 4.5 (App. E).
- Metrics: Pass@1 mean+-sd over 3 test runs; dev accuracy curves; fix/regression rates; patch acceptance rates.
- Budget/cost reporting: YES, notable. Budget = rollouts (K) and epochs: AutoSaddler & GEPA 2 epochs (GAIA2, SBP), 4 epochs (TB2); Meta-Harness matched on total task executions (20/15/8 epochs) (App. B, p20). Fig 1a p2: AutoSaddler 72.3% dev with ~1,000 task executions vs GEPA 64.6 / Meta-Harness 61.5 at ~2,800. Optimizer-side cost App. I (p24): $14.56/patch AutoSaddler vs ~$12.65 Meta-Harness vs $5.50 GEPA; 533 s vs 883 s per patch. 21 of 51 candidates reached dev evaluation (App J) = cheap-first (mini-batch) gating then dev: "selective evaluation".
- Reported limitations (App. R, p44): needs gold labels/task-level metric; stateless independent tasks only; no memory/skill curation; broader LLM families unvalidated; recommends human review before deployment.
- Key results: Table 2 p7 GAIA2 test avg: default 53.0, GEPA 54.6, Meta-Harness 53.2, AutoSaddler 62.0+-1.2. - Candidate-evaluation allocation: sequential gate: mini-batch (train) paired before/after -> only improving candidates promoted to dev set (cheap-first triage then confirmation); no Bayesian/posterior allocation; no bandit.
- Task selection/curriculum: mini-batches sampled from train; phased patch scheduling (capability then steering) is a curriculum on edit types, not tasks.
- Merge/composition (verified?): Evolution agent composes/cherry-picks from multiple lineages; merged harness then re-enters the same mini-batch + dev gate (so merges are verified by gate, not by separate component-wise check); merge failures observed (I46).
- Optimizer self-modification: none; optimizer agents/instructions fixed (App. P); explicitly not self-referential (p3).
