- Authors: Subhojyoti Mukherjee, Md Mehrab Tanjim (Adobe Research)

- Code URL + license: none; "We will release all harness code, evaluation infrastructure, and cross-model logs" (abstract). License n/a; OpenAI-compatible: n/a.
- Citation count: unavailable
- Editable surface: a single Python harness class (init/run) wrapping an LLM client: prompts, routing, retries, verification loops, schema pruning, parsing; AST-GUARD whitelist (Layer 1) bans many imports/calls; per-domain markdown "skills" (proposer_skill.md, proposer_<domain>.md, safety_<domain>.md) steer the PROPOSER (they are not the optimized artifact).
- Search method: Meta-Harness-style propose-evaluate-log loop with Claude Code as agentic proposer having filesystem access to prior candidates, scores, traces and CLI tools list/top/pareto/diff/show (p4); single structural mutation per iteration from a fixed action set (p5); acceptance requires strict improvement of scalar R = accuracy + lambda_s*safety - lambda_t*tokens (Eq.3, lambda_s=1.0; 1k tokens = 1pp), while the proposer sees the raw three axes.
- Archive / selection / merge / memory: filesystem history of all candidates (proposer reads median 82 files/iteration, p6); argmax R returned; Pareto "pool" mentioned; no merge; failed candidates remain on disk (memory implicit via filesystem) -- claim (e) overlap is implicit.
- Feedback signal: per-example scores, tokens_used, traces.jsonl; domain-specific reward; LLM-judge for U-SafeBench safety domains (judge agreement kappa 0.77-0.94 on 30-60 items, p35).
- Task splits / held-out: per domain 50 search examples (visible to proposer) and 50 disjoint test examples (never read by proposer, p3, p6); seven real-world benchmarks (HumanEval, MBPP, Spider, FEVER, MMLU-Pro, LawBench, NuminaMath) evaluated with harnesses found on synthetic track, zero search cost (p6). Synthetic datasets are LLM-generated. Harnesses discovered with Claude Haiku 4.5 and evaluated unchanged on a 12-model fleet.
- Benchmarks and models: 17 domains (7 synthetic capability, 3 U-SafeBench-derived safety, 7 real-world); 12 models (Table 1 p6) incl. Claude Opus 4.5, GPT-5.2/5.4, Sonnet 4.5/4.6, GPT-4.1, o4-mini, DeepSeek-R1, Haiku 4.5, Gemini 3.1 Flash-Lite.
- Metrics: accuracy, behavioral safety composite, tokens/example, joint score J = acc*Safe/ln(tokens) (Eq.4 p7; author-defined), hypervolume.
- Budget/cost reporting: search budget ~100 harness evaluations per synthetic domain (range 98-106; 724 total across seven), ~25 each for the three safety domains (p6); gate funnel: only ~30% of ~100 proposer calls reach acceptance (p5); proposer cost "deferred to future work" (p6) but later says token cost comparable to APE and lower than 2-phase and DSPy (Limitations p10, Sec N.1). No dollar totals in main text.
- Reported limitations (p10): search uses LLM-generated 50-example datasets; ~100 proposer API calls per domain; transfer degrades on some models (cut off in text read).
- Key results: abstract p1: synthetic joint mean 0.482 vs 0.198-0.422 for ten baselines (+0.060 over TextGrad), wins 7/10; real-world 0.461 vs DSPy 0.377, wins 5/7 (Table 2 p7, Table 3 p8); safety composite 0.781 vs TextGrad 0.747; single-phase beats 2-phase by +2.7 points with 95 fewer tokens/example; hypervolume 0.481 vs MH 0.362.
- Candidate-evaluation allocation: four-gate funnel: AST-GUARD -> mock-run on dummy examples (catches ~90% malformed candidates without API calls) -> budgeted screening eval on the 50-example search set (100k tokens, 200 API calls, 300 s guard) -> joint-reward floor (running best minus margin) -> strict-improvement acceptance (p5, p35). This is a cheap-first screening cascade at candidate level, not task-level adaptive.
- Task selection/curriculum: none; per-domain skill files.
- Merge/composition: none.
- Optimizer self-modification: none (proposer skills are human-written files).
- Overlap with CapEvolve: medium. (f) controller is Claude Code with filesystem (same family as our agent-controller idea, but pipeline is a fixed loop); (a) screening funnel with budget guard; (c) not (Python harness code only). Multi-objective with tokens/safety is not our target.
- What it means for our claims: (f) prior art for coding agent as the proposer (already true of Meta-Harness) -- we must claim only the agent-driven CONTROL of the search (promote/prune/merge), not the proposing. (a) cheap-gate cascade exists but fixed, not posterior-based. Required comparison: Meta-Harness-style single-proposer loop at matched evals (they use MH as primary baseline). Reproduction: low-med (code to be released; 12-model fleet expensive).
- Evidence quality: one search run per domain apparently (no search seeds stated, UNVERIFIED); SEM computed across models x examples (cells "N_trials ~ 12x50") treats model fleet as trials, understates search variance; synthetic data LLM-generated and judged by LLM; J metric is author-defined and mixes variant-level Safe composite; baselines run on fixed harness skeleton ("qualitatively different search space"); real-world track is OOD transfer of synthetic-track harnesses with no search seeds.
