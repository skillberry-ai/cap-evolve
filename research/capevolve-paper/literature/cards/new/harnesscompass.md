# harnesscompass (SHORT)
- Title: HarnessCompass: Guiding Automatic Harness Evolution toward Generalizable and Effective Agent Harnesses
- Authors: Luan Zhang, Ruochen Zhou, Dandan Song, et al. (12 authors total; BIT / CityU HK)
- arXiv 2608.01918 v1; first 2026-08-03 (latest v1). Venue: "Preprint. Under review" (PDF p.1); no venue claimed. Code URL: none stated in text.
- Editable surface: 7 component types: system prompt, tool descriptions, tool implementations, middleware, sub-agent configs, skills, long-term memory (Fig.1 p.2). Split into structural (code) vs guidance tracks.
- Search: single-incumbent evaluate-analyze-improve loop (AHE-style); each round evolves 2 variants in parallel (structure track / guidance track), picks the one with higher Pass@1 as winner, then "R3" (Revision/Recombination/Refinement) LLM-merge of loser's edits into winner (Alg.1 p.3, p.5). Generalization gate = LLM rule rejecting task-specific edits; first-person agent feedback grounded against trajectories.
- Evaluation: full re-roll of every candidate on the 50-task evolution set (Pass@1, k rollouts); accept if Pass@1 improves (Alg.1 l.12). No subset/bandit/Bayesian allocation. Held-out: 450 disjoint SWE-bench Verified tasks never exposed to evolution, reported only (Table 1 p.5) -- not used for selection.
- Headline: GPT-5.4 non-thinking: 54.0% -> 66.0% on evolution sample in 5 turns (AHE 63.0% in 20); held-out 60.4% vs AHE 54.7% vs seed 51.6%; total 61.0% vs 55.5% vs 51.8% (Table 1, p.5). Frozen harness on Claude-Sonnet-4.6 total 70.0 -> 73.8 (Table 3, p.6). Ablation Table 2 p.6: adding feedback alone lowers held-out 58.4 -> 55.8; R3 restores 60.4.
- Budget: reported only as evolution turns (iterations); no token/dollar cost. Single run apparently (no seeds/CI stated; UNVERIFIED).
- RELEVANCE: MED. Threatens (b) partially: a merge of parallel edit tracks (R3), but LLM-judged merge, not verified by re-evaluation of merged result vs components (merged harness is only checked against the sample score, Alg.1 l.12); and (c) partially (multi-component incl. tool code, tool descriptions, skills; but no MCP exposure). Supports (d)-style held-out split (50/450) but no sealed-until-finalize protocol or accounting of failed search.
