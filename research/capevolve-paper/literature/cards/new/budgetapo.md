# budgetapo (FULL)
Exact title: How Should a Prompt Optimizer Spend a Tight Budget? BUDGETAPO with Noise-Adaptive Evaluation
Authors: Haoyue Liu, Zhichao Wang, Huanyu Yan, Xiaoying Tang (CUHK-Shenzhen; FNii-Shenzhen)

Editable surface: a single prompt string (seed "You are a helpful assistant."), rewritten for reasoning strategy and output format jointly. Prompt-only.
Search method: single-stage greedy hill-climb from the seed (single incumbent; no archive, merge, memory). Per round: optimizer LLM (GLM-5-FP8 default) sees the incumbent, its slice score and the first 3 failing rows and returns k=2 candidates; each scored on the SAME fixed slice; candidate replaces incumbent if slice mean strictly greater (Eq 7, p4). No significance test in the accept rule.
Feedback signal: per-row scorer in [0,1] (+ raw failing rows with constraint info).
Task splits / held-out protocol: per benchmark R_cal (training; 150, MBPP+ 78, LB-IF 100), R_opt = validation V (300 / 150), R_test (200 / 150) (Table 4, App C p15). BudgetAPO draws probe+slice from V; GEPA uses R_cal as trainset and R_opt as valset; OPRO/GrIPS/MIPROv2 sample R_cal. Final prompt scored once on test pool outside the budget; test not used for selection (p5, p12-13). Post-hoc "landing guards": runs with <95% of test rows scored or <80% of cap spent (at B>=250) are discarded/re-run (p15) -- a data-quality filter applied equally?; asymmetry UNVERIFIED.
Benchmarks and models: HotpotQA, CollIE, IFBench, SuperGPQA, generated StackEval, MBPP+, LiveBenchIF; subjects Gemma-4-31B, Qwen-3.5-27B, GPT-OSS-20B, Nemotron-3-Super-120B, Ministral-8B; optimizer GLM-5-FP8 (swap to Qwen-3.5-27B in Table 3).
Metrics: normalized test score (%); Wilcoxon signed-rank with Holm correction over 35 (subject,benchmark) cells, Cohen dz; seed-return rate.
Budget/cost reporting: budget = number of subject-model (prompt,row) evaluations on search rows only: B=250 default (sweep 100-1000). Optimizer-LLM calls and final test evaluation are FREE for all methods (p4, App C p15), following GEPA's counting. So optimizer token cost is not accounted.
Reported limitations: depends on optimizer LLM quality; text benchmarks only (p9). When subject optimizes its own prompt, OPRO leads at seed 0 (69.5 vs 67.4, p8).
Key quantitative results: Table 1 p5: 5-subject mean test 63.52 vs OPRO 61.54, aPSF 61.15, MIPROv2 61.03, GEPA 59.93, GrIPS 59.78 (no-opt 58.98 by benchmark average); gap +1.98; Table 1a per subject: Gemma-4-31B 71.57 vs GEPA 67.11. 630 runs (3 seeds). Fig 1b/p7: seed returned in 13% of BudgetAPO runs vs 86% GEPA (105 runs each); GEPA 71% on Gemma. Fig 1a/p6: GEPA needs 500 calls to match BudgetAPO's 100-call score (65.1 vs 64.9) on GPT-OSS-20B; on Gemma GEPA needs 1000 calls to match 250-call score. Table 2 p8 ablation (Gemma, 3 seeds): full 71.6; -adaptive slice 69.8; -fixed slice 70.2; -strategy 70.0; -failing rows 70.7; adaptive sizing worth 8.2 pts on HotpotQA but sizes mostly clamp-bound (lower clamp binds 34% of runs, p4). Fixed-slice reuse +1.4.
Candidate-evaluation allocation: NOISE-ADAPTIVE SLICE SIZING (pre-search): 16-row probe of the seed estimates per-row sd sigma_hat; slice size s = clamp(round((sigma_hat/tau)^2), 10, 30) with target SE tau=0.10 (Eq 2-4, p3-4); the same fixed ordered slice then scores all candidates (paired comparison). Not racing, not successive halving, not posterior; one-shot calibration from the SEED's noise, not candidates'. Trade-off: rounds T(s)=floor((B-16-s)/(k s)) (Eq 5). Cited as contrast: CAPO (Zehle et al., 2025) races candidates; TRIPLE (Shi et al., 2024) fixed-budget best-arm identification -- not compared against (App unverified).
Task selection/curriculum: fixed first-s rows of probe ordering; no per-task weighting.
Merge/composition (verified?): none.
Optimizer self-modification: none.
Overlap with CapEvolve: claim (a) directly: budget-aware, noise-adaptive evaluation allocation (slice size from measured task noise) and paired comparison on a fixed slice; hill-climb paired gate (we use mean(delta) > k*SE) is a stricter version of their greedy paired slice accept. Also compares to MIPROv2 and GEPA with official code under a tight-budget cap.
What it means for our claims: (a) is unsafe in generic form: "noise-adaptive evaluation sizing" and "paired fixed-slice comparison under a tight budget" are published (Oct 2026). Surviving niche: allocation across a candidate DAG with per-task Bayesian posteriors, cheap-subset triage plus full-val confirmation, and spend awareness by an agent. Required comparison: BudgetAPO's probe-sized fixed slice as a baseline triage rule in our hill-climb at equal subject-call budget; also GEPA's cap-truncation behaviour (seed return) should be avoided in our baselines by giving GEPA enough budget or reporting separately. Reproduction feasibility: HIGH (algorithm is ~30 lines; no code released).
Notes on evidence quality: 3 seeds x 5 subjects x 7 benchmarks, official baseline implementations, Holm-corrected tests (strong); but test sets are small (150-200 rows) per cell, headline win driven largely by HotpotQA and by GEPA returning the seed (its 300-row initial valset exceeds the 250-call cap, so GEPA is run outside its intended regime -- the authors acknowledge GEPA catches up near 350 calls), budget excludes optimizer-LLM cost, benchmark-average gains of ~2 points; greedy accept without significance test.
