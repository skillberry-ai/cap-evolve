# modularrsi (SHORT) -- arXiv 2609.14857v1
- Title: ModularRSI: Modular and Generalizable Recursive Harness Self-Improvement
- Authors: Siwei Wu, Jincheng Ren, Yizhi Li et al. (14 authors; Manchester, IQuest Research, Beihang, M-A-P, others)
- arXiv 2609.14857 v1 (cs.CL); first/latest 2026-09-14; venue: arXiv preprint (no comment); code https://github.com/IQuestLab/ModularRSI (Apache-2.0 per GitHub API; OpenAI-compatible: unverified).
- Editable surface: harness code split into five functional modules (Agent Loop, Observation Mgmt, Tool Use, Context Mgmt, Task Completion Detection), each with a restricted modification scope; infrastructure (sandbox, LLM client) not editable; function library with Task-Aware Function Composer.
- Search: contrastive success/fail trajectory pairs for the same task aggregated across tasks into findings; Code-Modify Agent edits one module at a time; Validation Gates = program checks + generalization-oriented diff review + execution validation (accept/rollback, Fig.1 p4); per-function Evolution History to avoid oscillation; then Cross-Module Integration epoch: integrated harness run on evolution tasks, agent resolves duplicated/conflicting mechanisms; Function Merge removes redundant functions (p4, p6).
- Evaluation/held-out: BENCHMARK-DISJOINT evolution set: 2,000 curated executable tasks from external sources (a subset used, limitation p~10); harness frozen, then evaluated on TerminalBench 2.0 (89) and SWE-Bench Verified (500?) never used in evolution; also cross-model transfer (Table 3). Test benchmarks sealed by construction (no selection on them). Number of seeds: Pass@3 over 3 rollouts; search runs single (UNVERIFIED).
- Headline: Table 2 p9 (DeepSeek-V4-Flash-Preview): TB2.0 Acc 47.57 -> 52.43 (in-domain evolution), SWE-V 73.40 -> 76.45; cross-domain TB-evolved on SWE-V 75.80; Table 3 cross-model TB2.0: GLM-5.2 59.55 -> 61.80, MiniMax-2.5 41.57 -> 44.94.
- Budget/cost: not itemised in text read (computational cost cited only as reason for using a subset of 2,000 tasks, limitation).
- Limitations: no dedicated ablation of contrastive analysis; only a subset of the 2,000 tasks used (conclusion section).
- RELEVANCE: MED. Threatens (b) mildly (module-wise independent evolution followed by a cross-module integration epoch with conflict resolution by an agent -- merging not statistically verified per module), (d) mildly (benchmark-disjoint evolution data for honest generalization; sealed test by construction), (e) (Evolution History per function). Surface is harness code only. No allocation scheme, no baselines vs other optimizers (only no-evolution baseline), so not a comparator for (a).
