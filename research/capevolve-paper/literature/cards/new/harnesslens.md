- Editable surface: "user-configurable components" of an existing agent framework (OpenCode, Codex CLI, Pi Coding Agent): instructions, skills, prompt templates, tool descriptions/integrations, agent roles, runtime extensions; components + update mechanism are discovered at runtime (Def.1 p.3, contributions p.2). Joint over components, one modification may touch several.
- Search method: single confirmed-incumbent lineage: H_{j+1} = accepted candidate or H_j (p.5-6). An LLM "evolution agent" (same harness framework) picks a proposal from Trajectory Diagnosis (based on evidence, previous attempts, regression risk, remaining budget), picks verification tasks, decides accept/reject/revise; a deterministic controller tracks budget, isolates candidates, reuses rollouts, enforces criteria (p.4). No population/DAG, no merge. Memory: diagnosed "reusable experience / recurring deficiencies" and previous attempts reused in later proposals (p.2, Fig.2 p.3).
- Feedback signal: binary task reward + trajectory-derived "behaviors"; behavior-to-channel attribution; labels per task (recovered/regressed etc., Table 6 App.).
- Splits / held-out: per benchmark 30 random TRAIN tasks; TEST = official split where available else all remaining; disjoint; "all information from TEST ... is inaccessible throughout harness evolution" (p.6). Test not used for selection.
- Benchmarks/models: tau2-bench Retail, tau3-bench Banking Knowledge, Terminal-Bench 2.0, BIRD Mini-Dev Challenging; one model deepseek-v4-flash-preview for all agent and evolution roles; 3 harnesses (p.6).
- Metrics: pass@1 on held-out TEST (Table 1 p.7).
- Budget: unit = LLM sessions + task trials; HarnessLens capped B=200 (incl. 60 initial trials); baselines at configured maxima: Self-Harness 4,800, Meta-Harness 660, HarnessFix 300 TRAIN rollouts (p.6, Table 9 p.15); tokens/$/latency not normalized (Limitations p.8-9).
- Reported limitations: one model family, three harnesses, four benchmarks; no token/latency/$ normalization (p.8).
- Key results: Table 1 p.7 avg over 4 benchmarks: OpenCode H0 41.83 -> HarnessLens 47.53 (HarnessFix 44.57, Self-Harness 40.04, Meta-Harness 40.38); Codex 40.94 -> 44.06 (HarnessFix 41.63); Pi 45.49 -> 49.67 (HarnessFix 47.98). Best/tied-best in 8 of 12 pairs (p.6). Self-Harness and Meta-Harness fall below H0 in half of 24 pairs, losing ~10 pts worst case (p.7). Ablation Table 2 p.8 (OpenCode): Fixed/Random Batch leave H0 unchanged (75.00/20.90/37.50); Metric-Only Gate 80.00/20.90/37.50; full 85.00/25.37/45.83.
- Candidate-evaluation allocation: per-candidate behavior-aware task subset (>=5 distinct tasks, selected from supporting trajectories + related-goal tasks + regression-probe tasks, more groups for broader edits), paired current-vs-candidate trials (2 per task), then confirmation on a NEW batch (<=2 carried-over tasks + unused tasks); controller ensures verification fits remaining budget (p.5-6, App. p.12). Not a bandit/posterior; heuristic LLM-chosen, gate = attributable evidence AND primary metric.
- Task selection/curriculum: yes - task grouping by goal (Task-Space Exploration, p.4) used for verification and regression coverage.
- Merge/composition: none (single lineage). Accepted modifications accumulate on the incumbent.
- Optimizer self-modification: none.
- Overlap with CapEvolve: very high on (a) (budget-aware, per-candidate task allocation, two-stage cheap subset -> confirmation batch, spend awareness) and (f) (LLM agent as evolution controller within a deterministic budget controller), (e) partially (prior attempts in proposal selection), and (c) partially (prompts+skills+tool descriptions in one gate).
- What it means for our claims: (a) "budget-aware/adaptive allocation of evaluation across candidates and tasks" is NOT novel as stated; must be narrowed to "pooled-evidence Bayesian per-task posterior signals + DAG-wide allocation across many candidates". Required comparison/citation: HarnessLens (cheap-subset triage + confirmation batch is nearly our agent-optimize triage->full-val flow). Reproduction feasibility: med-high (public MIT code, OpenAI-compatible endpoint, small 200-unit budget).
- Evidence quality: single model; seeds/CIs not located (UNVERIFIED); test small (e.g., Banking pass@1 steps 1.5-3 pts imply ~67 tasks; Retail 5-pt steps imply 40 tasks); baselines re-run at "configured maxima" with differing budgets and internal splits (footnote p.6) - not matched compute; test not used for selection.
