# SkillVine (slug: skillvine)
- Title: SkillVine: Agent Skill Evolution via Branching Exploration; authors Kaiwei Liu, Jiqian Dong, Liran Dong et al. (10 total; CUHK, Huawei Noah's Ark Lab); arXiv 2609.32731v1; first 2026-09-26; preprint (no comment/journal_ref).
- Code: none stated for SkillVine (github strings in text are references, e.g. SkillOpt-Lite repo it builds on) -> unverified.
- Surface: skill library (set of skill documents) as versioned nodes; text only.
- Method: version graph (DAG-of-versions, tree edges) with a "trunk" updated on every training batch and k side branches (k=2) started from historical nodes; node score Select(v)=q(v)+lambda_exp*sqrt(log(N_exp+1)/(n_exp(v)+1))+lambda_comp*C(v), where C(v) is credit for validation samples v solves that the trunk fails minus beta times samples trunk solves that v loses (per-task solved/failed sets stored per node; Eq.3-4 p5); discovery vs refinement selectors mixed (lambda 0.08/0.5 vs 0). Adaptive-granularity branch update: coarse (apply all edits at once, 1 validation eval) if trunk accepted batch, fine (apply edits one by one with a validation eval after each) if trunk rejected (Eq.5-6 p6). Memory: node metadata (n_exp, solved/failed sets); no merge operator (branches never recombine); final = argmax validation accuracy over all nodes (Alg.1 p7).
- Eval/gate: every candidate (trunk and branch) accepted iff validation accuracy strictly exceeds its parent on the full validation set (p5-6); final selection also by max validation over all graph nodes, which biases val upward (winner's curse; they report final-node validation in App Table 6). Test set separate; protocol sizes not extracted (UNVERIFIED). Linear baseline run once and its trunk reused by Best-of-3, Random, SkillVine, SkillOpt(-Lite) to reduce rollout noise (p7) - results are therefore NOT independent runs; no seeds/CIs.
- Headline (Table 1 p8, test): DeepSeek-V4-flash SpreadsheetBench 71.53 vs Linear 48.04, Best-of-3 64.41, SkillOpt-Lite 66.19, Hermes-SE 50.53; LiveMath 53.77; SearchQA 74.43; OfficeQA 55.41; TABVERSE 67.35. Qwen3.8-Flash gains smaller (SSB 67.97 vs 66.90; LiveMath 39.62 vs Hermes-SE 42.45 best). Best in 9 of 10 combos. Best final node found via a branch in every setting (abstract). Ablations Table 2 p8 show removing selector or AGBU lowers most cells but several are within 1 pt.
- Cost: training cost = number of agent rollouts (Fig 2 p9, SpreadsheetBench only); branching and AGBU need extra rollouts (paper says more but better); no dollars/tokens.
- RELEVANCE: HIGH for (a): candidate archive as a graph with a selection rule mixing validation score, expansion-count exploration bonus, and per-task complementarity vs the incumbent, plus adaptive evaluation granularity (one eval vs per-edit evals) driven by the trunk's outcome. Threatens "adaptive allocation across candidates" and the use of per-task solved sets; does not merge (b) or use Bayesian per-task posteriors, nor sealed test accounting for all branch evals.
