- Editable surface: harness code/runtime (context construction + execution flow) as in Meta-Harness; classification harnesses and agent harnesses (SWE-V, AppWorld, TB2.0-V). Single harness program; not heterogeneous prompt/tool/MCP/skill bundle.
- Search method: Meta-harness with an external persistent "improvement graph" of EVIDENCE/HYPOTHESIS/INTERVENTION/OUTCOME nodes (Sec 3.2, p4). Loop OBSERVE->PLAN->PLANSELECT->IMPLEMENT->EVALUATE->UPDATE (Eq.4, Alg.1 p4-5). Local proposer calls (LLM) own sub-steps, graph owns state. PLANSELECT scores each plan on seven 0-4 scales (evidence strength, expected gain, information value, novelty, falsifiability, cost, risk) with redundancy penalty and picks a portfolio incl. a branch/restart (p4). 
- Archive / selection / merge / memory: graph retains successful AND unsuccessful experiments with revisable hypothesis assessments (memory of failed edits: yes, claim (e) overlap); parent-relative corrected/regressed/unchanged task sets T+/T-/T0 are recorded per candidate (Eq.5, p5). No merge of branches mentioned (UPDATE has lineage links only).
- Feedback signal: external evaluation scores plus per-task transition sets; intervention fidelity, association with prediction, verdict.
- Task splits / held-out: "Candidate selection depends only on validation performance. Held-out test outcomes are revealed only after search and selection are complete" (p6). Primary metric = test of validation-selected harness; also "selection regret" = test oracle minus test of val-selected within each method's pool (p6). Table 1 follows HarnessFix split sizes/protocol (specific counts not restated in text read: UNVERIFIED).
- Benchmarks and models: USPTO-50k, Symptom2Disease, LawBench classification (Meta-Harness tasks); SWE-bench Verified, AppWorld, Terminal-Bench 2.0 (TB2.0-V). Table 1 uses GPT-5 mini for task+optimization agents; classification solvers Qwen3.5-Plus, Qwen3.7-Flash, DeepSeek-V4-Flash, GLM-5.2-Fast-Preview, MiniMax-M2.5 with GPT-5.4 proposer; SWE-V proposers GPT-5.5, GPT-5.6 Sol, GLM-5.3, Kimi K3, DeepSeek-V4-Pro with Qwen3.5-Plus solver.
- Metrics: test task completion %, 3-run means (Table 1), mean over 5 runs elsewhere (p19), selection regret, AUC of search curve.
- Budget/cost reporting: budget measured in complete candidate evaluations B (p3); matched studies use 8 candidate evaluations (Wide: 2 waves x 4; Deep: 4 waves x 2). Proposer token usage reported in App. A.7 (p19): at 0.530M tokens CIG-Wide reaches 46.8% with 5 candidates vs Full History 41.3% with 8; complete CIG uses 0.820M (1.55x). Planning calls not counted as evaluations.
