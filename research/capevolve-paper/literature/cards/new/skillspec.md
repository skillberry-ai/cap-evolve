- Editable surface: a single skill artifact (text, then re-expressed in flat / graph / hybrid representation with retrieval metadata and auxiliary modules); policy model frozen (p3-7). Not tools/MCP.
- Search method: Phase I (10 rounds, batch 40): per round, 4 intent-conditioned full-skill candidates (repair, preserve, simplify, rewrite) plus an optional "combo" candidate composed from compatible changes of different intents (p4, Table 4 p14). All candidates and the incumbent run on full D_val; paired counts n+ / n- per task; top Nf=2 by net paired gain are re-run on D_val with extra execution seed(s); commit iff pooled gain >= Gpool=3 tasks and min per-evaluation gain >= Gmin=0 (consensus gate, Eq.2, Alg.1 p5). Single incumbent lineage (no archive of live branches); trajectory Gamma_I of accepted and rejected candidates is kept as telemetry. Phase II: PSS/RSS (process / redundancy sensitivity) from ridge regression over Phase I candidates + 2000 round-cluster bootstraps routes to flat/graph/hybrid (thresholds 0.5); then 4 epochs of single-candidate revision gated by strict accuracy improvement on a held-out selection set (A.1 p14). Merge: the combo candidate is evaluated through the same paired gate (validated). Memory: rejected-candidate evidence is reused only to pick representation, not to steer future edit proposals (optimizer state Omega exists but unspecified).
- Feedback signal: hard accuracy per task; execution trajectories (success/failure) for proposals; LLM rubric annotations (0-3) of process/interference for each candidate diff.
- Task splits / held-out protocol: official train split for proposals, official validation split to accept/reject, complete official test split only for final evaluation (p8); "no test-set labels provided" for routing. Fixed seed 42 frozen artifact for ablations (p14). Phase II gate uses "a fixed held-out selection set" (same IDs and seed across epochs) - whether this equals D_val is not stated (UNVERIFIED).
- Benchmarks and models: SearchQA, SpreadsheetBench, OfficeQA, DocVQA, LiveMath, ALFWorld; GPT-4.1, GPT-5.4 Nano, GPT-5.4. Optimizer/telemetry: Claude Sonnet 5 via Copilot CLI (Phase I); Phase II optimizer = the evaluated model (Table 4 p14).
- Metrics: success rate (hard accuracy), macro-average over six benchmarks; failures (setup/timeouts) count as incorrect (Table 4).
- Budget/cost reporting: no dollar/token cost reported (UNVERIFIED by grep for cost/token). Hyperparameters/rounds given (Table 4); ablation states "equal compute" control for Phase II (Table 3 p10).
- Reported limitations: no limitations section found; text notes "removes direct identifiers but does not imply semantic task characteristics absent" from routing (p14).
- Key quantitative results: avg test GPT-4.1 60.41 vs SkillOpt 48.78 (+11.63), GPT-5.4 Nano 48.05 vs 42.13, GPT-5.4 78.27 vs 75.15 (Table 2 p8); mean gain over SkillOpt 6.89pp. Phase I only (SkillSpec-I): 56.88 / 47.31 / 75.60. Phase II over Phase I: +3.52/+0.74/+2.67 (p9); 13 wins, 1 tie, 4 losses of 18 settings. Table 3 p10 (Nano): Phase I equal compute 46.69, Flat 46.91, Graph 47.91, Hybrid 49.10, router 50.27. Baselines include GEPA, Trace2Skill, SkillAdam, SkillOpt, SkillOpt-lite; SkillOpt-lite beats SkillSpec-I on GPT-5.4 (76.51 vs 75.60).
- Candidate-evaluation allocation: uniform/full: every candidate evaluated on full D_val; extra confirmation runs only for top-2 finalists (successive-halving-like two stage, fixed). No per-task posterior.
- Task selection/curriculum: random training batch per round; no task selection.
- Merge/composition (verified?): combo candidate from compatible intent changes is generated by the LLM optimizer and validated by the same paired consensus gate (p4-5). Yes validated, but it is intra-round combination, not branch merging.
- Optimizer self-modification: Phase II optimizer is the evaluated model; no optimizer-prompt edits.
- Overlap with CapEvolve: (a) partial - two-stage screen/confirm with paired per-task counts and repeated seeds (a sign-count gate, not Bayesian); (b) intra-round combo validated by gate; (e) weak (rejected-candidate telemetry); (f) Sonnet 5 via Copilot CLI used as optimizer. Not (c),(d).
- What it means for our claims: (b) "verified merging" must be stated as merging of independently evolved branches in a DAG, since validated combination of same-parent candidates exists here. The paired no-regression consensus gate (net paired gain, min per-repeat gain >= 0) is close to our hill-climb paired gate; novelty of hill-climb gate is not claimable, only the k*SE form. Required comparison: Phase I gate vs our paired mean(delta)>k*SE gate on equal validation spend. Reproduction feasibility: medium (no code link found).
- Notes on evidence quality: single seed (seed 42) per cell, no SE/CI on test; test used only for final eval per text; baselines numbers include SkillOpt/SkillAdam/SkillOpt-lite - re-run by authors (not stated how; UNVERIFIED); Fig 3 caption says "three validation repeats" vs Table 4 "2 validation execution seeds" (internal inconsistency, p9 vs p14); ablation Table 3 shows router vs fixed Hybrid differs by 1.17pp on one seed.
