# pluginrsi (SHORT) -- arXiv 2609.32423v1
- Title: PluginRSI: Recursive Improvement of Agent Harnesses with Reusable Plugins
- Authors: Yaorui Shi, Yuchun Miao, Yuxin Chen et al. (9 authors; USTC, Meituan, Wuhan Univ., NUS)
- arXiv 2609.32423 v1; first/latest 2026-09-26; venue: "Preprint. Work in progress." (p1), no venue; code https://github.com/syr-cn/PluginRSI (MIT per GitHub API; OpenAI-compatible: unverified).
- Editable surface: harness = workflow W + set of atomized plugins P (tools, roles, skills, mechanisms with standard interfaces); shared plugin library L accumulates beneficial plugin implementations.
- Search: per iteration, N=8 parallel plugin mutations, each a single-plugin edit evaluated on its own balanced minibatch (b=20: 10 solved + 10 unsolved) paired against incumbent on the same minibatch; improving plugin variants enter L; then ONE recomposition candidate (choose plugin subset P' from L and revise workflow W') is evaluated on all held-in validation tasks and accepted if S[H'] > S[H] (Alg. 1 p5). Recomposition = composition of components from different lineages, verified by full held-in evaluation (strict improvement).
- Evaluation/held-out: SWE-bench Verified 400 held-in / 100 held-out; Terminal-Bench 2.1 59 held-in / 30 held-out; QA 150 held-in (3 domains) / 250 held-out (5 domains); harness selected by highest held-in score and fixed; test not used in search (p4-5); one run (no seeds stated, UNVERIFIED).
- Headline: Table 1 p6 SWE-V held-out (100) 65.00 (GPT-5.6 Terra proposer, solver GPT-5.6 Terra) and 69.00 (Kimi-K3) vs best baseline Meta-Harness 55.00 / 63.00 (+10/+6); Table 2 p6 TB2.1 held-out (30) 73.3 vs Meta-Harness 66.7; Table 3 QA overall 0.675 vs 0.638. Library reuse: 69% after two steps vs 65% without (p2).
- Budget/cost: per iteration 560 solver rollouts on SWE-V (400 full-val + 8x20 minibatch, App. E p16); PluginRSI T=15 iterations vs baselines T=25 iterations (rollout parity not shown; token/$ cost not reported in text read).
- Limitations (App. D p16): fixed task sets/limited iterations; transfer domain-dependent; single-plugin mutation misses coordinated multi-plugin changes (plugin-workflow joint optimization left to future work).
- RELEVANCE: MED-HIGH. Threatens (b) (library of components from different edits recomposed into one candidate; verified only by strict improvement on full held-in set, not per-component) and (a) mildly (cheap balanced-minibatch triage of single-plugin mutations before full-set recomposition eval). Limited to harness code/plugins; no heterogeneous surfaces across prompt/MCP/skills; no sealed-test accounting of unsuccessful search; no Bayesian allocation.
