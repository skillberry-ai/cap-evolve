# harnessoptbench (SHORT) -- arXiv 2608.06301v1
- Title: HarnessOpt-Bench: Evaluating LLMs at Harness Optimization
- Authors: Varun Ursekar, Apaar Shanker, Yash Maurya et al. (7 authors total; Scale AI)
- arXiv 2608.06301 v1; first/latest 2026-08-06; venue: arXiv preprint (no comment/journal_ref); code URL: none found in text (builds on VERO [23] trusted execution; release unverified).
- Editable surface: the target agent's Python harness (prompts, tools, control flow, memory, orchestration code) edited by a coding-agent optimizer.
- Search/selection: benchmark, not an optimizer; optimizer = LLM + coding harness (opencode shared, or native claude-code/codex/kimi-cli) that edits the seed harness and nominates one final candidate under a fixed target-evaluation budget B; objective max E(H)-E(H0) s.t. sum of costs <= B (Eq.2, p6).
- Evaluation/held-out: per task fixed non-overlapping splits (Fig.1 p2: 20 dev with traces, 40 val metrics-only, 40 test reveals nothing); trusted execution environment, API gateway with per-scope token budgets, candidate versions preserved for audit; test scored only after nomination; K=3 rounds; resolution band from re-scoring noise (p6-7). 4 tasks (OfficeQA, BrowseComp-Plus, Terminal-Bench, GAIA), pinned seed harness and one pinned target model per task.
- Headline: 5 optimizer models (opus-5, sonnet-5, gpt-5.6-sol/terra, kimi-k3) x shared/native harness, 111 scored runs; optimizer models separate more than coding harnesses; native harnesses not consistently superior; e.g. Table 1 p7 opus-5/opencode normalized gain OfficeQA 0.63, BrowseComp 0.48, TB 0.29, GAIA 0.47; gpt-5.6-terra near zero.
- Budget/cost reporting: target-evaluation budget enforced and metered; optimizer inference metered but uncapped (p7), so results estimate capability when optimizer reasoning is not scarce.
- Limitations (p11): hack-resistant not hackproof; repeated dev/val feedback may still reward evaluator-specific strategies; seed prior effect; Python-only; one target model per task.
- RELEVANCE: HIGH for (d) and (f). Provides an existing protocol and benchmark for sealed-test, budget-metered, audited harness optimization with coding agents as optimizer (f), so "honest sealed held-out" cannot be claimed as a new protocol; cites VERO and MetaHarness as end-to-end coding-agent optimizers. Does not propose a search algorithm (no (a)/(b)/(c)/(e) threat). Candidate evaluation harness for our CapEvolve: run our hill-climb/agent-optimize inside this benchmark if released.
