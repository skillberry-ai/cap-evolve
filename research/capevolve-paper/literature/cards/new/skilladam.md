# SkillAdam (slug: skilladam)
- Title: SkillAdam: Stable and Efficient Skill Evolution for Agents; authors Gaoyuan Li, Meihao Fan, Yizhe Liu et al. (10 total; Renmin U., Tencent); arXiv 2609.08944v1; first 2026-09-08; preprint (comment: 17 pages, 4 figures, 6 tables; no venue).
- Code: https://github.com/ruc-datalab/SkillAdam (p1); LICENSE file = MIT (Tencent text; GitHub API reports NOASSERTION); README has no API-compat statement (unverified).
- Surface: single Markdown skill document.
- Method: single-lineage hill-climb; per iteration LLM patch from rollout + persistent "Evolving Issue Tracker" (structured issues with prior solution attempts and their outcomes, reopened on recurrence) + volatility-driven edit budget (EMA of variance of per-case improvements shrinks next edit size) (Eq.11-18, Alg.1 p5-8).
- Evaluation/gate: candidate vs current evaluated on the SAME sampled mini-batch used for the rollout; multi-metric acceptance gate (threshold on a designated metric, protected metrics within regression bound); "does not use an additional validation set" (p9). Test set only for final eval; seed 42; test case evaluated once; DeepPlanning odd/even split (p9). Non-DP benchmarks pool original train+selection.
- Headline: 5 short-horizon benchmarks with GPT-5.5 vs SkillOpt: SearchQA 87.5/87.3, Spreadsheet 81.1/80.7, OfficeQA 72.1/72.1, DocVQA 92.3/91.2, LiveMath 67.7/66.9 (Table 2 p10, SkillOpt baselines copied from SkillOpt paper); DeepPlanning Claude Sonnet 4.5 DP-Avg 28.3 vs 21.7, DP-Travel 11.7 vs 1.7 on 60 cases (Table 3 p10). Single seed, no CIs.
- Cost: DeepPlanning optimization tokens 74.0M vs SkillOpt 226.6M (-67.3%), requests 2,830 vs 9,071 (Table 6 p13); excludes init and final test eval; tokens not dollars.
- Cumulative ablation (DP only): memory + budget 28.3; -budget 21.7; -both 19.2; NoSkill 15.8 (Table 4 p11); authors note interaction not isolated.
- RELEVANCE: med-high. Directly threatens claim (e) (optimizer memory of failed edits: issue tracker stores each attempted modification with outcome, SkillOpt also has optimizer memory); partly (a) adaptive update scope (not eval allocation). Gate has no held-out split, so it is weaker than ours; (d) not claimed.
