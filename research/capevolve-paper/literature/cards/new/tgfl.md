# SkillMorph (arXiv title: Trajectory-Guided Fault Localization for Agent Skill Evolution; file slug tgfl is a label, not a name used in the paper)
- Title: Trajectory-Guided Fault Localization for Agent Skill Evolution (method named SkillMorph); authors Yu Ge, Linna Xie, Zhong Li, Yu Pei, Tian Zhang (5; Nanjing U., PolyU); arXiv 2610.11858v1; first 2026-10-08; preprint (arXiv comment: 20 pages, 3 figures; no venue).
- Code URL: none stated (the only github URL in the paper is the reference to cap-evolve) -> unverified.
- Surface: multi-skill sets / skill packages (SKILL.md, files, scripts); edit-sites span line ranges across several skills/artifacts (p9).
- Method: per loop, run each evolution task m=3 times, abstract trajectories to state transitions, spectrum-based (Ochiai-like) suspiciousness of actions across runs, loops (history weights) and tasks, top-10 actions -> LLM agent localizes edit sites in skills/files/lines -> one LLM proposal per site -> an LLM evaluates proposals (evidence, duplication/conflict, success-case disruption, revision history) selects a subset and consolidates them into one patch. NO execution-based validation gate on the patch: the patch is applied and the next loop executes it (p10). Evolution memory keeps edit/coverage history so earlier edits can be retained, refined or reverted (p9) -> memory of failed edits (e).
- Eval/held-out: SWE-Skills-Bench 49 skills x 10 tasks, 2-fold swap A->B and B->A (evolution set vs held-out set "never accessed during evolution"); CannBot 12 coordinated skills, 15 evolution + 15 held-out tasks; 3 trials; L=3 (SWE) or 5 (CannBot) loops; Claude Code + DeepSeek-V4-Flash-0731 for both execution and evolution; baselines reproduced from official implementations (p10-11).
- Headline (Table 1 p11, held-out): SWE overall pass@3 95.51 / trial acc 92.24 / pass3 88.37 vs CAP-Evolve 92.24 / 89.39 / 84.90, SkillOpt 88.98 / 84.90 / 80.41, EvoSkill 85.71, SkillAdaptor 86.73, base 82.45. CannBot pass3: SkillMorph 93.33, CAP-Evolve 73.33, base 46.67 (15 tasks; one task = 6.7 pts). Ablation Table 2 p14.
- Cost: wall-clock only (49 min/loop on SWE, 127 min on CannBot; execution 19.8 / 97.8 min) (p13); no token/dollar accounting found. Single seed/run per config (no CIs).
- RELEVANCE: HIGH for provenance. Cites "CAP-Evolve: a skills-native, host-agnostic harness for honestly optimizing ai-agent capabilities" (github.com/skillberry-ai/cap-evolve, 2026) as a baseline [6] described as evolving "agent prompts, skill packages, and tools through failure diagnosis, candidate generation, and validation-based selection" (p10) and reports it as second-best (Table 1). So a third party has already run our system; check version/claims. Method threat: (e) memory of edit effects and (b)-like consolidation of multiple proposals (LLM-judged, not validated).
