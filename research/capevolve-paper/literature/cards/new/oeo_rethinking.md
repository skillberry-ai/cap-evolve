- Citation count: unavailable
- Editable surface: a single persistent natural-language SKILL document (one artifact, byte-identical initial skill). Not code/tools/MCP/multi-file packages.
- Search method: OEO (Open-Ended Optimization) = a frontier LLM acts as controller in a contract-enforced agent loop (Alg. 1 p12): at each turn it chooses INSPECT / RUN_TARGET / REVISE(s') / SELECT(checkpoint j) / STOP; revisions commit immediately; it may later select any earlier committed checkpoint as output. No reflection template, edit language, candidate schedule or stopping rule is prescribed. Comparators: SkillOpt (staged pipeline, bounded patch operators, strict improvement gate with rejected-edit memory, validation-selected best; Table 1 p4) and GEPA (Pareto reflective evolution; merging disabled; returns one val-selected candidate; A.2 p11).
- Archive / selection / merge / memory: OEO keeps committed checkpoints and history; checkpoint selection by the optimizer using permitted selection data. No merging. SkillOpt has rejected-edit memory (description only).
- Feedback signal: task pass/fail from frozen evaluator on selection split (valid_seen); optimizer may request targeted rollouts.
- Task splits / held-out: explicit optimization contract: selection data (e.g. valid_seen) may guide candidate/checkpoint choice; sealed valid_unseen/test used ONCE after selection (A.1 p11); runner "prevents access to the sealed final split" (p4). Sealed n: SearchQA 1,400; SpreadsheetBench 280; OfficeQA 172; LiveMathematicianBench 124. Each cell is ONE completed optimization run (no seeds, A.1).
- Benchmarks and models: SearchQA, SpreadsheetBench, OfficeQA, LiveMath; targets Qwen3.5-4B and GPT-5.5; optimizer GPT-5.5 (frontier); capability ladder Qwen3.5-4B / Qwen3.5-27B / GPT-5.5 on SearchQA and LiveMath.
- Metrics: sealed pass rate; realized target-interaction tokens as % of SkillOpt-configured budget; path metrics (max edit, section breadth, churn), item-level agreement and Jaccard.
- Budget/cost reporting: YES, two-part: optimizer tokens recorded separately from target-model tokens during optimization and checkpoint-selection rollouts (A.2 p11); common reference budget = SkillOpt's configured allocations; OEO median 34.3% of target-interaction budget, but OEO slightly exceeds the optimizer-token budget in 3 settings and reaches 98.9% in a fourth (p6). Atomic-call overshoot acknowledged. No $ figures.
- Reported limitations: capability boundary (p6-7, 8): medium optimizer -> SkillOpt wins (+9.68pp LiveMath, +3.50pp SearchQA); weak optimizer cannot operate OEO interface (blocked). No separate limitations section located in text read (UNVERIFIED).
- Key results: Table 2 p5 sealed: OEO vs SkillOpt vs GEPA, e.g. LiveMath/GPT-5.5 0.6855 vs 0.5000 vs 0.4032; OfficeQA/GPT-5.5 0.7267 vs 0.7035 vs 0.6977; SpreadsheetBench/GPT-5.5 0.7607 tie with SkillOpt. Abstract: 14 comparisons, 12 wins, 1 tie, 1 loss of 0.21pp (vs GEPA SearchQA GPT-5.5: 0.8714 vs 0.8736). Table 3 p6 one-shot rewrite below OEO in all 4 settings. Table 4 p6 ladder.
- Candidate-evaluation allocation: OEO chooses its own rollouts adaptively (6.1%-62.3% of reference target budget vs GEPA ~100%) (Fig 2b p5); no explicit statistical allocation rule.
- Task selection/curriculum: optimizer-directed (it can request targeted rollouts); not specified further.
- Merge/composition: none (GEPA merge disabled).
- Optimizer self-modification: none of the optimizer's own code; the "meta-policy" (procedure) is composed online per run, i.e. procedure is generated, not the optimizer program edited.
- Overlap with CapEvolve: HIGH for (f) and for our agent-optimize algorithm: an LLM agent drives propose/probe/select/stop under a framework-enforced budget + sealed split, with checkpoint selection and budget accounting (d). Differs: single skill text surface, no DAG, no merge, no per-task Bayesian posteriors, no paired statistical gate, single run.
- What it means for our claims: (f) is no longer novel as "agent as controller"; must cite and position as prior art, and the delta must be: richer search state (candidate DAG, clusters, pooled evidence, posteriors), heterogeneous surfaces, statistical gates. (d) their sealed-once + realized-token accounting is similar; our claim must go beyond (e.g. accounting for unsuccessful search/spend across all candidates, seeds). (a) their finding that the optimizer chooses fewer target rollouts with better results motivates a baseline "free-form agent without our posterior machinery". Required comparison: OEO-style free-form controller ablation against our structured agent-optimize at matched tokens, including capability-ladder. Reproduction feasibility: med (simple loop; code not released).
- Evidence quality: single run per cell, no CIs; sealed n smallish (124-172) so 1-3 point gaps within noise; GEPA SpreadsheetBench cells post-hoc (excluded); SkillOpt/GEPA re-implemented under OEO's contract; optimizer all GPT-5.5 via Copilot API; authors' own method wins; test used once (per text).
