- Authors: Junbo Li, Boyi Liu, Canwen Xu, Yite Wang, Yuxiong He, Zhangyang Wang, Qiang Liu, Zhewei Yao (8; UT Austin, Snowflake)

- Code: https://github.com/Snowflake-AI-Research/ReASearch (p.1 footnote). GitHub API license endpoint returned 404 "Not Found" on 2026-10-11 (repo public; no license detected). README lists OpenAI, Anthropic, Gemini(OpenAI-compat), Azure, Bedrock, Cortex providers (README only; behaviour unverified).
- Citation count: unavailable.
- Editable surface: three separate settings, one at a time: (i) a system prompt for a student LLM; (ii) a single Python program; (iii) ML training scripts/workflows (p.4-6). No joint prompt+tool-code+MCP+skills surface; README mentions multi-file repos via opencode for ML tasks.
- Search method: NO outer-loop controller. One tool-using code agent (Claude Sonnet 4.6; GPT-5 also) decides what to evaluate, edit, revert, verify, and when to finalize. Tools: get_next_minibatch, call_student_model_batch, validate_candidate, python_exec, edit_code (sub-agent applies edits), verification sub-agent, run_experiment, git, compaction (p.4-6). Archive/tree: agent navigates a candidate tree and reverts; harness re-emits "search state" (best result, recent experiments, lessons, stagnation warnings, structured search-tree view) into the system prompt every turn (App. F p.18). Memory: persistent lessons.md of what worked/failed (p.5). Final selection: the agent reasons over full history and may synthesize a new prompt rather than take best-val (p.5). Merge: only agent-synthesized "composite" (no verified-merge procedure).
- Feedback: train trajectories (full), validation returns aggregate accuracy only to limit overfitting (p.4); for programs/ML: evaluator score.
- Splits: prompt tasks use train/val/test; HotpotQA 500/500/1000, GSM8K 500 train + 500 val + 1,319 official test, Terminal-Bench 2.0 22/22/remaining tasks (App. H p.20). Test used for reporting; agent's choice of final prompt is made without test (p.5). Program tasks have no split (single instance); Crypto uses hidden private Kaggle split (p.9).
- Benchmarks/models: AIME 2025, GSM8K, HotpotQA, Terminal-Bench 2.0; circle packing, Heilbronn, TXN, EPLB, ARC-AGI-2; NanoGPT, IMG-100, Atari Q*bert, MuJoCo, DRW Crypto. Agent: Claude Sonnet 4.6 (and GPT-5 for programs); students GPT-4.1 mini, Llama 3.1-8B, GPT-5 (p.6).
- Metrics: test accuracy mean+/-SE over 3 independent runs (p.6); objective scores.
- Budget: student-model calls matched to GEPA; "full ReASearch run costs less than $20" with caching (p.7); evaluator calls matched for programs (500/100); wall-clock matched vs Claude Code; token use plotted (Fig.7 p.9).
- Limitations: no dedicated limitations section located in text (UNVERIFIED; searched 'Limitation'); claims depend on rich-feedback environments (p.2).
- Key results: Table 1 p.7 (test): AIME 52.00+/-0.67 vs GEPA 50.67 vs baseline 46.00; GSM8K 83.40 vs 82.11 vs 81.20; HotpotQA 67.60 vs 65.80 vs 63.00; Terminal-Bench 2.0 53.33+/-1.96 vs GEPA 42.22 vs 35.56. Tables 2-5 p.7-8: circle packing ties/exceeds human best for n=23..32 with Sonnet 4.6; ARC-AGI-2 test 50.0% vs AdaEvolve 12.5%.
- Candidate-evaluation allocation: agent-chosen minibatch size B, re-check of promising candidates on extra train samples before validation, "cheap channels before expensive validation" (p.4-5, App. B); no formal bandit/posterior.
- Task selection: agent can pick "previously identified difficult cases" for re-evaluation (p.4).
- Merge: none formal; Optimizer self-modification: none (agent edits artifact only).
