- Citation count: 341 (Semantic Scholar API, retrieved 2026-10-11)
- Editable surface: the coding agent's own Python repo (tools, prompts, workflow). Open-ended-exploration loop (archive, parent selection) is fixed and NOT editable (p.5). The "diagnose what to improve" step is a separate fixed o1 call on eval logs (App. C.3, pp.28-29).
- Search method: archive of ALL valid agents (tree: each child has one parent), initialised with one agent; 80 iterations; k=2 (SWE) / k=4 (Polyglot) parents sampled per iteration in parallel (p.5, p.28). Only children that compile and still can edit code are kept (p.4). No merging. Memory = archive + per-agent eval logs fed to the diagnosis call.
- Parent selection: sample w/ replacement prop. to sigmoid(lambda(score-0.5), lambda=10) * 1/(1+n_functioning_children); agents with perfect score excluded (App. C.2, p.28).
- Feedback signal: scalar pass rate on coding tasks plus eval logs/trajectories (text) to the diagnosis LLM. Ground-truth tests hidden from agent (pass@1 on Polyglot, p.6).
- Task splits / held-out protocol: no train/val/test split for SWE-bench. Search selects on the same task pool used for the headline number: 10 tasks (gate) -> +50 (SWE-bench-verified-mini, 60) -> 200 tasks for agents >40% and top-2 in archive (p.6, E.2 pp.33-35). Polyglot: 50-task random subset; final base-vs-best on full Polyglot (p.6). Headline SWE 50.0% is the 200-task score used in selection, not a sealed test. A full SWE-bench Verified (500) eval of the final agent: not found in text (UNVERIFIED). Genuinely held-out transfer: other models, other benchmark, other languages (p.8, Fig 4).
- Benchmarks and models: SWE-bench Verified (Python) and Polyglot (Aider). Self-modification Claude 3.5 Sonnet (New); eval Claude 3.5 Sonnet (New) on SWE, o3-mini on Polyglot; temp 1.0 (Table 3, p.32).
- Metrics: % tasks solved (single run per config; no seeds/CIs reported -- grep found none).
- Budget / cost reporting: Yes but coarse. ~USD 22,000 and ~2 weeks per DGM SWE-bench run; baselines ~USD 10,000 each (E.1, p.32; p.10). Not matched budget: DGM costs 2.2x the baselines. Breakdown: 60 SWE tasks ~USD 350, 60 Polyglot tasks ~USD 5 (o3-mini).
- Reported limitations: heavy compute; bounded by frozen FM; assumes coding benchmark reflects self-improvement ability; fixed exploration loop (pp.9-10). Reports an objective-hacking example (hallucinated tool use, App. H pp.69-70).
- Key quantitative results: SWE 20.0 -> 50.0 and Polyglot 14.0 -> 38.0 on search subsets [Fig 2 p.7, Sec 4.4 p.6]; full Polyglot 14.2 -> 30.7 [p.6]. Table 1 [p.25]: DGM 50.0/38.0; w/o open-ended 23.0/14.0; w/o self-improve 39.0/28.0; DGM-Greedy 39.7/30.0 (SWE/Polyglot). Transfer SWE: Claude 3.7 19.0 -> 59.0 (figure; text p.8 says 59.5), o3-mini 23.0 -> 33.0 [Fig 4 p.8]. Cross-benchmark: SWE-evolved agent 28.9% on Polyglot vs 14.2 base; Polyglot-evolved 24.5% on SWE vs 20.0 [p.8].
- Candidate-evaluation allocation: STAGED subset gating (10 -> 60 -> 200 tasks) with a heuristic threshold (>40% and top-2) chosen from preliminary noise (p.6). No bandit/posterior; each surviving candidate gets one pass, no re-evaluation.
- Task selection / curriculum: fixed task lists (E.2/E.3); no curriculum, no per-task selection.
- Merge/composition: none (tree only; features compose only along lineages).
- Optimizer self-modification: PARTIAL. The agent edits itself, which is both solver and (implementor of) modifier, but the archive/selection code and the o1 diagnosis prompt are fixed (p.5, App. C.3). Hyperagents paper (2603.19461 p.2) states the instruction-generation step is a bottleneck.
- Overlap with CapEvolve: archive of candidate agents, parent selection, staged/cheap-then-full evaluation, failure-log-driven proposals, git-like lineage; baselines "w/o archive" ~ hill-climb.
- What it means for our claims: "archive/branching beats single-lineage hill-climb" has a direct precedent (DGM vs no-archive 50 vs 23; vs Greedy 39.7), so any CapEvolve claim of novelty for branching must be framed around budget-matched allocation, not archives per se. DGM comparisons were NOT compute-matched (22k vs 10k USD) and used one run each. Need: hill-climb vs agent-optimize at equal rollouts/$ with repeats. Reproduction feasibility: LOW for SWE-bench (USD 22k, 2 weeks); MED for Polyglot (~USD 5 per 60 tasks eval with o3-mini) but model set differs from CapEvolve's frozen-agent surfaces.
