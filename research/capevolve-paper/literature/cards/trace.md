- Citation count: unavailable (Semantic Scholar rate-limited 429 on 2026-10-11)
- Editable surface: "trainable" nodes in a traced Python workflow: prompts, code functions (bundle-decorated), hyperparameters, numeric values; heterogeneous and jointly optimized (Sec 1.2, 3; Sec 5.3 optimizes prompt_template + create_prompt + extract_answer code of a DSPy program).
- Search method: not a search/archive algorithm. OPTO setup: optimizer gets execution-trace subgraph + output feedback and proposes parameter update (Sec 4, p.6-7). OptoPrime = single LLM call per step with ReAct-CoT prompt; "optimization memory" of past parameter-feedback pairs (p.7). Backward propagation of minimal subgraph (Alg 1-2, p.6). Streaming one-candidate-per-iteration; no archive, no merging.
- Feedback signal: rich -- scalar/binary reward text, console/error output, natural-language feedback, plus the computation-graph trace (p.1-2, 7).
- Task splits / held-out protocol: varies per experiment. BBH: 15 train / 5 val / rest test per task (p.8). Meta-World: train rollouts, evaluated on 10 held-out initial conditions (p.8-9). Numeric/traffic/Battleship: no held-out split (optimization instances). Table 2 reports last-iterate (no best-of selection) over 5 seeds (p.10).
- Benchmarks (with versions) and models: synthetic numerical opt; UXSim traffic control; Battleship; BigBench-Hard (23 tasks, Table 1); LLF-Bench Meta-World (Reach/Pick-place/Push); TextGrad eval suite (MMLU-ML, MMLU-Physics, GPQA, BBH counting/word-sorting, GSM8K; Table 2). Optimizer GPT-4-0125-preview (p.7); Table 2 optimizer GPT-4o-2024-08-06, student GPT-3.5-turbo-1106 (p.10).
- Metrics: absolute error, traffic delay, % ship squares hit, BBH accuracy, success rate, wall-clock minutes (Table 2).
- Budget / cost reporting: token counts per prompt at iteration 1 (Table A.1, p.23: e.g. MetaWorld OPRO 470 vs OptoPrime 7101); wall-clock minutes vs TextGrad (Table 2); claims OPRO plateaus even at 7-10x more iterations (p.23). Not a matched-$ or rollout-budget study; no total search cost in $.
- Reported limitations: feedback design open problem; cannot trace in-place stateful functions or distributed/parallel workflows; OptoPrime preliminary, "uses more tokens than OPRO", limited by LLM context/debugging ability (Sec 6, p.10).
- Key quantitative results: BBH 0-shot all-23 tasks Trace 59.5 vs DSPy-COPRO 55.3 vs DSPy 41.6; with CoT 78.6 vs 71.6 vs 70.4 [Table 1, p.8]. Algorithmic subset 51.1 vs 45.2 [Table 1]. vs TextGrad (GPT-4o optimizer): MMLU-ML 86.6 vs 86.1, GPQA 59.6 vs 53.2, BBH-Counting 89.4 vs 89.2; ~3x faster (e.g. GPQA 12.2 vs 19.5 min) [Table 2, p.10]; "similar success rates" per text p.9. Numeric: matches Adam (Fig 5a). Meta-World: top of OPRO and NoMem variants (Fig 6, p.9; values only in plot -> UNVERIFIED numerically).
- Candidate-evaluation allocation: none; each step evaluates one proposed update on the sampled task/episode (streaming OPTO). No subset triage, bandit, or posterior.
- Task selection / curriculum: none (fixed training instances/episodes).
- Merge/composition: none. Updates are applied to the parameter set directly; no branch merge.
- Optimizer self-modification: none (optimizer prompt fixed; "OptoPrime" is a hand-designed optimizer). TextGrad reimplemented as an optimizer inside Trace (p.9).
- Overlap with CapEvolve: closest conceptual ancestor of "trace/trajectory-conditioned multi-surface editing": heterogeneous parameters (prompts + code) edited from execution traces with textual feedback; library-level (Python decorators) vs CapEvolve's coding-agent CLI edits.
- What it means for our claims: unsafe to claim novelty for "optimizing prompts+code jointly from execution traces"; safe to claim differences in held-out protocol, paired-gate acceptance, multi-candidate DAG. Required comparison: a Trace/OptoPrime (or OptoPrime memory) arm on our adapter tasks with equal LLM-token budget, since Trace itself shows token cost >> OPRO. Reproduction feasibility: medium-high (MIT, pip library, LiteLLM backend; needs adapter to decorate target code; their benchmarks are small/synthetic so no native task overlap).
