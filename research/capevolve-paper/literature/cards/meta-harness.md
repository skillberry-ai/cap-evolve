- Citation count: 273 (Semantic Scholar API, retrieved 2026-10-11)
- Editable surface: single-file Python harness (prompt construction, retrieval, memory, orchestration, state update) per task domain (p.5). Not the proposer/outer loop.
- Search method: outer loop with ONE coding-agent proposer (Claude Code, Opus 4.6) that reads a FILESYSTEM holding source, scores and raw execution traces of EVERY prior candidate via grep/cat; proposes k new harnesses per iteration; each passing interface validation is fully evaluated and logged (Algorithm 1 p.5). Archive = population + Pareto frontier (accuracy vs context cost); "imposes no parent-selection rule" (p.4). No merging operator; proposer may recombine freely. Memory = the filesystem (median 82 files read per iteration, 41% code/40% traces; Table 8 p.15, TB2 run).
- Parent selection: none (proposer free to inspect any prior harness). Initial population = baselines (zero/few-shot, ACE, MCE; zero/few-shot, ACE for math; Terminus 2 + Terminus-KIRA for TB2).
- Feedback signal: scalar score(s) PLUS full traces and code (ablation: scores-only median 34.6 / best 41.3; scores+LLM summary 34.9 / 38.7; full 50.0 / 56.7 [Table 3 p.7], search set).
- Task splits / held-out protocol: Text classification and math retrieval: search set selects candidates; test sets held out until final (p.4, 6). Math: search set described as 250 problems (p.8) but App. D tips say "88 problems for math retrieval" and "50-100 examples" for classification (p.24-25) -- internal inconsistency; test = 200 IMO-level problems (App. C.3 p.23), retrieval corpus decontaminated (p.8). Text classification OOD: 9 unseen datasets (Table 5). TerminalBench-2: SEARCH AND FINAL EVAL ON THE SAME 89 TASKS, declared a "discovery problem" (p.9); regex/manual leakage audit only.
- Benchmarks and models: LawBench, Symptom2Disease, USPTO-50k (GPT-OSS-120B classifier); math retrieval with GPT-OSS-20B search model, held-out GPT-5.4-nano/mini, Gemini-3.1-Flash-Lite, Gemini-3-Flash; TerminalBench-2 with Claude Opus 4.6 and Haiku 4.5.
- Metrics: accuracy; extra context tokens; pass@1 averaged over 3 samples (math); TB2 pass rate.
- Budget / cost reporting: Matched evaluation count vs OpenEvolve/TTT-Discover/GEPA/Best-of-N ("same budget of proposal harness evaluations", p.6). Typical run ~60 harnesses/20 iterations, "a few hours of wall-clock" (pp.5,10); Table 1 gives ~10 MTok/iteration context. NO dollar cost or proposer token total for the search. Text classification run: 20 iterations x 2 candidates = 40 harnesses (p.6); math: 40 iterations, 109 candidates (p.8); TB2 search 10 iterations (Table 8).
- Reported limitations: only one strong proposer (Claude Code) tested; broader study of proposer agents left to future work (p.10); TB2 specialised to the benchmark; ForgeCode result not reproducible from public code (p.9).
- Key quantitative results: Text classification test avg acc 48.6 vs ACE 40.9, MCE 40.0, few-shot(all) 40.8; ctx 11.4K vs 50.8K/28.5K [Table 2 p.6] (USPTO 14.0 < ACE 16.0). Search-set median/best: MH 50.0/56.7 vs GEPA 32.6/40.2, Best-of-N 34.0/44.2, OpenEvolve 39.1/43.3, TTT-Discover 34.1/45.6 [Table 4 p.7]. OOD 9 datasets avg 73.1 vs ACE 70.2 [Table 5 p.8]. Math (200 IMO-level): avg 38.8 vs no-retriever 34.1 (+4.7), BM25 37.5 [Table 6 p.8] (GPT-OSS-20B was the search model, so 1 of the 5 "held-out" models is not held out). TB2: Opus 4.6 76.4 (Terminus-KIRA 74.7, ForgeCode 81.8), Haiku 4.5 37.6 (Goose 35.5) [Table 7 p.9].
- Candidate-evaluation allocation: FULL search-set evaluation of every candidate; no subset/racing/bandit. Efficiency comes from proposer quality ("matches best prior optimizers in 0.1x evaluations", p.6).
- Task selection / curriculum: none during search; tip: pick a search set the baseline fails (App. D p.24).
- Merge/composition: none explicit; proposer can combine ideas from multiple prior candidates (TB2 trajectory: separated confounded edits, then additive change; p.9).
- Optimizer self-modification: No (proposer + skill prompt fixed; "Meta-Harness is itself a harness" but not optimised).
- Overlap with CapEvolve: very high: coding-agent proposer, edits code, read access to prior candidates' code/scores/traces, Pareto objective option, harness vs held-out evaluation. Differences: no acceptance gate, no explicit failure clustering/impact attribution, no staged eval, no sealed test in TB2.
- What it means for our claims: "agentic proposer with full-history access" is NOT novel (Meta-Harness); any such claim must be dropped or narrowed to digested/structured evidence, gates, and cost-aware allocation. Required comparison: Meta-Harness-style raw-filesystem proposer vs our digest at equal candidate-evaluation count AND equal proposer tokens (their proposer cost is unreported). TB2 results cannot be cited as held-out. Reproduction feasibility: MED-HIGH for text classification (MIT code, ~40 candidate evals, but Opus-4.6 proposer cost unknown); LOW for TB2 leaderboard parity.
- Discrepancies vs prior review/catalog: Venue: COLM 2026 per OpenReview (catalog/review say preprint). Review's TB2 caveat is correct (same 89 tasks). Review's "cross-model mathematical transfer" -- note one of five models is the search model. Math search-set size inconsistent in paper (250 vs 88).
