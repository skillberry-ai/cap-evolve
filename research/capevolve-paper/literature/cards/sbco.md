# SBCO (Self-supervised Block Coordinate Optimizer)
- Exact title: SBCO: Self-Supervised, Verifier-Grounded Harness Optimization For Planning Agents
- Authors: Vivek Kulkarni; Sudipta Paul; Aounon Kumar; Nicholas Tzou; Srinivas Chappidi (arXiv API 2026-10-11; Samsung Research America per PDF p.1)
- arXiv id + version read: 2608.10157, PDF sbco_2608.10157 (stamp "2608.10157v1 [cs.AI] 10 Aug 2026", p.1)
- First date (v1) / latest: 2026-08-10 / 2026-08-10 (v1 only). No arXiv comment/journal_ref.
- Venue/status: preprint. PDF contains no venue statement; acceptance not verified (preprint).
- Code URL + license + endpoint note: none found (no URL in PDF text; GitHub repository search for the title returned nothing). Not released as far as verified.
- Citation count: 0 (Semantic Scholar API, retrieved 2026-10-11)
- Editable surface: harness tuple (P prompt, T frozen tools, W workflow); optimizes P, a bank V of learned per-constraint verifiers (signature block + implementation block) and a free-form repair policy Pi (code) (Sec 3.1, p.3). Tools T are NOT edited. Domain-specific to constraint-checkable planning.
- Search method: fixed meta-agent (critic/strategist) doing approximate block coordinate ascent with textual gradients (TextGrad-style). Outer loop E=3 epochs over blocks in dependency order (signature -> implementation -> policy); inner BlockOptimize: <=5 tactical refinements + <=2 strategic pivots, keep-best ratchet, downstream can "escalate" to reopen upstream verifiers (Alg 1-2, p.4). Single incumbent; no population/archive/merge.
- Feedback signal: black-box evaluator returning reward + error descriptions per constraint; verifiers are judged by P/R/F1 against labels derived from baseline-run evaluations, accepted only if precision >= 0.80 and recall >= 0.55 (Sec 3.2, p.3). "Self-supervised" = no human labels.
- Task splits / held-out protocol: NO held-out test. Optimizes on a "subset of the benchmark for training (and validation)" and reports on the FULL task set (train+val), explicitly arguing this matches DGM/HGM practice (Sec 4, p.4). Train vs val gap reported (Travel 84.3 vs 83.9; Shopping 93.7 vs 94.8, p.5). Sizes of train/val subsets not found in text (UNVERIFIED). Means of two runs of the final policy.
- Benchmarks and models: DeepPlanning (Zhang et al. 2026e): Travel Planning and Shopping. Task agent GPT-5.4-mini; critic/strategist GPT-5.4 medium; transfer/scratch to a Mistral model (unnamed size) (p.4-5, Tables 2-3).
- Metrics: Composite score + Case Accuracy (Travel); Match score + Case Accuracy (Shopping); latency; budget = number of plans generated in optimization (HGM protocol).
- Budget / cost reporting: yes, in plans generated during optimization: HGM 8000, HGM-C 4000, SBCO 733 (Travel) / 989 (Shopping) => "4-5.5x lower" (Table 1, p.6; numbers read from garbled table: values 8430 523733 94 79132989 parse as Composite 84, Case 30, Latency 523, Budget 733; Match 94, Case 79, Latency 132, Budget 989; consistent with 4000/733=5.5 and 4000/989=4.0). Dollar/token cost not reported.
- Reported limitations: two constraint-based planning domains only; gains bounded by base LLM; fixed meta-agent, no meta-cognition; open when verification is as hard as solving (Sec 6, p.7).
- Key quantitative results (Table 1, p.6, scale 0-100): Travel composite baseline 76 / HGM 77 / HGM-C 83 / SBCO 84; Shopping match 83 / 83 / 91 / 94, case acc 50 / 50 / 70 / 79. Cross-model (Table 2, p.6): Mistral Travel 32.2 -> 42.1; Shopping 62.3 -> 94.4. 86% of gains from verifiers with F1>=0.80 (p.1). Observed reward hacking in Shopping: policy only appends items because extra items are not penalized (p.7).
- Candidate-evaluation allocation: no racing/bandit/subset scheme; each block step evaluates a generated artifact against its own surrogate (verifier F1 on a small ground-truth set, cheap) or against the task reward on training plans; keep-best ratchet + acceptance gate; strategic pivot after stalled iterations. Unclear how many tasks per policy evaluation (UNVERIFIED).
- Task selection / curriculum: none stated; verifier ground-truth sets derived from baseline-run evaluations.
- Merge/composition: none. Verification is of the OUTPUT at deploy time: every repair re-runs verifiers and is kept only if it strictly reduces the trusted-fail set with no regression, else reverts (Travel policy, p.6) -- this is runtime plan verification, not merge verification.
- Optimizer self-modification: none by design ("fixed meta-agent", self-supervised not self-referential, p.1-2); contrasts with DGM/HGM/Hyperagents.
- Overlap with CapEvolve: structured block-wise optimization of prompt + code policy under verifiable feedback; compute-efficiency vs HGM; keep-best ratchet; train/val gap check. Little overlap on tool descriptions/MCP/skills.
- What it means for our claims: Low risk to core claims. Reminder that a structured fixed optimizer can reach population-search quality at 4-5.5x fewer evaluations (HGM-C comparison). It weakens "held-out measurement" norms (it reports on train+val), which supports our sealed-test differentiator; do not cite its numbers as held-out. Reproduction feasibility: low (no code, DeepPlanning benchmark, GPT-5.4 access, tiny n of 2 runs).
- Discrepancies vs prior literature review / catalog: Review lists it as "verifier-grounded block-coordinate optimization for planning agents ... a simple structured optimizer can be the right comparator": consistent. Note the review does not flag that results are on train+val (no held-out) and from 2 runs. Catalog has no code_url (none found). Catalog date 2026-08-10 matches arXiv API.
