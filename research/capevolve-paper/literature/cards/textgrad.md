# TextGrad
- Exact title: TextGrad: Automatic "Differentiation" via Text (arXiv v1). The Nature version has a different title: "Optimizing generative AI by backpropagating language model feedback".
- Authors (arXiv v1): Mert Yuksekgonul, Federico Bianchi, Joseph Boen, Sheng Liu, Zhi Huang, Carlos Guestrin, James Zou. Nature version adds Pan Lu (author list from nature.com meta tags, 8 authors).
- arXiv id + version read: 2406.07496v1 (PDF stamp "arXiv:2406.07496v1 [cs.CL] 11 Jun 2024"; 41 pages; arXiv API shows no later version)
- First date (v1) / latest version date: 2024-06-11 / 2024-06-11
- Venue/status: PUBLISHED in Nature, vol. 639 (issue 8055), pp.609-616, online 2025-03-19, DOI 10.1038/s41586-025-08661-4, under the title "Optimizing generative AI by backpropagating language model feedback". Source: nature.com article page meta tags fetched 2026-10-11. The arXiv text we read is the preprint (v1), not the Nature version, so numbers below are from v1 and may differ from the journal paper (not read).
- Code URL + license + endpoint note: https://github.com/zou-group/textgrad (PDF p.1 "Repository"); MIT (GitHub API). README announces a litellm-based engine (any litellm-supported model); engine/openai.py has OpenAI client and an OLLAMA_BASE_URL override (grep of raw files), so OpenAI-compatible endpoints are supported in practice (not run).
- Citation count: 257 (Semantic Scholar Graph API, arXiv:2406.07496, retrieved 2026-10-11; arXiv-id record, may not include Nature-version citations)
- Editable surface: any text variable in a computation graph: a system prompt, a code solution, a final answer for one instance, molecule SMILES, radiotherapy plan parameters. In the prompt-optimization setting: one system prompt.
- Search method: textual gradient descent (TGD): forward pass through LLM calls builds a graph; the evaluator LLM produces a loss as text; backward() asks an LLM, per node, for criticism of the variable given its consumers' criticism (Eq. 6-9, pp.4-5); optimizer.step() = LLM(prompt "Below are the criticisms on {x}: ...") rewrites the variable. Features: minibatch via tg.sum of per-example losses, natural-language constraints, optional momentum (see earlier values, App. B). Prompt optimization is greedy hill-climb with a validation gate: after each iteration run the validation loop and keep the update only if validation performance improved (p.11). Archive: single incumbent (+ optional history in context). No candidates population, no merge.
- Feedback signal: textual critiques from an evaluator/gradient LLM (gpt-4o), optionally with code unit-test results (LeetCode), docking/QED scores, dose-volume metrics, or ground-truth correctness via an exact-match/LLM judge. Test-time instance optimization (GPQA/MMLU) is self-supervised (no labels).
- Task splits / held-out protocol: prompt optimization: BBH Object Counting and Word Sorting randomly split 50/100/100 train/val/test; GSM8K 200/300/1319 train/val/test (DSPy splits) (App. E.1 p.33); batch size 3, 12 iterations (36 training examples seen, sampled with replacement), validation after each iteration (p.11). Table 3 does not name its split in the caption; the text implies reporting on the held-out split but I did not find the word "test" for it (UNVERIFIED which split the 81.1/91.9/79.8 are measured on). GPQA Diamond 198 q, MMLU-ML 112 q, MMLU-College Physics 92 q (App. D p.32): Table 2 numbers are measured directly on these evaluation questions after 3 label-free test-time refinements plus majority vote; no train/val/test.
- Benchmarks and models: LeetCode Hard (gpt-4o, 5 seeds), GPQA Diamond, MMLU-ML, MMLU-College-Physics (gpt-4o), BBH Object Counting / Word Sorting, GSM8K (forward model gpt-3.5-turbo-0125, gradient/optimizer gpt-4o), DOCKSTRING molecules (58 targets, 10 iterations, 3 starting fragments), prostate radiotherapy plans (10 iterations max).
- Metrics: LeetCode completion rate; accuracy; docking Vina + QED; clinical dose criteria.
- Budget / cost reporting: iterations only (5 for code, 3 for solution refinement, 12x3 examples for prompts, 10 for molecules); per iteration of GPQA: 1 gpt-4o call for loss, 1 for gradient, 1 for update (p.32). No $/tokens/wall-clock.
- Reported limitations (Discussion p.17): framework a first step; need to extend to tools/RAG operations; variance reduction/adaptive-gradient ideas, self-verification and meta-learning of TextGrad left to future work; molecule/treatment plans only in silico, clinical validation out of scope.
- Key quantitative results: Table 1 (p.8) LeetCode Hard gpt-4o completion rate over 5 seeds: zero-shot 0.26; Reflexion (1 demo, 5 it.) 0.31 +- 0.012; TextGrad (0 demos, 5 it.) 0.36 +- 0.018. Table 2 (p.10) gpt-4o: GPQA CoT 51.0, best reported 53.6, TextGrad 55.0; MMLU-ML 85.7 -> 88.4; MMLU-College Physics 91.2 -> 95.1. Table 3 (p.11) gpt-3.5-turbo prompt optimization: Object Counting CoT 77.8, DSPy BFSR 84.9, TextGrad 91.9; Word Sorting 76.7 / 79.8 / 79.8; GSM8K 72.9 / 81.1 / 81.1 (82.1 with DSPy demos added to TextGrad prompt, p.12). In GEPA's reimplementation on GPT-4.1 mini TextGrad aggregate is 59.14 vs GEPA 65.22 (GEPA Table 2 p.8; run inside Trace framework).
- Candidate-evaluation allocation: none beyond greedy accept/reject on the full validation set per step (single candidate lineage; each update is evaluated once on full val).
- Task selection / curriculum: random minibatches of 3; no failure-targeted sampling.
- Merge/composition: none (momentum shows previous iterations to the optimizer but does not merge branches).
- Optimizer self-modification: none; suggests meta-learning TextGrad as future work.
- Overlap with CapEvolve: closest conceptual match to our hill-climb: single incumbent, textual-gradient edit from failures on a batch, accept only if val improves (we use paired gate mean(delta) > k*SE instead of raw improvement). Also test-time instance refinement.
- What it means for our claims: (a) a greedy validation-gated textual-gradient hill-climb is established; our hill-climb's novelty is the large multi-part edit across surfaces plus paired-SE gate and protect-set, not the loop. (b) Raw "improved on val" gating with val of 100-300 and stochastic LLM scoring is noisy; this motivates our paired SE gate; TextGrad is the control for that ablation. (c) TextGrad results on GPQA/LeetCode are instance-level test-time optimization with self-evaluation; not comparable to held-out generalization. (d) Use the Nature version for citation but note the arXiv v1 experiments. Reproduction feasibility: HIGH (MIT code, litellm/OpenAI engines; small tasks) for prompt optimization; the GEPA-style comparison (Trace-hosted TextGrad) is a stronger fidelity check.
