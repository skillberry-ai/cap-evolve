- Citation count: unavailable (Semantic Scholar rate-limited on 2026-10-11)
- Editable surface: the coding agent's own codebase (same DGM initial agent, App. C.1 p.18). Search/estimator code is fixed.
- Search method: self-modification TREE (explicitly a tree, p.3). Three sub-policies (Table 5 p.20): selection (expand vs evaluate; UCB-Air rule: expand when N^alpha >= |tree|, alpha=0.6), expansion (Thompson sampling over clade success/failure counts, i.e. Clade-Metaproductivity CMP estimate with annealed scheduler tau=B/b-like), evaluation (Thompson sampling over agent's own successes/failures, ONE agent-task pair per step). Final agent = "best-belief" (epsilon-percentile of Beta posterior, eps=1). Async version for parallel CPUs. Pp.6-7.
- Parent selection: Thompson sample on clade-aggregated counts (descendants' task outcomes pooled), not on the agent's own score (p.6).
- Feedback signal: binary per-task pass/fail only; no textual signal in the allocation rule.
- Task splits / held-out protocol: Optimisation and headline selection on the same pool: SWE-Verified-60 (first two DGM stages) and Polyglot subset with 800 task evaluations (p.8); full SWE-bench Verified (500) with 8000 evaluations for the large run (p.9). The 61.4% on full Verified is therefore in-sample. Held-out = SWE-bench Lite (300 tasks; "filtered" setting drops 93 overlapping with Verified -> 207) and model shift to GPT-5 (Tables 3-4, p.10).
- Benchmarks and models: SWE-bench Verified, Lite; Polyglot. Expansion GPT-5, eval GPT-5-mini (SWE); Qwen3-Coder-480B / 30B (Polyglot) (p.8).
- Metrics: accuracy of best-belief agent; allocated CPU-hours for 800 evaluations; Pearson corr. of selection criterion vs empirical CMP (Table 1 p.8).
- Budget / cost reporting: YES, matched count of task evaluations (800) and wall-clock CPU-hours (Table 2 p.9). Not tokens/$. Single run per method; no seeds/CI found.
- Reported limitations: no dedicated limitations section found; notes SICA failed on SWE-60 with context overflow after 360 evals (p.9); leaderboard overfitting caveat (p.9).
- Key quantitative results: Table 2 [p.9] (acc / hours): SWE-Verified-60 SICA 50.0 / "infinite loop", DGM 53.3 / 1231, HGM 56.7 / 517 (start 40%); Polyglot SICA 25.4 / 572, DGM 27.1 / 2385, HGM 30.5 / 347 (start 20.3%). Table 1 [p.8] CMP correlation weighted: HGM 0.778 vs DGM 0.285, SICA 0.444 (SWE-60); 0.626 vs 0.383/0.274 (Polyglot). Full Verified: 53.2 -> 61.4 after 8000 evals [p.9]. SWE-Lite (GPT-5-mini) standard 44.0 -> 49.0 (SWE-agent+GPT-5-mini 47.6), filtered 34.8 -> 40.1 (39.6) [Table 3 p.10]; with GPT-5: 57 standard vs SWE-agent 56.7, filtered 47.8 vs 48.3 [Table 4 p.10].
- Candidate-evaluation allocation: ADAPTIVE BANDIT: decoupled expansion from evaluation; Thompson sampling picks which existing agent gets one more task evaluation; new children are not auto-evaluated. Closest published analogue to CapEvolve's posterior-based probe/promote.
- Task selection / curriculum: none stated (tasks drawn within an agent's evaluation; asynchronous variant biases toward easy tasks finishing first, App. B p.17).
- Merge/composition: none.
- Optimizer self-modification: no more than DGM (agent edits own code; selection rule fixed). Claims theory (CMP oracle suffices to implement Godel Machine under Assumption 1, p.5).
- Overlap with CapEvolve: highest among this group for the "allocate budget across candidates and tasks with posteriors" part: per-agent Beta posteriors, Thompson sampling, final selection by posterior quantile, budget-matched comparison.
- What it means for our claims: "Bayesian/posterior allocation of evaluation budget across candidate branches" is NOT novel as such (HGM); CapEvolve's novelty must rest on per-task signals, multiple editable surfaces, merge verification, sealed test. Required comparison: equal-evaluation-count comparison vs a HGM-style Thompson allocator or at least cite. HGM compares only SICA/DGM at 800 evals, single run. Reproduction feasibility: MED (800-eval Polyglot runs reported at 347-2385 allocated CPU-hours; open code; but coding-agent self-modification target, different from CapEvolve surfaces).
