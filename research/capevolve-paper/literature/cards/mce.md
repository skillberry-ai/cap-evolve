- Citation count: unavailable (Semantic Scholar rate-limited 2026-10-11)
- Editable surface: "context function" = folder of files and code (static knowledge/rules/examples + dynamic retrieval/selection operators) built by a base agent; plus the "CE skill" (folder: methodology text, scripts, templates, validation protocols, operators) evolved by a meta agent (Sec 3.1-3.3, pp.4-5). Scope is context engineering for a single-shot query->context interface; not agent tool code or MCP.
- Search method: bi-level (1+1)-ES. Each iteration k: meta-agent does "agentic crossover" over skill database H_{k-1} (skills, resulting contexts, train/val scores) -> new skill s_k; base agent runs s_k on training rollouts of the previous best context c*_{k-1} (warm start) and writes c_k; c_k scored on D_train and D_val; keep better of {c*_{k-1}, c_k} by VAL score (Alg.1, p.6). Archive = full history but selection is single-incumbent. 5 epochs.
- Feedback signal: labels/ground truth (supervised tasks: tag, SMILES, disease, charge, safe/unsafe); rollouts with eval; agent reads raw errors.
- Task splits / held-out protocol: train/val/test per domain, test used only for reporting; selection on val (Eq.3, p.5). FiNER 200/100/100 (A.1 p.16); USPTO-50k 50/30/100 (A.2 p.17); Symptom2Disease 200/50 train/val, original test split 212 stated (A.3 p.18; subset actually used UNVERIFIED); LawBench 200/50/100 (A.4 p.19); Aegis2 400 train/128 val/140 test (A.5 p.20). "use data subsets due to computational budget" (p.6).
- Benchmarks and models: FiNER, USPTO-50k, Symptom2Disease, LawBench (criminal charge), AEGIS2. Generator DeepSeek-V3.1 (Qwen3-8B for AEGIS2); reflector DeepSeek-V3.1; MCE agent MiniMax M2.1 via Claude Agent SDK; all through OpenRouter (Sec 4.1, p.7). Transfer to Llama3.3-70B, Qwen3-8B, Gemma3-4B (Table 2, p.8).
- Metrics: accuracy (pass@1) / micro-F1 / F1; relative gain over base; rollout count and wall-clock.
- Budget / cost reporting: partial. Baselines "training budget no less than MCE"; GEPA/MIPROv2 auto="heavy" and GEPA matched to MCE total rollout budget (p.7). Training efficiency on FiNER only: MCE 95% train acc at 450 rollouts vs ACE peak 94% at 2169 (4.8x); 1.9h vs 25.8h (13.6x) (Fig 4, p.9; Obs 8-9, pp.9-10). No $/token cost of the meta-agent reported (UNVERIFIED beyond these).
- Reported limitations: advantage on knowledge/pattern tasks, may not help reasoning-heavy tasks; may struggle with very long complex trajectories (p.10-11).
- Key quantitative results: Offline avg relative gain 89.1% vs ACE 70.7% (Table 1, p.8): FiNER 75.0 vs ACE 71.0, USPTO 20.0 vs 18.0, Symptom2Disease 89.2 vs 79.2, LawBench 0.70 vs 0.65, Aegis2 0.80 vs 0.68. Online avg 74.1 vs ACE 41.1. Ablation on FiNER: full 75.0 vs no-skills 73.0 vs fixed skill 71.0 vs ACE 71.0 (Table 3, p.10) -> skill evolution adds +2 on 100 test items (single run, no CIs). Abstract: 5.6-53.8% relative gain over SOTA, mean 16.9%.
- Candidate-evaluation allocation: one offspring per iteration, evaluated on full train and full val sets; no subset/racing/bandit. Training data batching optional.
- Task selection / curriculum: none (all training data, optional batching).
- Merge/composition: "agentic crossover" = LLM agent reads history of skills and synthesizes a new skill by combining elements of prior skills (Sec 3.2). Not verified by anything other than the child's val score; no merge-conflict check or per-component verification.
- Optimizer self-modification: yes at the procedure level: the evolved "skill" is the learning procedure the base agent executes (how context is built), improved by a meta-agent with val feedback. The meta-agent's own prompt/tools stay fixed. Fixed-skill and no-skill variants are ablated (Table 3).
- Overlap with CapEvolve: skill folders (methodology+scripts+templates) as an evolved artifact; train/val split with val-based incumbent selection; skill DB history (like LEDGER); batch-level rather than instance-level reflection.
- What it means for our claims: Unsafe: "first to evolve multi-file skill packages with an agentic optimizer" and "optimizer-procedure evolution is novel" (MCE evolves the optimizer's skill). Our edge must be surfaces beyond context (agent tool code, MCP descriptions), pass^k, sealed test, and budgeted allocation. Required comparison: MCE-style (1+1)-ES with agentic crossover as baseline vs hill-climb on the same tasks. Reproduction feasibility: medium-high (MIT, OpenRouter, small data), but domains differ from our adapters.
