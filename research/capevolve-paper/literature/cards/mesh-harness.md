- Editable surface: harness Python code decomposed into k typed functional slots (k=5 or 7; p=640/896 features, d=128 per slot; Table 11 p.22), each with fixed interface; 10 LLM-generated implementations per slot. Whole-harness code, not prompts/skills only.
- Search method: contextual-bandit selection of complete slot compositions. Archive = validation archive (config, reward, traces, cost). Selection = full-covariance LinUCB over concatenated frozen-embedding (Qwen3-Embedding-8B) features; U_t = mean + alpha*g*sigma + coverage bonus - lineage-reuse penalty (Eq.6-7 p.5); maximized by mixed-start coordinate ascent (start: incumbent 0.65 / top-5 archived 0.20 / random 0.15; two sweeps). Every L=5 evaluations an LLM diagnoses val traces and proposes <=2 child modules in distinct slots; child replaces lowest-retention module (mean reward of configs containing it) in a fixed-size pool (Eq.10 p.6). Children get no immediate evaluation. Memory: bandit stats (A,b), archive, lineage records.
- Feedback signal: scalar validation score per complete configuration (no per-module reward; p.4) plus textual execution traces for the module proposer.
- Task splits / held-out protocol: train/val/test (Table 9 p.20): USPTO 50/30/100; Symptom-to-Diagnosis 200/50/212; LawBench 200/50/100; Math -/400/500 (200 OlympiadBench + 200 MathArena dev; 254+246 test); LiveCodeBench v6 100/100/100; ScienceWorld 66/22/102 episodes. Stated: "Test data are not used for generation, selection, or stopping" (p.4); final harness picked from validation archive (App. C.5 p.23), frozen, test = mean of 3 reruns of the SAME frozen harness (p.6, C.4). Search seed 42; single search run per task (no across-search variance reported).
- Benchmarks and models: LawBench, USPTO, Symptom-to-Diagnosis (Gretel 22-class), OlympiadBench+MathArena (retrieval corpus 433,926 pairs), LiveCodeBench v6 (cap-8 protocol), ScienceWorld. Executor DeepSeek V4 Flash (thinking off); proposer Claude Code with Claude Opus 5 (medium effort); transfer test on GPT-5.6 Luna, Qwen 3.8 Flash, Claude Sonnet 5 (Table 7 p.9). (Model names as stated in paper; not independently verifiable.)
- Metrics: text macro-accuracy, pooled math pass@1, LCB cap-8 solve rate, ScienceWorld mean progress; 0-100.
- Budget / cost reporting: YES. Budget = 40 complete candidate evaluations per task for all optimizers (Meta-Harness = 20 rounds x 2 candidates; MESH = 40 x 1) (p.6, C.5 p.23). USD search+test and test-only reported (Table 6 p.9): total 195.0537 -> 166.6078 (-14.6%); test-only 3.5528 -> 1.9835 (-44.2%). Pool init, embedding, interface checks, reference-harness evals counted in search cost (C.5). Matching is on #candidate evaluations, not tokens; all baselines run with same cap.

- Candidate-evaluation allocation: EXACT. Arms = complete configurations in H_t = prod_j P_j,t (N=10 impls/slot; 10^5 or 10^7 combos); a "pull" = one full evaluation of the composed harness on the full validation set, yielding one scalar reward; exactly T=40 pulls total, 1 per round, repeat-pulls of an already-evaluated config avoided (favor unevaluated on ties, random fallback; Alg.1 p.4, p.5). No subset evaluation, racing, or successive halving; no repeated measurement of the same arm, so validation noise is not averaged. Cheap comparison happens ONLY in the surrogate (ridge posterior; O(S*sum|P_j|) scores per round, no execution). New modules enter pools without evaluation and are evaluated only when the bandit picks a composition containing them. Posterior update A<-A+xx^T, b<-b+r x (Eq.9). Guarantee: only a ridge-transfer/uncertainty proposition (App. A.1-A.3) with an extra confidence-envelope assumption; no regret bound claimed in the text read.
- Task selection / curriculum: none; full fixed validation set each pull. Trace clustering picks which slots to edit (failure-driven / random-diverse / top-local proposals).
- Merge/composition (verified?): composition = pick one implementation per slot from different lineages, no LLM rewrite (p.3). Each composition actually chosen is evaluated end-to-end on val before it can be selected; untested compositions are never deployed. Per-module contract/interface + execution checks (p.4); no pairwise-interaction verification beyond that, and surrogate is additive in slot features plus cross-slot covariance for uncertainty only (p.5).
- Optimizer self-modification: none (proposer and bandit fixed).
- Overlap with CapEvolve: allocation of a fixed evaluation budget across candidate compositions; module-level recombination analogous to branch merge; held-out discipline (val-only selection, frozen test) matches CapEvolve's sealed split.
- What it means for our claims: "budgeted allocation across candidates" is no longer novel in principle; a bandit/surrogate over compositions with matched #evaluations beat a single-lineage proposer (Meta-Harness) in this paper, so a hill-climb-vs-surrogate-composition comparison at matched full-evaluation count is required if we claim allocation benefits. Claims of "first merge/composition of harness components" are unsafe. Note the matched budget is in #full evaluations (40) not tokens, and test deltas (e.g. LCB +2.0 on 100 problems, ScienceWorld +5.0 on 102 episodes) come from one search run per task, so SE is not accounted for. Reproduction feasibility: med (algorithm and hyperparameters fully specified in Table 11; no code released that I could find; needs slot decomposition per adapter).
