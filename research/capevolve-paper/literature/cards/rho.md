# rho (RHO, Retrospective Harness Optimization)
- Exact title: Evolving Agents in the Dark: Retrospective Harness Optimization via Self-Preference
- Authors: Wenbo Pan, Shujie Liu, Chin-Yew Lin, Jingying Zeng, Xianfeng Tang, Xiangyang Zhou, Yan Lu, Xiaohua Jia (arXiv API)
- arXiv id + version read: 2606.05922, v3 (PDF stamp "29 Aug 2026")
- First date / latest: 2026-06-04 (v1) / 2026-08-29 (v3) [arXiv API]
- Venue/status: EMNLP 2026 Findings (not main track), accepted -- source: arXiv comment only ("Accepted to EMNLP 2026 (Findings)"); ACL Anthology/proceedings page NOT checked. Treat as accepted-per-arXiv-comment.
- Code URL + license + endpoint note: https://github.com/wbopan/retro-harness ; MIT (GitHub API). Drives the Codex CLI as base agent; model backend selected via a Codex config TOML (README); use with a non-OpenAI OpenAI-compatible endpoint UNVERIFIED (paper used Azure Foundry, GPT-5.5, App. E p.21).
- Citation count: 16 (Semantic Scholar API, retrieved 2026-10-11)
- Editable surface: whole harness directory: markdown instructions + skills + executable tool scripts (p.6, Fig 3). Not model weights.
- Search method: ONE retrospective round (no archive). (1) coreset: LLM judge scores difficulty of every past trajectory, DPP (theta=0.7) picks k=10 difficult+diverse tasks; (2) group rollout: re-solve each coreset task G=3 times with the current harness; self-validation and self-consistency rankings give improvement instructions; (3) best-of-N (N=3) harness proposals, each re-solves the 10 coreset tasks; agent pairwise-ranks new vs old trajectory; accept best candidate only if mean score S_j>0 (Algorithm 1 p.3; pp.4-5). No merging; no persistent archive across rounds (multi-round not studied; limitation).
- Parent selection: n/a (single parent = starting harness).
- Feedback signal: NO ground-truth labels or grader during optimisation; signals are the agent's own LLM judgments (difficulty, self-validation, consistency, pairwise self-preference). Graders used only for held-out evaluation (p.5).
- Task splits / held-out protocol: seeded hash-ordered split per benchmark. SWE-Bench Pro: first 100 = trajectory/train pool, next 100 = held-out test, rest unused; Terminal-Bench 2: 30 train / 59 held-out; GAIA-2 (mini): 100 train / 100 held-out (App. E pp.20-21). Test not used for selection by the method. BUT Table 3 reports all N=3 candidates' test scores (chosen vs best: SWE-Pro chosen 0.78, one other 0.85) -- analysis only, not used to choose. Prompt-level (not sandbox) instruction not to read verifier (p.20).
- Benchmarks and models: SWE-Bench Pro, Terminal-Bench 2, GAIA-2; Codex CLI with GPT-5.5 high reasoning (p.5). Single backbone only.
- Metrics: held-out pass rate (single number per cell; one optimisation run; Table 4 ablation n=1, reruns n=2 only for two ablations, p.9).
- Budget / cost reporting: YES, best in this group: agent-invocation counts per role, wall-clock (sum and end-to-end) and auxiliary LLM calls for every baseline (App. G Tables 7-8, pp.22-23). RHO optimisation phase = 103 agent calls (30 rollout, 10 diagnose, 3 optimize, 30 after-solve, 30 rank) on SWE-Pro. Matched-budget comparisons vs trajectory-only baselines (k=10, N=3). No $ or tokens.
- Reported limitations: needs resettable environments; assumes editable-harness-mediated competence; single backbone/agent framework; single round, no monotone/compounding claim; harnesses are benchmark-specific; trajectories can embed injected content (pp.9-10).
- Key quantitative results [Table 1 p.5] pass (held-out): SWE-Bench Pro vanilla 0.59 -> RHO 0.78 (+0.19) (Dynamic Cheatsheet 0.62, ReasoningBank 0.61, Sleep-time 0.64); Terminal-Bench 2 0.71 -> 0.76; GAIA-2 0.29 -> 0.37. Table 2 [p.7]: Meta-Harness (re-implemented) 1 round 41 calls (0.4x) = 0.62; 10 rounds 320 calls (3.1x) = 0.80 vs RHO 103 calls = 0.78. Ablation [Table 4 p.7]: -self-consistency 0.56/0.75/0.27; -self-validation 0.70/0.73/0.30; raw trajectories 0.60/0.75/0.29. Coreset ablation SWE-Pro: random 0.64, difficulty-only 0.62, coverage 0.58, DPP 0.78 [Fig 5 p.8].
- Candidate-evaluation allocation: every candidate (N=3) is re-solved ONCE on the same fixed 10-task coreset and scored by agent pairwise preference vs the original rollout; no labelled eval, no racing.
- Task selection / curriculum: YES -- difficulty+diversity coreset via DPP over LLM-judged trajectories (Sec 4.1 p.4); ablated (Fig 5).
- Merge/composition: none (best-of-N pick).
- Optimizer self-modification: No (pipeline fixed; the same agent is the judge and optimizer).
- Overlap with CapEvolve: subset/coreset-based triage of tasks; cost accounting in agent calls; harness = instructions+skills+tools (multi-surface); matched-budget comparison to Meta-Harness; acceptance gate (S_j>0) analogous to paired gate but on self-preference.
- What it means for our claims: "low-evaluation / label-free improvement" is claimed by RHO with a 10-task coreset and 103 agent calls; if CapEvolve claims cost-efficiency it needs call-count accounting in the same units (RHO's Table 7) and a comparison where our method also gets no val labels, or must say we use labels. RHO's Meta-Harness comparison is a re-implementation under reduced budget (1 round x 3 cand x 1 trial), so its "RHO beats Meta-Harness at matched budget" is weak evidence. Held-out sets are small (59-100 tasks, single run) -> SE of ~0.04-0.06. Reproduction feasibility: MED (MIT code, Codex+GPT-5.5 dependency, ~100-200 agent calls per dataset).
- Discrepancies vs prior review/catalog: Review says "unlabeled": confirmed; but selection among candidates uses LLM self-preference, not "new external labels" only. Catalog EMNLP 2026 Findings is from arXiv comment, not proceedings -- unverified beyond that. Review wording "offline access to rich traces is a resource": consistent with Table 7 (trajectory source runs are excluded from the 103 count). Otherwise none found.
