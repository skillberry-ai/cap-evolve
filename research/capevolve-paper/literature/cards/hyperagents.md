- Editable surface: a single Python program containing both task agent and meta agent ("hyperagent"); the meta agent's own code is editable (p.4-5). Outer loop (parent selection, evaluation protocol) is fixed in main experiments (p.5, p.14).
- Search method: DGM archive (tree) of hyperagents; ~80-100 iterations; handcrafted parent selection prop. to performance and number of compiled children (score-child-prop, App. A.2); children evaluated and added. No merging.
- Parent selection: score-child-prop (as DGM), using VALIDATION score when a validation split exists else train (p.6). Appendix E.5 (p.57): a variant where the agent edits parent selection (5 runs) got 0.491 vs random 0.428 vs handcrafted 0.532 on test (differences n.s., p>0.05).
- Feedback signal: scalar task scores on train tasks, plus archive/eval logs read by the meta agent; AI judges for paper review/IMO grading.
- Task splits / held-out protocol: Explicit train/val/test (Table 2, App. C p.28): Polyglot 60 train / none / 165 test; Paper review 100/100/100; Robotics reward 6 train / 6 test (different task: torso height); IMO-GradingBench 100/100/100 (held-out meta-eval domain). Parent selection on val; only best-by-val/train agents evaluated on test (p.8). Test not used for selection.
- Benchmarks and models: Polyglot, paper review (Zhao et al. 2026 dataset), Genesis robotics reward design, IMO-GradingBench. Self-mod Claude 3.5 Sonnet (New) on Polyglot, Claude 4.5 Sonnet elsewhere; eval o3-mini / GPT-4o / Claude 4.5 Sonnet / o4-mini (Table 3 p.35).
- Metrics: test accuracy / task score; imp@k (improvement of best-by-val generated agent over start after k=50 iterations with meta agent held fixed; p.9, D.3).
- Budget / cost reporting: partial: ~33M tokens self-modification per 100-iteration run, ~88.6M tokens total for paper+robotics run; evaluation tokens per iteration (Polyglot 0.89M/60 tasks; paper review 0.5M/100; robotics 0.006M; IMO 0.11M/100) (App. D.2 pp.35-36). No matched-budget comparison between methods stated in main text.
- Reported limitations: fixed task distribution; outer loop (parent selection, eval protocol) not modifiable; unbounded progress not shown (p.14).
- Key quantitative results: 5 runs per method, median with 95% bootstrap CI, Wilcoxon (p.7). Polyglot: train 50-task 0.140 -> 0.340 (CI 0.300-0.380); full Polyglot 0.084 -> 0.267 (0.231-0.280) [p.7]; DGM reference 0.142 -> 0.307 [p.8]. Paper review test 0.0 -> 0.710 (0.590-0.750) vs static AI-Scientist-v2 reviewer 0.630 [p.9]; DGM-custom 0.590; DGM 0.0. Robotics test 0.060 -> 0.372 (0.355-0.436), DGM-custom 0.348, default reward 0.348 [p.8-9]. DGM-H vs DGM-custom: higher median, NOT significant (p>0.05) [p.9]. imp@50 on IMO grading: initial 0.0; transfer hyperagents 0.630 (0.540-0.630) vs DGM-custom transfer 0.0 [Fig 3 p.10-11].
- Candidate-evaluation allocation: STAGED: 10 tasks first, then remaining train tasks only if "sufficient performance"; unevaluated tasks scored zero; joint domains: failing stage in any domain zeroes all (pp.6, 8). No bandit.
- Task selection / curriculum: fixed splits, no curriculum (stated as a limitation).
- Merge/composition: none within search; "transfer" of whole hyperagents across domains/runs (Sec 5.3).
- Optimizer self-modification: YES -- central claim. The meta agent (instruction generation + modification procedure) is part of the editable program; ablation DGM-H w/o self-improve fixes initial meta agent. Outer loop still fixed.
- Overlap with CapEvolve: held-out protocol with validation-based selection; staged evaluation; archive of agents; improvement@k as a way to measure optimizer quality independent of the task.
- What it means for our claims: Claim of "optimizer that learns to improve itself" is unsafe unless we modify and separately test our own optimizer (CapEvolve changes algorithms via human research, not autonomously). imp@k with fixed meta agent is a ready-made protocol for comparing hill-climb vs agent-optimize. License CC BY-NC-SA constrains reuse of the code. Reproduction feasibility: MED (token costs documented ~88.6M per run; robotics needs simulator; code NC license).
