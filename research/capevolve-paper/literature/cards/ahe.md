- Citation count: 123 (Semantic Scholar API, retrieved 2026-10-11)
- Editable surface: 7 file-level component types on the NexAU harness: system prompt, tool description, tool implementation, middleware, skill, sub-agent config, long-term memory (Sec 3.1, p.4). Seed H0 = single shell tool, no middleware/skills.
- Search method: single sequential lineage, no archive/population. Per round: k=2 rollouts/task on whole benchmark -> clean -> attribute previous manifest and ROLLBACK rejected edits (file granularity) -> Agent Debugger distills traces -> Evolve Agent edits workspace + writes change manifest (predicted fixes and at-risk regressions) -> git commit (Alg.1, p.5). H_best updated if round pass@1 > best. Memory: versioned manifest + evidence corpus. 10 iterations.
- Feedback signal: binary task pass/fail from benchmark verifier; textual root-cause reports from an LLM "Agent Debugger" over ~10M tokens of raw traces (Fig 2, p.4).
- Task splits / held-out protocol: NO train/val/test split for the headline result. Evolution runs on all 89 Terminal-Bench 2 tasks and Table 1 reports pass@1 on the same 89 (Sec 4.1, p.6). Held-out evidence only as frozen-harness transfer: SWE-bench-verified (500 tasks, Table 2, p.7) and 5 alternate model bases on TB2 (Fig 3, p.8; same 89 tasks, so task-overlap but model-transfer).
- Benchmarks and models: Terminal-Bench 2 (89 tasks; 4 easy/55 med/30 hard, 1h timeout); SWE-bench-verified (500). GPT-5.4 high for code agent, debugger, evolver (evolver xhigh, Table 4 p.16). Transfer: GPT-5.4 med/xhigh, qwen-3.6-plus, gemini-3.1-flash-lite-preview, deepseek-v4-flash.
- Metrics: pass@1 (mean over k rollouts; timeouts count as failure); tokens/trial; Succ/Mtok (App A, p.16).
- Budget / cost reporting: only "roughly 32 hours" for the 10-iteration campaign (p.6). Token cost reported for evaluation runs on SWE-bench (Table 2), NOT for the search ($ / tokens of evolution not reported). No matched-budget comparison with ACE/TF-GRPO stated (UNVERIFIED that budgets match).
- Reported limitations: benchmark scope; evolution operating point (step budget/timeout fitted to GPT-5.4 high, confounds transfer, p.10); self-modification governance incomplete (p.10); components interact non-additively; regression blindness of self-attribution (p.9).
- Key quantitative results: TB2 pass@1 NexAU0 69.7 -> AHE 77.0 (Table 1, p.6), vs Codex 71.9, TF-GRPO 72.3, ACE 68.9 (same seed NexAU0). SWE-bench-verified aggregate 75.6 vs seed 75.2, ACE 74.6, TF-GRPO 74.2 (Table 2, p.7); tokens 461k vs seed 526k (-12%). Cross-model gains +2.3 to +10.1 pp (Fig 3, p.8). Single-component swaps: memory-only 75.3, tool-only 73.0, middleware-only 71.9, prompt-only 67.4 (Table 3, p.8). Self-prediction fix precision 33.7% / recall 51.4% vs random 6.5/10.6; regression precision 11.8%/recall 11.1% vs random 5.6/5.4 (Fig 4, p.9). One campaign, no seeds/CIs.
- Candidate-evaluation allocation: one candidate per round, evaluated on the FULL benchmark (all 89 tasks x k=2). No subset/racing/bandit. Acceptance is not a statistical gate: next round continues from H_t minus edits whose predictions the delta falsified; H_best tracked by raw pass@1 on the same tasks.
- Task selection / curriculum: none; every round uses the entire task set. Per-edit prediction (which tasks will flip) is attributed afterwards.
- Merge/composition: none (no branches). Multiple edits per round are one commit set; ineffective edits reverted per file via manifest verdict (Alg.1 line 7).
- Optimizer self-modification: none for the Evolve Agent itself (it is fixed, edits only `workspace/`; runs dir, tracer, verifier, LLM config read-only; seed prompt non-deletable, p.5). The HARNESS self-evolves; the optimizer does not.
- Overlap with CapEvolve: multi-surface edits (prompt, tools, middleware, skills, memory) with file-level git commits and rollback; trace digestion into layered evidence; per-edit predicted fix/regression sets checked against next-round task deltas (close analogue of CapEvolve per-task fixed/broken impact + ledger).
- What it means for our claims: Unsafe: "first to jointly edit prompts+tool code+skills+memory of an agent with git-revertible components" and "first causal edit ledger / predict-then-verify edits". Required comparison: AHE-style per-edit rollback vs our paired-gate acceptance on the same seed harness and budget; report held-out (AHE has none for its headline, our sealed test is a differentiator). Reproduction feasibility: medium (MIT code, but needs E2B sandboxes, NexAU, GPT-5.4-class models, ~32 h per campaign).
- Discrepancies vs prior literature review / catalog: Review says "Terminal-Bench 2 Pass@1 69.7 to 77.0 over ten iterations" and asks whether gains are discovery or held-out: answer from PDF = discovery (same 89 tasks, Table 1); held-out only for SWE-bench-verified transfer and model transfer. Review says "lower token use in a coding evaluation": confirmed (-12% vs seed, Table 2). Catalog code_url empty; repo exists (p.1, p.16). Catalog venue "preprint" consistent with arXiv API.
