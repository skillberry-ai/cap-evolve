# ProTeGi (APO)
- Exact title: Automatic Prompt Optimization with "Gradient Descent" and Beam Search
- Authors: Reid Pryzant, Dan Iter, Jerry Li, Yin Tat Lee, Chenguang Zhu, Michael Zeng (arXiv API; Microsoft Azure AI per PDF p.1)
- arXiv id + version read: 2305.03495v2 (PDF stamp "19 Oct 2023"; 12 pages)
- First date (v1) / latest version date: 2023-05-04 / 2023-10-19
- Venue/status: EMNLP 2023 main conference (Singapore, Dec 2023), pp.7957-7968, DOI 10.18653/v1/2023.emnlp-main.494. Sources: arXiv comment "EMNLP 2023"; ACL Anthology 2023.emnlp-main.494 page and .bib fetched 2026-10-11.
- Code URL + license + endpoint note: https://github.com/microsoft/LMOps/tree/main/prompt_optimization (footnote p.1); LMOps repo license MIT (GitHub API). Code hard-codes https://api.openai.com/v1/chat/completions and /completions with config.OPENAI_KEY (utils.py, grep of raw file), so OpenAI-compatible endpoints need a small code edit (no base_url flag seen). Task data in repo.
- Citation count: 877 (Semantic Scholar Graph API, arXiv:2305.03495, retrieved 2026-10-11)
- Editable surface: a single natural-language task prompt (with a fixed pair of few-shot examples held constant, p.5). Classification tasks only.
- Search method: Alg.1 beam search, beam width b=4, depth r=6 steps. Expand (Alg.2): sample minibatch of 64 training examples, collect errors, sample groups of 4 errors, LLM "gradient" prompt Delta produces m=4 textual criticisms per group, editing prompt delta produces q edited prompts per gradient (one edit per gradient), plus p=2 Monte-Carlo paraphrase successors per candidate; at most 8 successors per parent are sampled before selection (p.5). Select_b (Sec 2.2.2): treat selecting the top-b prompts as best-arm identification; options UCB (c=2.0), UCB-E, Successive Rejects (SR, with n_t formula, Eq.1 p.4), Successive Halving (SH). Reward of an arm pull = metric of the prompt on a random subset D_sample of training data. Final prompt = best in last beam. Archive = current beam only (no history of rejected candidates); no merge.
- Feedback signal: scalar F1 for selection; textual error-example criticism (the "gradient") for generation. No traces beyond (input, label, prediction).
- Task splits / held-out protocol: per task, 50 examples "for development" and 150 for test, rest of the data is train (p.5); the role of the 50 dev examples is not stated in the text read. Bandit selection samples from D_tr. Reported number = test F1 of "max-pooling over the final beam", i.e. the best test score among the final beam candidates (p.5), which is selection on test (optimistic) unless the beam is narrowed on dev; Fig.4 plots test F1 per step and the text notes peaking at ~3 steps. 3 trials averaged (12 replicates for the Appendix C variance study).
- Benchmarks and models: Jailbreak (new, 452 multilingual examples), Ethos (997), Liar (4000), Arabic Sarcasm (10,000); gpt-3.5-turbo (Jan 2023 version, Azure OpenAI; temp 0 for classification, 1.0 for generation); Table 3 compares GPT-3 davinci, text-davinci-003, ChatGPT, GPT-4 as backbone.
- Metrics: binary F1 on test (Fig.3); accuracy + SE in Appendix Table 5.
- Budget / cost reporting: query budget per prompt candidate (12 to 50 evaluations per candidate, Fig.3 x-axis; 25 and 50 in Table 2); matched query budgets across selection variants (B set to T*|Dsample|*n, p.6). No tokens/$/wall-clock; authors note runtime can exceed 1 hour even with a small query budget (Limitations p.9).
- Reported limitations: API rate limits and many API calls per round (gradient generation + full evaluation of selected beam candidates) can push runtime past 1 hour; only four classification tasks (p.9). Also "preliminary" framing in abstract.
- Key quantitative results: abstract: improves initial prompt by up to 31% (p.1); text: +3.9% over MC and +8.2% over RL baselines on average, +15.3% over p0, +15.2% over AutoGPT (Fig.3, values only in a figure, p.6). Table 1 (p.6) beam ablation F1: Jailbreak 0.80/0.82/0.85 (no iteration/greedy/beam), Liar 0.63/0.63/0.67, Sarcasm 0.87/0.85/0.88. Table 2 (p.7) bandit variants, Jailbreak/Liar F1: at 25 per prompt Unif 0.77/0.59, UCB 0.83/0.66, UCB-E 0.83/0.65, SR 0.81/0.62, SH 0.82/0.64; at 50 per prompt Unif 0.77/0.61, UCB 0.85/0.66, UCB-E 0.83/0.67, SR 0.82/0.66, SH 0.80/0.62. Table 3 (p.7) base models Sarcasm/Jailbreak: GPT-3 0.73/0.55, InstructGPT 0.83/0.75, ChatGPT 0.86/0.85, GPT-4 0.86/0.88. Table 5 (App. C p.11, budget 6/candidate, 12 reps) accuracy ProTeGi vs MC: Ethos 0.95 vs 0.94, Sarcasm 0.87 vs 0.86, Jailbreak 0.81 vs 0.76, Liar 0.64 vs 0.62.
- Candidate-evaluation allocation: THE bandit reference. Candidates on the beam are scored by sampled-subset evaluation allocated by UCB / UCB-E / Successive Rejects / Successive Halving; all beat uniform allocation (Table 2); UCB-style beat SR-style in practice (paper's own surprise; c=2.0 is a "relatively high" untuned exploration value), contrary to the theory-motivated expectation for best-arm identification. Differences between bandit variants are 0.01-0.05 F1 with test size 150 and 3 trials, so ranking among UCB/UCB-E/SR/SH is not statistically supported.
- Task selection / curriculum: random minibatches; errors only (failed examples) feed the gradient.
- Merge/composition: none (beam keeps parallel prompts; no crossover).
- Optimizer self-modification: none; the gradient/edit meta-prompts are static and the same for all tasks.
- Overlap with CapEvolve: textual-gradient from failures (our failure clusters), beam of candidates, budgeted subset evaluation by bandit (our posterior-based triage), minibatch error sampling.
- What it means for our claims: (a) "adaptive allocation of evaluation budget across candidates" is established prior art; our novelty must be allocation across tasks and across surfaces with Bayesian per-task evidence and a confirmation gate, not bandit selection per se. (b) A UCB/SR candidate-selection arm is a cheap control to include. (c) Do not reuse their test-max-pooling protocol. Reproduction feasibility: MED (small public repo; tasks are small; but gpt-3.5-turbo-0301-era model not available, endpoint is hard-coded).
- Discrepancies vs prior literature review / catalog: none found on venue (EMNLP 2023 verified) or on the "beam search and evaluation allocation" description. Not in the review: the UCB>SR result and the test-set max-pooling protocol; the review's ProTeGi paragraph says metrics "span task accuracy and domain-specific objectives", whereas the paper uses F1 on binary classification only. Catalog fields consistent.
