- Citation count: unavailable (Semantic Scholar 429)
- Editable surface: (a) a natural-language insight list injected into the task prompt (ADD/EDIT/UPVOTE/DOWNVOTE with importance counts; initial 2, removed at 0) and (b) a vector store of successful trajectories retrieved top-k by task similarity as few-shot examples (Faiss, all-mpnet-base-v2) (Sec 4.2, p.4). No code/tool edits.
- Search method: not a search over candidates. Three stages: gather experiences on train tasks with Reflexion retries (<=Z trials) (Alg. 1); extract insights with gpt-4-0613 over (success,fail) pairs for the same task and L-sized chunks of successes (Alg. 2); evaluate unseen tasks with a single attempt using insights + retrieved trajectories (Alg. 3). Memory = experience pool + insight list. No accept/reject gate on a val set; insights are all applied.
- Feedback signal: environment success/reward from training tasks (ground truth success flags), reflections; insights derived from success/failure comparison.
- Task splits / held-out protocol: four-fold validation: train on one half of the task set, evaluate on the other half, and vice versa (App D.1, p.14); eval sets are the ReAct/Reflexion sets: 100 HotpotQA dev (distractor) tasks, 134 ALFWorld, 100 WebShop. Hence each training half is ~50 HotpotQA / 67 ALFWorld / 50 WebShop tasks (my arithmetic from "one half"). Test split not sealed, and design decisions (e.g., LLM choice for insights, ablations) were made on the same sets -> tuned-on-eval risk. Mean +- standard error over folds.
- Benchmarks and models: HotpotQA, ALFWorld, WebShop, FEVER (transfer). Acting LLM gpt-3.5-turbo-0613, temperature 0; insight/reflection model gpt-4-0613 (p.7, 4).
- Metrics: success rate (EM for HotpotQA/FEVER), WebShop mean reward, ALFWorld per-task breakdown.
- Budget / cost reporting: no $ or total token cost for gathering/extraction; per-trajectory step/token statistics are tabulated in App (Table 6, p.35-38; not transcribed). Compute section lists only hardware (App C).
- Reported limitations: text-only observations; closed API LLMs; insights fit in context so retrieval of insights untested for lifelong use; prompting lacks theory (Sec 6, p.10).
- Key quantitative results: Table 3 (p.10): HotpotQA ReAct 28.0+-1.4 -> ExpeL 39.0+-1.7 (hand-crafted insights 32.0, gpt-3.5 insights 32.0); ALFWorld ReAct 40.0+-0.3 -> ExpeL 59.0+-0.3 (random in-context selection 42.5, reasoning-similarity 48.5). Insights-only vs retrieve-only: 36%/31% HotpotQA, 50%/55% ALFWorld (text p.7). Versus Reflexion: ExpeL 40% (R0 single attempt) ~ Reflexion 39% (R3) on HotpotQA; ALFWorld 59% vs 54% (text p.7-8). Transfer HotpotQA->FEVER (Table 1 p.9): Act 58, ReAct 63, ExpeL transfer w/o task demos 65, with demos 70. ExpeL+Reflexion on ALFWorld R0 59.0 -> R3 64.2 vs ReAct+Reflexion 40.3 -> 54.4 (Table 2, p.9). WebShop SR figures only in Fig 5 (not extractable) -> UNVERIFIED; WebShop reward ExpeL 0.701 vs ReAct 0.665 (Table 5, p.36).
- Candidate-evaluation allocation: none.
- Task selection / curriculum: training tasks processed in order with retries; pairs of same-task fail/success used for insight extraction (a contrastive selection of experiences, not of tasks).
- Merge/composition: insight list is merged online by LLM operators (ADD/EDIT/UP/DOWN) with importance counts (voting) -- a form of incremental merge; no verification of the merged list on held-out tasks except the final eval.
- Optimizer self-modification: none.
- Overlap with CapEvolve: closest "experience -> reusable artifact" precedent: contrastive success/failure pairs for the same task and cross-task insights (cf. our failure clusters and per-task fixed/broken impact), plus importance counts (akin to ACE counters). Single-attempt deployment matches our held-out evaluation regime better than Reflexion.
- What it means for our claims: cannot claim novelty for cross-task insight distillation with votes into a prompt, or for retrieval of successful trajectories as an editable surface. Need ExpeL-style insight-list baseline (no gate) vs our gated acceptance to show the gate matters; ExpeL's own protocol (4-fold on tiny task sets, SE over folds) lacks sealed test. Reproduction feasibility: medium-high (Apache-2.0, small; uses gpt-3.5-turbo-0613/gpt-4-0613 which are deprecated, so re-baselining on current models is required).
