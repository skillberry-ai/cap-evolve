- Search method: Not applicable. Construction pipeline (Alg.1 p.3): Stage 1 evaluate N1=6 real "anchor" LLMs with broadly separated accuracies on the FULL benchmark (binary item outcomes y_ij; continuous metrics discretized, App A.3). Stage 2 synthesize N2 virtual LLMs: enumerate k-subsets of the 6 anchors, majority vote per item, accept by rejection sampling only if the subset's accuracy falls in an empty one of M equal-width accuracy buckets (goal: near-uniform anchor accuracy spread); stop at N2 (they set N1=N2=6, p.8 Fig 3). Stage 3 fit IRT-style P(y_ij=1)=sigmoid(a_i^T b_j) by NLL (Eq.6-7), run K-means on item fingerprints b_j, take one representative per cluster with weight |C_l|/m; K set by compression ratio (App A.2).
- Feedback signal: binary item-level correctness of anchors (real + majority-vote pseudo logs); no labels beyond benchmark outcomes.
- Task splits / held-out protocol: here "held-out" = held-out LLMs, not held-out items. Test set H of mainstream LLMs excluded from construction (Eq.8-9 p.4); counts per benchmark in Table 4 p.15 (Appendix A.1): SWE-bench Verified 181, Multilingual 7, Pro 9, tau3 Retail/Airline/Telecom 7 each, Terminal-Bench 2.0 67, OSWorld Verified 44, Toolathlon 53 (extraction garbled; read as the number following the dataset link). Pipeline rerun with 100 random seeds, mean MAE/SP reported (p.4).
- Benchmarks and models: 100+ benchmarks (text, multimodal, 9 agent benchmarks listed in Table 2 p.5). Specific model lists "will be provided in the released code".
- Metrics: MAE of proxy vs full benchmark score; Spearman rank correlation (SP) of the model ranking over held-out LLMs; one-sided Spearman significance (p<0.01); build cost ($).
- Budget / cost reporting: construction cost reported per benchmark (Table 2 "Build Cost", e.g. LiveCodeBench v6 $243.9, LongBench v2 $670.7, tau3 Retail $34.2; $0.0 where public logs exist). Evaluation cost with proxy "20%-40% of original on average" (abstract/intro). Limitation (p.9): the 6 anchors must still be run on the full benchmark, "non-negligible for expensive settings such as agent benchmarks".
- Reported limitations (authors' own, p.9): approximation error; construction not free; completely removing performance records "unlikely to yield reliable compression"; 3 repeated runs of a >75%-reduced proxy can still be faster than one full run.
- Key quantitative results: Table 2 p.5 averages: small version -57.4% size, MAE 0.008, SP 0.99; tiny version -77.5% size, MAE 0.015, SP 0.98 (abstract: MAE 0.002-0.02, SP ~0.98). Agent rows (Table 2): SWE-bench Verified small 188/500 MAE 0.016 SP 0.99, tiny 125 MAE 0.020 SP 0.99; tau3 Retail small 86/114 (only -30%) SP 0.96, tiny 72 SP 0.93; Terminal-Bench 2.0 small 72/89 (-19.1%) MAE 0.009 SP 1.00, tiny 50 SP 0.99. Table 3 p.8 OOD extrapolation (proxy built from a 75% accuracy window, tested on LLMs outside it) mean MAE 0.0309 vs tinyBenchmarks 0.0381, SUBLIME 0.0336 (lower is better). Fig 1(b)/p.7: lower MAE than random subsampling (Welch p<0.001).
- Candidate-evaluation allocation: n/a as an optimizer, but it is a fixed representative-subset baseline: ONE static weighted subset per benchmark; every candidate model is evaluated on the same K items; score = sum_l w_l y_{i,s_l}. Weights are cluster sizes, not adaptive. No sequential screening, no confidence bounds, no per-candidate escalation.
- Task selection / curriculum: EXACT selection rule = one representative per K-means cluster in learned item-fingerprint space (fingerprints from IRT fit on 6 real + pseudo-anchor logs), with cluster-size weights. Theory (p.6): Thm 1: |mu_i - mu'_i| <= A*eps/4 (A = max fingerprint norm of LLMs, eps = max within-cluster fingerprint radius) under the IRT model; Thm 2: E[rho] >= 1 - 96 c^2 delta_w^2 - O(c delta_w / N) for N models with abilities drawn from a density bounded by c; bound tightest when anchor accuracies are uniform (Sec 5.3); assumes full-row-rank fingerprints and unidimensional monotone responses (App C, Assumptions 1-2). Guarantee is for ranking models whose accuracies are drawn from a spread distribution, not for resolving small deltas.

- Overlap with CapEvolve: relevant only for "cheap subset triage" of candidate agents: provides one concrete recipe (cluster items by learned response fingerprints, weight by cluster size) and fidelity metrics (MAE, Spearman over held-out systems).
- What it means for our claims: ZipBench shows rank preservation across DIFFERENT LLMs with wide accuracy spread (MAE ~0.01-0.02); candidate harness edits of one frozen model typically differ by a few points on small val sets, i.e. at or below the proxy MAE, so rank fidelity across base models does not transfer to near-tie candidates (my inference; the paper tests no such setting - its OOD test is still across LLMs, Table 3, MAE ~0.03). Its pipeline needs full-benchmark runs of >=6 anchor systems; with val sets of tens of tasks that cost equals just evaluating all candidates fully, so any subset-triage claim must count the calibration evaluations (matches review). Four of nine agent benchmarks have only 7-9 held-out models so SP is computed over very few points. If we use a fixed subset we should report false-negative rate for promote/reject decisions and total evaluations incl. calibration. Reproduction feasibility: high for the compression code (Apache-2.0, official repo), but low relevance to harness-variant ranking without new calibration experiments.
