- Editable surface: ONE compact skill document best_skill.md (300-2,000 tokens) via add/delete/replace (patch ops append/insert_after/replace/delete) or rewrite-from-suggestions mode; protected "slow-update" field; optimizer-side meta skill (not shipped). No tools/code/MCP, no multi-file package.
- Search method: single-incumbent hill-climb, no archive. Rollout batch (40) -> separate failure/success reflection minibatches (8) -> hierarchical merge of atomic edits -> LLM ranks and clips to edit budget L_t=4 (cosine to floor 2) -> candidate evaluated on selection split, accepted only if STRICTLY greater than current (ties rejected), best -> best_skill.md [Sec 3-4, App C]. 4 epochs. Rejected-edit buffer (epoch-local) fed back; epoch-wise slow/meta update compares previous-vs-current epoch on 20 sampled tasks, passes through same gate.
- Feedback signal: scalar score r∈[0,1] + full trajectories + verifier feedback; needs automatic verifiers (stated limitation).
- Task splits / held-out [Sec 3.1, 4, App C]: deterministic train/selection/test, split_seed=42, default 2:1:7; ALFWorld 39 train / 140 sel / 134 test; LiveMath 35 train items/epoch. Test "locked until final report"; selection split only gates edits. INTERNAL INCONSISTENCY: Table 2 caption says 4:1:5 split, App C says 2:1:7 for the same train-size ablation.
- Tuned on test? NOT stated that hyper-parameters were chosen on val. Tables 2-3 (sweeps/ablations, GPT-5.5) report what appear to be test-split numbers. The headline GPT-5.5 direct-chat cells coincide with the best sweep cells rather than the stated default (cosine, L=4: 87.1/77.5/61.3 in Tables 2-3): SearchQA 87.3 = Table 2(e) "constant" row; SpreadsheetBench 80.7 = Table 2(e) "constant" row; LiveMath 66.9 = Table 2(d) lr=8 row. This pattern suggests best-of-sweep reporting on test; UNVERIFIED (paper does not say). Treat headline as possibly optimistic. One run per cell, no variance/seeds reported.
- Benchmarks and models: SearchQA, SpreadsheetBench (version unspecified; multi-round, <=30 turns), OfficeQA (oracle parsed pages supplied, Fig 4 rule), DocVQA, LiveMathematicianBench, ALFWorld; GPT-5.5/5.4/5.4-mini/5.4-nano/5.2, Qwen3.5-4B, Qwen3.6-35B-A3B; harnesses: direct chat, Codex CLI, Claude Code CLI. Baselines: no skill, human, one-shot LLM, Trace2Skill, TextGrad, GEPA, EvoSkill (harness only; "–" where no aligned run).

- Reported limitations (App B): needs verifiers + held-out split; training cost; single skill not a library; learned heuristics may not transfer.
- Key quantitative results (Table 1, p.7): GPT-5.5 direct chat no-skill -> SkillOpt: SearchQA 77.7->87.3; SpreadsheetBench 41.8->80.7; OfficeQA 33.1->72.1; DocVQA 78.8->91.2; LiveMath 37.6->66.9; ALFWorld 83.6->95.5 (avg +23.5). Same table GEPA SpreadsheetBench 73.6, Trace2Skill 49.6, human skill 72.9. Codex GPT-5.5: Spreadsheet 27.5->85.0 (EvoSkill 67.5), OfficeQA 38.3->51.1 (EvoSkill 42.4). Claude Code GPT-5.5: Spreadsheet 22.1->80.4 (EvoSkill 75.0), OfficeQA 57.6->71.5 (EvoSkill 70.3). Transfer (Table 4): Codex-trained spreadsheet skill on Claude Code 22.1->81.8; GPT-5.4 spreadsheet skill to mini 36.1->45.5, nano 23.5->26.5. Target-matched optimizer recovers 56-74% of strong-optimizer gain (Table 5). 52/52 cells best-or-tied (self-reported). No SkillsBench.
- Candidate-evaluation allocation: every candidate evaluated on full selection split (size per benchmark not tabulated in text read); no triage.
- Task selection / curriculum: random rollout batches from train; success and failure analysts split; no curriculum.
- Merge/composition: LLM merge of per-minibatch edits (dedupe/conflict resolve); not separately verified except via the final gate.
- Optimizer self-modification: optimizer-side meta skill that accumulates helped/rejected edit patterns (prepended to optimizer prompts) -- prompt-level only.
- Overlap with CapEvolve: very high with hill-climb (bounded edit budget ~ our single large edit; held-out accept; rejected-edit buffer ~ LEDGER). CapEvolve already has a SkillOpt reimplementation.
- What it means for our claims: "propose-and-test with held-out gate", "negative-edit memory", "meta memory" are not novel. Differences to exploit only if measured: paired gate mean(delta)>k*SE (SkillOpt uses strict > on a raw mean), sealed test consumed once, multi-surface.
