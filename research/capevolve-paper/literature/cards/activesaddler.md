- Editable surface: whatever the underlying optimizer (AutoSaddler) edits: prompts, tool interfaces, runtime control logic (Sec 3, p.3). ActiveSaddler itself edits NOTHING in the harness; it only chooses which training scenarios generate feedback.
- Search method: wrapper around AutoSaddler (Park et al. 2026, a separate paper, not read). Optimizer per iteration: execute H_t on batch X_t (<=3 scenarios) -> diagnose and patch -> execute candidate H'_t on SAME batch -> if H'_t improves on the batch, additionally evaluate on D_dev -> reflect (fixed/regressed/still-failing/still-passing) -> update EvoDAG (node archive) -> EVOLVE next harness (Alg. 2, pp.16-18). Final = dev-best.
- Feedback signal: binary task outcomes + LLM-diagnosed failure root causes from traces (labels via benchmark graders).
- Task splits / held-out protocol: disjoint train/dev/test, OOD by task group. GAIA2 (split by Universe): train 75 (U29), dev 65 (U30), test 300 (U21 107, U22 112, U27 81). Terminal-Bench 2.0 (random partition): train 30, dev 19, test 40 (Table 3, p.15). Test reported over 3 test-time executions; test not used for selection.
- Benchmarks and models: GAIA2 (Froger et al. 2026), Terminal-Bench 2.0 (89 tasks); gpt-5.5 for task agent (medium) and optimizer sessions (xhigh) (Sec 5.1, p.7).
- Metrics: Pass@1 mean +- std over 3 test-time executions (std is over repeated test evals, not over optimization runs); dev accuracy vs cumulative rollouts; $ cost.
- Budget / cost reporting: yes. Shared rollout budget K = 10*(|Dtrain|+|Ddev|) = 1,400 rollouts (GAIA2) and 490 (TB2) for ALL methods, and ALL executions including optimizer candidate evaluation count (App A p.15). Dollar cost reported: ActiveSaddler reaches 58.5% dev on GAIA2 at $298 vs AutoSaddler $1,360; TB2 78.9% at $128 vs $220 (Sec 5.2 p.8; App F p.20-21); per-patch optimizer overhead $11.44 vs $7.87 (App F p.20).
- Reported limitations: research prototype; benchmark-only; no safety/reward-hacking detector (App L, p.37). No statistical-significance discussion; TB2 test is only 40 tasks.
- Key quantitative results: Table 1 (p.7): GAIA2 test Pass@1 (300 tasks) default 53.6, GEPA 54.2, Meta-Harness 54.2, AutoSaddler 55.4, +category-acc order 55.9, +scenario-acc order 55.7, ActiveSaddler 59.8+-1.0 (=> +4.4 over AutoSaddler). TB2 (40 tasks): Terminus2 64.2, Terminus-KIRA 69.2, AutoSaddler 72.5, ActiveSaddler 80.0+-2.5 (=> +7.5). Ablations (Table 1): category arms 56.8/69.2, scenario arms 56.2/73.3, w/o arm prioritizer 55.3/72.5, w/o exploration controller 55.3/71.7. Second independent GAIA2 run: ActiveSaddler 61.6 vs AutoSaddler run2 56.6 (Table 4, p.18). On GEPA: 54.2 -> 57.2 (App E). Non-LLM alternatives: EMA scoring 56.7, UCB-AIR controller 55.6 (Table 5, p.18).
- Candidate-evaluation allocation: NOT the paper's contribution; inherited from AutoSaddler and held fixed: a candidate is run on the same <=3-scenario batch, and only if it improves there is it evaluated on full D_dev (cheap triage then dev confirmation), Alg. 2 lines 31-32 (p.17). ActiveSaddler allocates which TRAINING evidence the optimizer sees, not which candidates get evaluated.
- Task selection / curriculum (exact mechanism): arms = LLM-extracted "failure patterns" (two-stage symptom extraction then normalization to existing/composed/new arms; each arm keeps its supporting-scenario set from D_train). Each iteration: (1) Exploration Controller = an LLM agent session making a binary DRAW (sample X_t without replacement from unseen pool U_t) vs PULL (use an arm) decision (Eq.11); (2) if PULL, Arm Prioritizer = LLM scores each arm phi in [0,1] from severity, fixability, breadth, side-effect risk, then samples a_t ~ Softmax(phi/tau), tau=0.15 (Eq.8-10, p.6; App A p.15); (3) X_t drawn from the arm's supporting scenarios, <=3 per iteration. After all training scenarios explored and every arm visited, earlier successes become eligible again (regression rediscovery). So it is a bandit-INSPIRED, LLM-scored stochastic curriculum, not UCB/Thompson with statistical posteriors; the count-based UCB-AIR controller and EMA scoring were worse (Table 5). Task selection is on the TRAINING (evidence-generation) side; they explicitly contrast Task-CoEvolve (selects validation tasks that discriminate candidates) and HarnessLens (verification tasks per modification) as evaluation-side methods (Sec 2, p.3; those two works not read).
- Merge/composition: none in ActiveSaddler (EvoDAG synthesis is inside AutoSaddler; merge verification not described in text read).
- Optimizer self-modification: none. Optimizer O and its candidate-evaluation procedure are held fixed (Sec 3 p.4).
- Overlap with CapEvolve: failure clusters -> targeted training evidence; revisit vs explore; rollout-budget-matched comparison with random/fixed order; dev-set final selection; regression rediscovery. CapEvolve agent-optimize's failure clusters + Bayesian per-task posteriors do similar prioritization but also allocate candidate evaluation.
- What it means for our claims: Unsafe: "first adaptive allocation of optimization effort across failure patterns/tasks" and "first to treat harness search as a bandit over failure clusters". Safe-ish: statistical (Bayesian posterior) per-task signals for candidate acceptance and merge decisions, subset triage for candidate evaluation (which ActiveSaddler leaves fixed), multi-surface edits. Required comparison: random/fixed order vs failure-cluster-prioritized task selection at equal rollout budget on our adapters (their Table 1 protocol; fixed random order baseline). Reproduction feasibility: medium (MIT code branch, but gpt-5.5 + Copilot SDK + GAIA2 simulators; ~$1-2k per run).
- Discrepancies vs prior literature review / catalog: Review says "test Pass@1 gains of 4.4 points on GAIA2 and 7.5 on Terminal-Bench 2.0 over the same optimizer with fixed scenario order": the baseline is AutoSaddler (random shuffled fixed order, 55.4 and 72.5), confirmed; TB2 test has only 40 tasks and GAIA2 gain uses one of two runs (second run +5.0 to +5.7). Review phrase "non-stationary bandit" is the authors' term but the selection is LLM-scored softmax, not a classical bandit algorithm; UCB-AIR variant did worse. Review asks "data to learn from vs measure with": answer = data to LEARN from (training-side evidence selection); candidate measurement is fixed.
