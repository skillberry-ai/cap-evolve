- Authors: Zekai Wang; Yingqiang Ge; Zekun Wang; Hai Wang; Yuhui Xu; Joshua Frandsen; Shancong Fu; Ashia C. Wilson; Chandan K. Reddy (arXiv API 2026-10-11; MIT, Amazon)

- Code URL + license + endpoint note: https://github.com/wzekai/VERSE (abstract p.1); MIT (GitHub license API). README: executor/optimizer "served locally with vLLM" (vLLM exposes OpenAI-compatible API, but whether the code calls it that way is UNVERIFIED; code not read). Paper says repo has configs, split task IDs, baseline reimplementations, selected harnesses (p.10).
- Citation count: unavailable (Semantic Scholar rate-limited 2026-10-11)
- Editable surface: executor harness (prompts + executable hooks; "harness edit space (executable hooks plus prompts)", App D.2 p.23) AND the optimizer's own harness g = prompts, skills, tools, hooks, notes (Sec 2.1 p.3). Not MCP descriptions or multi-file skill packages for the executor.
- Search method: HOST harness optimizer (Meta-Harness, AHE, Self-Harness, HarnessX; all REIMPLEMENTED by the authors under a shared protocol, App E) + VERSE add-ons. Per round (T=6 SWE-rebench, T=3 Terminal-Bench): 3 candidate executor harnesses generated by the optimizer (<=60 turns each), compared, best one smoke-checked, validated, archived; then optimizer self-update (<=30 turns) edits g (Alg. App B, pp.16-18; Sec 3.1 p.5). Archive of per-round harnesses h0..hT; final = better of the 2 lowest-val-loss archived harnesses after one more re-eval (App B p.17-18).
- Feedback signal: binary test pass/fail on SWE-style tasks; trajectories; validation summary (per-round val accuracy, IDs of up to 30 val tasks whose outcome changed and whether the change held on rerun; no task content) fed back to optimizer (Sec 2.2, p.4; App B p.17).
- Task splits / held-out protocol: disjoint train/val/test. SWE-rebench: 110 train + 50 val from 593 tasks (Jan 2025-Feb 2026 releases); in-dist test = 108 gradable tasks of March 2026 release; OOD test = 107 gradable tasks of July 2026 release (Go 21, Java 17, Python 20, Rust 25, TS 24) (Sec 2.2 p.3; App D.1 p.22). Terminal-Bench: train 104 TB1.x tasks, val 50 sampled from a 98-task pool, test = 89 TB2.x tasks (App D.1 p.23). Test never used for selection; authors acknowledge adaptive reuse of validation (bounded in App C.3.2).
- Benchmarks and models: SWE-rebench, Terminal-Bench (also closed-weight "small/mid-size tier" in App F). Main: optimizer Qwen3.8-Flash-Next (176B/6B active), executor Qwen3.8-27B via vLLM, low reasoning, greedy (App D.2 p.23; model names as printed, not independently checked). Observation 2 uses Qwen3-Coder-480B, DeepSeek V3.2, GLM-5, Mistral Large 3 executors.
- Metrics: avg@3 accuracy (% tasks resolved averaged over 3 test evaluations) +- SEM over the 3 test evaluations, NOT across evolution runs (Tables 1-3 are "one evolution run per row").
- Budget / cost reporting: yes, unusually explicit. Same rounds, 3 candidates/round, proposal-turn limit; NOT matched on total execution/token cost (App D.2 p.23). Table 4 (p.24): e.g. Meta-Harness 1,326 agent runs, 21.6 h; +VERSE w/ self-evolve 1,453 runs, 38.0 h; verification adds 27-104 agent runs (2-7%); VERSE runs 1.3-2.5x wall-clock. Optimizer tokens not logged (only turn counts).
- Reported limitations: no dedicated Limitations section found; stated caveats: self-evolution's incremental benefit varies across hosts; single-run rows; Terminal-Bench gains within noise (App F); safety discussion in Ethics (p.10).
- Key quantitative results: Table 1 (p.4) Meta-Harness host, in-dist test: blank 33.95; MH 39.20 (val-sel); self-evolve w/o verification 31.79 (no round beat round 0); simple verification only 39.81; both 41.05. Table 2 (p.8): Meta-Harness 39.20/OOD 28.66; +VERSE w/ self-evolve 42.28 in-dist, OOD 37.69 (abstract's 42.3 and 37.7; strongest baselines 39.2 and 29.3 [Self-Harness OOD 29.28]). VERSE w/ self-evolve > host in all 16 pairs, but w/o self-evolve falls below host in 8 of 16. Self-evolution raises val-selected accuracy over no-self-evolve in only 3 of 8 host x test-set cases (p.8). Ablation on AHE host (Table 3, p.9): full 37.96; w/o attribution+minimization 35.80; AHE alone 33.95. Appendix F Table 7 (p.27): 3-run means, SWE-rebench small/mid models: VERSE(HarnessX host) 32.82+-0.20 vs best baseline 30.56; Terminal-Bench 40.57+-0.45 vs best 37.83 (blank 37.08).
- Candidate-evaluation allocation: two-stage triage. (1) 3 candidates per round compared on a SHARED SUBSET of up to 12 TRAINING tasks by net tasks fixed (ties: more verification-confirmed passes) (App B p.17; D.2 p.23); (2) winner -> smoke check (1 train run) -> evaluated on full 50-task val; val changes rerun once, non-reproducing flips reverted to parent outcome; (3) at end top-2 val rounds re-evaluated, better kept. No bandit/racing/posterior; fixed schedule. How the <=12 subset is chosen: not specified in text read (UNVERIFIED).
- Task selection / curriculum: none beyond the optimizer's own choice of target failing tasks; ablations show random or fixed experiment (probe) schedules cost accuracy (App H, p.31; Fig 8). Verification-tool probes are on training tasks; budget 8 units/candidate, shared pool 24/round.
- Merge/composition: none. One chosen candidate per round replaces the parent; no merge of branches, no merge verification.
- WHAT "VERIFIED" MEANS: execution-based verification of draft EXECUTOR-HARNESS EDITS on TRAINING tasks BEFORE submission: `verification` (run draft on up to 3 target tasks; counts as fixed only if it passes twice), `replay` (re-run recorded failing trajectory), `perturbation` (remove/replace one step, replay), plus trace minimization (median failed trajectory 129 -> 8 steps, Sec 3.1 p.5; App I p.33) and a cross-round training audit (fixed/regressed tasks). Checks are advisory: "No check result blocks a submission" (App B p.17). Not a statistical gate, not merge verification. Figure 5 (p.9): only 17/170 draft evaluations confirmed a fix; 90% of predicted fixes still failed; 49% of rerun validation changes did not reproduce.
- Optimizer self-modification: YES. After each round the optimizer (<=30 turns) rewrites its own prompts, skills, tools, hooks, notes; self-written code loaded only after safety check + test run; verification-tool internals fixed (Sec 3.1 p.5; App B p.18). Evidence: with self-evolution but w/o verification Meta-Harness got worse (Table 1); audit of 51 self-built artifacts across 5 executors (Fig 3, p.5); theory (Thm 1-2) is bounds with assumptions, not a guarantee.
- Overlap with CapEvolve: closest on (a) disjoint train/val/test with sealed test, (b) val-selected incumbent from archive, (c) pre-submission execution checks and per-task fixed/broken tracking (our fixed/broken impact + protect-set), (d) budgeted 3-candidate/round subset triage then full val. Differs: executor surface is prompt+hooks only; no merge; no posterior/bandit allocation; optimizer self-evolves.
- What it means for our claims: Unsafe: "first verified self-improving/meta optimizer", "first self-modifying optimizer for harness search", "first sealed test + val selection for harness optimizers", "subset triage before full val" as novel per se. Safe(r): statistical paired gate k*SE; Bayesian per-task posteriors; merge of branches; MCP/tool-description surfaces; matched-search-cost reporting; pass^k. Required comparison: Meta-Harness/AHE hosts +VERSE on our benchmarks; or an ablation showing self-modification gives nothing without a verifier (their own Table 1 claim). Reproduction feasibility: medium (MIT, local vLLM, but 1,300-1,450 agent runs per round-set and large open models).
