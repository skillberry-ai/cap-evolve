- Editable surface: a workflow = Python code of LLM-invoking nodes (prompts only variable per node; model, temperature, output format fixed) + code-represented edges (control flow) + a predefined operator set (Generate, Format, Review&Revise, Ensemble, Test, Programmer, Custom) (Sec 3.2, p.5-6).
- Search method: MCTS variant; each tree node = a whole workflow. Loop: soft-mixed-probability selection P = lambda*uniform + (1-lambda)*softmax(alpha*(s_i - s_max)), alpha=0.4, lambda=0.2 over top-k + initial workflow (p.7, Eq 3); LLM expansion (Claude-3.5-Sonnet optimizer) with parent's tree-structured experience (all past edits + success/failure + prediction/expected logs); evaluation 5 runs on val; backpropagate experience; early stop if top-k (k=3) unchanged for n=5 rounds, max 20 rounds (p.7, Alg. p.19). Archive = the tree; merging none.
- Feedback signal: scalar score from executable evaluator on val + per-instance logs (prediction vs ground truth) given to the optimizer (p.7).
- Task splits / held-out protocol: random 20% val / 80% test, seed 42 (p.6); val further reduced to high-variance instances picked from 5 runs of the blank template (p.6). Full GSM8K/HumanEval/MBPP; 1,000 samples each for HotpotQA and DROP; 617 MATH lv5 problems (p.7-8). Test reported as mean of 3 runs (Table 1 caption). Internal inconsistency: Alg. in App A.6 (p.19) says "20% for validation, 80% for training" whereas main text says test.
- Benchmarks and models: HotpotQA, DROP, HumanEval, MBPP, GSM8K, MATH(lv5, 617). Optimizer Claude-3.5-Sonnet; executors GPT-4o-mini-0718 (main), DeepSeek-V2.5, Claude-3.5-Sonnet-0620, GPT-4o-0513 (p.8). ADAS baseline: 30 rounds, Claude-3.5-Sonnet optimizer, GPT-4o-mini executor.
- Metrics: solve rate, pass@1, F1; also inference cost ($) for pareto front (p.8).
- Budget / cost reporting: reports inference $ of FINAL workflows on test (Fig 4, App D p.30; e.g. AFlow(gpt-4o-mini)-with-DeepSeek matches GPT-4o IO at 4.55% of cost). Per-round cost listed in App C case tables. Total search cost / tokens not reported in main text (UNVERIFIED in appendix tables); no matched-search-budget comparison (ADAS given 30 rounds vs AFlow 20).
- Reported limitations: no dedicated limitations section found; Sec 3.2 states scope is reasoning tasks with numerical evaluation functions (p.6). Search space is simplified (model, temperature, format fixed).
- Key quantitative results (GPT-4o-mini, test, Table 1 p.8): AFlow avg 80.3 vs IO 72.8, CoT 74.7, CoT-SC 76.0, MedPrompt 75.3, MultiPersona 75.1, Self-Refine 70.7, ADAS 67.2. Per task AFlow: HotpotQA 73.5, DROP 80.6, HumanEval 94.7, MBPP 83.4, GSM8K 93.5, MATH 56.2. Abstract's "5.7% avg improvement over SOTA baselines" matches relative gain over best manual baseline CoT-SC (76.0->80.3 = +4.3 pts = +5.7% relative; my arithmetic). Text says +19.5% over ADAS (80.3 vs 67.2 relative, p.8). Transfer HumanEval (Table 2, p.9): AFlow 94.7/93.9/96.2/95.4 across 4 executors. Ablation GSM8K without operators 93.1 (p.9).
- Candidate-evaluation allocation: every candidate gets 5 full runs on the (variance-filtered) val set (p.7); no racing/bandit; high-variance instance filter is a one-time val-set reduction.
- Task selection / curriculum: val set filtered to instances with high score variance for the blank template (p.6) -- a static hard/uncertain-task selection, same spirit as our subset triage but fixed once, not adaptive.
- Merge/composition: none (tree edits only; one-step modification per round, Fig 6 case study p.9). Option to restart from blank template via selection.
- Optimizer self-modification: none.
- Overlap with CapEvolve: tree-structured experience reuse (per-parent history of edits and effects) resembles our LEDGER/JOURNAL and per-task fixed/broken impact; MCTS-style parent selection resembles a candidate DAG with selection probability. Surface differs (workflow code vs prompts/tools/skills).
- What it means for our claims: cannot claim first use of experience-conditioned tree search over code; cost-vs-quality "weaker model beats stronger" claim is already made. Baseline required: AFlow at matched optimizer-token budget on a shared adapter task; because val is 20% and there is no held-out sealed protocol, our sealed-test finalize is a contrast to emphasize. Reproduction feasibility: medium (MIT, OpenAI-compatible config; workflows are tied to their six benchmarks and operator set; search cost not reported so budget matching needs measurement).
