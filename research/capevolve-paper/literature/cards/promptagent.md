- Editable surface: a single zero-shot task prompt (the paper frames it as strategic planning over prompt states); BBH, biomedical and NLU tasks.
- Search method: MCTS over prompt states (Sec 3.2 pp.5-6, Alg.1, A.3 pp.16-17). State = prompt; action = error-feedback summary produced by the optimizer LLM (GPT-4) from errors the base LLM makes on a training batch (batch size 5); transition = optimizer rewrites the prompt given the action and the trajectory of ancestor prompts. 12 MCTS iterations; selection by UCT with c=2.5 (Eq.1); expansion samples expand_width training batches and num_samples new prompts each (Standard: width 3, 1 sample, depth 8; Wide: width 3, 2 samples, depth 6; Lite: width 3, 1 sample, depth 4); simulation = greedy rollout expanding the best child until terminal depth or early-stopping (reward below mean of parent and root, or above the max so far, after depth 2); back-propagation averages cumulative future rewards into Q (Eq.2). Output: highest-average-reward path, then highest-reward node on it. Archive = the full search tree; memory = tree statistics and ancestor prompt trajectory.
- Feedback signal: scalar reward = base-model metric on a held-out reward subset of train data (default size 150; 60-200); textual error feedback from the optimizer LLM over base-model errors (inputs, predictions, labels).
- Task splits / held-out protocol (Table 6 p.16, train/test): Penguins 70/79; Geometry 150/200; Epistemic 500/500; Object counting 300/500; Temporal 300/500; Causal judgement 90/100; NCBI 2000/940; Biosses 60/40; MedQA 2000/500; Subj 400/1000; TREC 400/500; CB 125/56. A reward subset is carved from train; test is used for reporting. Best of Standard/Wide/Lite is selected by reward (p.7). Test curves (Fig.4b) are plotted but selection is described as reward-based. Test sets of only 40-100 examples for 4 of 12 tasks (Biosses 40, CB 56, Penguins 79, Causal 100); no CIs or seeds reported in the tables read.
- Benchmarks and models: 12 tasks (6 BBH, NCBI, Biosses, MedQA, Subj, TREC, CB). Base LLM GPT-3.5 (temp 0), optimizer GPT-4 (temp 1.0); transfer to GPT-4 and PaLM 2 (chat-bison-001) base models (Table 3). Baselines: human prompts ZS/FS, CoT ZS/FS, GPT Agent (an AutoGPT-like plugin), APE (one iteration, 150 prompts explored).
- Metrics: accuracy; F1 for NCBI.
- Budget / cost reporting: explored-prompt counts, not $ or tokens: Greedy-S 34, Greedy-L 72, Beam 72, MC 72, APE 150 prompts (A.4 p.17, Fig.4a); PromptAgent's own count is shown only in Fig.4a ("tens of nodes", A.3). Search ablations hold the explored-prompt count equal (Table 4). No tokens, $ or wall-clock in the paper.
- Reported limitations: no limitations section in the PDF (searched). Authors note computation budget limited the search ablation to a subset of tasks (p.9).
- Key quantitative results: Table 1 (p.7) BBH avg: Human ZS 0.513, CoT 0.707, APE 0.690, PromptAgent 0.802 (5 of 6 tasks, CoT wins Object Counting 0.960 vs 0.860). Table 2 (p.8): domain avg PromptAgent 0.655 vs APE 0.582; general NLU avg 0.868 vs APE 0.778 (NCBI F1 0.645 vs 0.576; CB 0.911 vs 0.804). Table 3 (p.9) transfer average over 12 tasks: GPT-3.5 Human 0.552 / APE 0.685 / ours 0.776; GPT-4 0.759 / 0.762 / 0.839; PaLM 2 0.392 / 0.381 / 0.441. Table 4 (p.9) search ablation (5 tasks): MC 0.635, Beam 0.697, Greedy 0.698, MCTS 0.754 (avg); relative +5.6% over best baseline. Internal inconsistency: Table 3 GPT-3.5 Penguins APE 0.747 / ours 0.797 vs Table 1 APE 0.797 / ours 0.873 (other tasks match; Table 3 average 0.776 matches the 0.797 value), p.7 vs p.9.
- Candidate-evaluation allocation: every generated node is evaluated on the whole reward subset (~150 examples); UCT allocates which node to expand next (tree-level exploration), not evaluation samples; early stopping prunes rollouts using reward thresholds.
- Task selection / curriculum: expansion draws random training batches and loops until a batch contains an error (A.3 p.16), i.e. error-focused sampling by construction.
- Merge/composition: none; the trajectory of ancestor prompts is shown to the optimizer, so later states accumulate earlier lessons, but branches are not merged.
- Optimizer self-modification: none (meta-prompts fixed).
- Overlap with CapEvolve: tree/DAG of candidates with reward statistics (our candidate DAG), failure-clustered/error-batch edit proposals, path trajectory memory, early stopping.
- What it means for our claims: (a) tree search over prompt edits with held-out reward is established; our DAG claim must lean on multi-surface edits, merges, per-task posterior and honest sealed test. (b) Its reward subset (<=200) is also the selection set; small test sets (40-100) mean its +5.6% search-ablation margin is within noise unless seeds are given. (c) MCTS node budgets (Greedy 34/72 prompts) are the right matched-budget unit for a tree-search arm. Reproduction feasibility: MED-HIGH (Apache-2.0, configs for tasks, small datasets; GPT-3.5/GPT-4 versions have changed).
