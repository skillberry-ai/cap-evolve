# WikiSkill
- Exact title: WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution
- Authors: Liyan Tang, Cyrus Rashtchian, Chun-Sung Ferng, Andrew Tomkins, Da-Cheng Juan, Tu Vu (arXiv API; Google Research / Virginia Tech)
- arXiv id + version read: 2608.27454v1 (PDF stamp 27 Aug 2026; header date 2026-08-28)
- First date / latest: 2026-08-27 / 2026-08-27 (arXiv API; no comment/journal_ref)
- Venue/status: preprint. OpenReview lists an "ICLR 2027 Conference Submission" (eENzccuqfn) = under review, not accepted. Acceptance not verified.
- Code URL + license: no official code in paper or catalog (catalog code_url empty). GitHub search finds only third-party reimplementations (e.g. kenhuangus/wikiskill, Stahl-G/wikiskill); these are NOT official and not evaluated. License n/a.
- Citation count: unavailable
- Editable surface: skills/ directory (SKILL.md + PURPOSE.md per skill, mapping to motivating wiki patterns). A persistent optimizer-side wiki (raw/ immutable traces, wiki/ patterns/*.md, index.md, logs.md, skill-impact.md) is maintained but NOT shipped to the inference agent. Full skill text injected in system prompt (no retrieval/trigger; Limitations).
- Search method: single-lineage greedy with rollback. Per iteration: full training split rolled out (B=N_train); Wiki Maintainer (1 call) consolidates <=8 sampled traces (<=5 fail, <=3 pass, logs capped 15k chars) into wiki patterns; Skill Proposer (ReAct, ~10-20 turns, reads wiki index + skill-impact tracker + raw traces on demand) emits ONE atomic proposal targeting a single skill (create or patch); validation gate: accept iff val score > R_best (strict), else roll back skills but keep wiki; early stop if R_best=1.0 [Alg 1 p.19]. Number of iterations K not stated in the text read (accepted-update stats cover Iter 0-7 => likely 8; UNVERIFIED). Memory: wiki (patterns, evolution log, skill-impact audit of past diffs + accept/reject).
- Feedback signal: scalar task score + full traces + ground-truth answers shown to proposer.
- Task splits / held-out [App B Table 6 p.20]: train/val/test: LiveMath 35/18/124; SealQA (July 2026 version) 16/10/85; SpreadSheet 80/40/280; OfficeQA 50/24/172; ALFWorld 39/18/134. "Strictly matched with prior work (EvoSkill, SkillOpt)". Test disjoint, not used for selection; 3 independent evolution runs, mean test score, paired bootstrap (1,000 it., p<0.05). Not tuned on test as far as stated. Gating noise from tiny val sets acknowledged. Gemini-3.5-Flash on ALFWorld hits 100% val => no evolution (85.9 for all methods).
- Benchmarks and models: LiveMathematicianBench, SealQA, SpreadsheetBench, OfficeQA (agent given pre-parsed ORACLE reference pages, following SkillOpt), ALFWorld. Qwen-3.5-4B/9B, Qwen-3.6-27B, Gemma-4-31B-It (vLLM), Gemini-3.5-Flash. Baselines Trace2Skill, EvoSkill, SkillOpt re-run by authors (all from empty skill set); GEPA deliberately omitted.
- Metrics: accuracy per benchmark and 5-benchmark average.
- Budget / cost reporting: no tokens/$/wall-clock/rollouts. Only an optimizer-API-call complexity analysis (App D.2, Table 7): WikiSkill (1+T_ReAct)N/B with B=N => 1+T (10<=T<=20) calls/iteration; EvoSkill 2N/B; SkillOpt K_opt~6-8 per step; Trace2Skill >=N. Concedes WikiSkill "may incur higher inference cost on some datasets". No matched-budget comparison.
- Reported limitations: no retrieval/triggering; strict gating excludes neutral steps; no wiki pruning; no very-long-horizon tasks.
- Key quantitative results (Table 1 p.8; test; mean of 3 runs; No skill / Trace2Skill / EvoSkill / SkillOpt / WikiSkill): SpreadSheet Gemma-4-31B 48.3 / 58.5 / 56.4 / 63.1 / 68.0; Qwen-3.6-27B 40.8 / 53.3 / 59.5 / 53.2 / 81.7; Gemini-3.5-Flash 50.5 / 56.0 / 55.4 / 66.1 / 76.6; Qwen-3.5-9B 24.3 / 26.5 / 35.4 / 29.0 / 33.6 (EvoSkill best); Qwen-3.5-4B 14.6/17.5/18.6/14.0/21.1. OfficeQA (oracle pages): Qwen-3.6-27B 42.1 / 54.3 / 52.5 / 54.8 / 53.7 (WikiSkill NOT best); Gemini 48.6/50.0/51.2/49.8/60.7; Qwen-3.5-4B 30.2/31.0/29.5/34.5/28.5 (below no-skill). 5-benchmark avg: 4B 26.2/32.1/33.7/35.2/38.5; 9B 29.9/36.7/42.3/40.2/47.4; 27B 39.4/47.3/53.3/50.7/63.3; Gemma 41.3/45.8/43.4/49.1/54.9; Gemini 49.5/55.6/56.1/55.9/68.1. Ablation (Table 3, Gemini): proposer without wiki avg 48.7 vs 63.7 with wiki. No SkillsBench.
- Candidate-evaluation allocation: one full val evaluation per proposal (10-40 tasks); no triage.
- Task selection / curriculum: whole train set each iteration; stratified trace sampling for the maintainer.
- Merge/composition: none (single skill set); cross-model skill transfer tested (Table 2).
- Optimizer self-modification: the wiki is a self-written persistent knowledge store for the optimizer (prompt/knowledge level, not code); skill-impact.md is programmatically appended by the harness.
- Overlap with CapEvolve: medium-high on memory: our LEDGER/JOURNAL/PROCESS files ~ wiki logs.md + skill-impact.md; gate = single-lineage val gate. CapEvolve differs by paired-gate rule and cost-aware agent mode.
- What it means for our claims: "persistent optimizer memory improves search" is claimed by WikiSkill with an ablation (+15.0 avg on Gemini); we need memory-on/off ablation before claiming memory files help. Baseline numbers come from authors' own reruns on a small-val protocol; not comparable to our setup. Reproduction: LOW-MED (no official code; reimplementation from Alg 1 + prompts in App E feasible).
