- Editable surface: multi-file skill PACKAGE (SKILL.md + executable scripts + reference docs) generated per task by the agent using a meta-skill (Anthropic skill-creator); plus an auxiliary surrogate-verifier test script (evolve-time only, not deployed).
- Search method (Alg 1 p.5): per-task generate-verify-refine, no population/archive/merge. Generator keeps a persistent conversation context C; independent-LLM Surrogate Verifier writes deterministic assertions V(j) from instruction I, observable inputs D (incl. background knowledge B) and produced artifacts; if surrogate reward <1 the diagnostics are appended and the skill revised (V fixed); when surrogate =1 the GROUND-TRUTH ORACLE (the task's hidden verifier) re-executes the skill in a fresh environment and returns only a pass/fail bit; if fail, verifier escalates tests; early exit on oracle=1, else best-oracle-score snapshot after K=5 oracle rounds / M=15 surrogate retries / context cap 0.7.
- Feedback signal: surrogate textual diagnostics (per-assertion results, root cause, suggestions) + opaque binary oracle bit from the real hidden tests of the SAME task.
- Task splits / held-out protocol: NONE. 85 SkillsBench tasks (87 minus scheduling-email-assistant and mhc-layer-impl, App B p.15); skills are evolved per task and evaluated on the same tasks, with the task's own grading verifier supplying the oracle bit during evolution and the early-exit/best-snapshot selection. Hence this is within-task, oracle-selected (tuned on the evaluation verifier), not train->test generalisation. Information isolation only withholds test CONTENT. The generator also receives task-relevant background knowledge B at init (+11.8 pts alone: 30.6->42.4). Whether evolution is repeated in each of the 5 evaluation runs is not stated (UNVERIFIED).
- Benchmarks and models: SkillsBench (Li et al. 2026c), 85 tasks / 11 domains; Claude Opus 4.6 (Claude Code), GPT-5.2 (Codex); transfer of Opus-evolved skills to GPT-5.2, Claude Sonnet 4.5, Haiku 4.5, Qwen3-Coder-480B, DeepSeek-V3-671B, Mistral Large 3-675B (Terminus-2 harness for four).
- Metrics: pass rate (task reward = 1.0 only), mean ± SD over 5 runs (primary), 3 runs (transfer); ablations single run.
- Budget / cost reporting: no tokens/$/GPU. Only: K=5 oracle rounds, M=15 surrogate retries, evolution timeout 5x (effective 3000 s/task), 4 workers; eval timeout 7200 s/task; mean 4.1 verification cycles and 2.4 oracle rounds per task (App B). No matched-budget baselines (Skill-Creator baseline runs >=3 self-iterations).
- Reported limitations: depends on task-relevant background knowledge at init; open-world evolution is future work.
- Key quantitative results: Fig 4 / Sec 4.2 (p.8), Opus 4.6 + Claude Code: CoEvoSkills 71.1%; no-skill 30.6; human-curated 53.5; Skill-Creator 34.1; self-generated 32.0 (±3.1); CoT-guided 30.7 (±5.2). GPT-5.2 + Codex: 69.8 vs 29.6 (Table 3). Transfer from Opus skills (Table 3): GPT-5.2 65.0 (no skill 29.6), Sonnet 4.5 63.1 (20.0), Haiku 4.5 54.5 (10.4), Qwen3-Coder 50.8 (8.4), DeepSeek-V3 48.8 (13.0), Mistral Large 3 43.1 (4.9). Sec 4.5 p.10 / Fig 2: pass rate in-loop 44% at round 2, 63% at round 3, converging at 75% by round 5 (final reported 71.1% is lower than the in-loop 75%; the two are different measurements). Ablation (Table A1, single run): w/o surrogate verifier 41.1; context only 42.4. 10 of 85 tasks never reached a perfect oracle score. No SpreadsheetBench/OfficeQA.
- Candidate-evaluation allocation: two-tier: cheap surrogate checks first (~40% of cycles resolved by surrogate alone), expensive oracle only when surrogate passes (<=5 per task). A task-level cascade, analogous to subset triage.
- Task selection / curriculum: none across tasks (independent per-task runs).
- Merge/composition: none.
- Optimizer self-modification: the verifier's test suite co-evolves (escalates) with the skill; no change to the optimizer prompts/code.
- Overlap with CapEvolve: medium. Multi-file skill packages and a SkillsBench lane; surrogate-then-oracle = cheap triage before full confirmation. Different regime: task-conditioned, oracle-in-loop.
- What it means for our claims: the 71.1% SkillsBench figure is a within-task oracle-selected result; it must not be compared as a leaderboard number with any train/val/test or common-skill result (including our 71.3% mixed val/test cut), and the review's misattribution to EvoSkill must be corrected wherever quoted. If we report a per-task adaptation arm it is the comparable protocol and should be labelled. We cannot claim others "tune on test" without citing this precisely: CoEvoSkills uses the test verifier's binary outcome as the stopping/selection signal. Reproduction: MED (Apache-2.0, official code, but needs SkillsBench Docker tasks, Claude Code/Codex, 5 oracle rounds x 85 tasks).
- Discrepancies vs prior review/catalog: review figures (71.1 vs 30.6, five runs, COLM 2026, transfer) CONFIRMED and COLM acceptance verified. SkillsBench evaluated on 85 tasks (not 87). Fig 2 shows 75% at round 5 vs 71.1% final. Catalog author list has two blanks (parsing).
