# EvoPrompt
- Exact title: EvoPrompt: Connecting Large Language Models with Evolutionary Algorithms Yields Powerful Prompt Optimizers. NB: arXiv API title is "EvoPrompt: Connecting LLMs with Evolutionary Algorithms Yields Powerful Prompt Optimizers"; OpenReview ICLR 2024 note title is "Connecting Large Language Models with Evolutionary Algorithms Yields Powerful Prompt Optimizers". Use the arXiv wording unless citing the proceedings.
- Authors: Qingyan Guo, Rui Wang, Junliang Guo, Bei Li, Kaitao Song, Xu Tan, Guoqing Liu, Jiang Bian, Yujiu Yang (arXiv API; Tsinghua + Microsoft Research per PDF p.1; first two equal contribution)
- arXiv id + version read: 2309.08532v3 (catalog downloaded_version v3; PDF header "Published as a conference paper at ICLR 2024"; 24 pages)
- First date (v1) / latest version date: 2023-09-15 / 2025-05-01 (v3)
- Venue/status: ICLR 2024 poster (main conference). Sources: arXiv comment "International Conference on Learning Representations (ICLR) 2024"; PDF p.1 header; OpenReview note ZG3RaNIsO8 venue "ICLR 2024 poster" (API search 2026-10-11).
- Code URL + license + endpoint note: https://github.com/beeevita/EvoPrompt (PDF abstract); MIT (GitHub API). README: requires an OpenAI API key and settings in auth.yaml (README grep); I did not read the code for base_url support (unverified for OpenAI-compatible servers).
- Citation count: 231 (Semantic Scholar Graph API, arXiv:2309.08532, retrieved 2026-10-11)
- Editable surface: a single discrete natural-language task prompt (instruction).
- Search method: Alg.1 (p.3). Population of N prompts (init from manual prompts plus LLM paraphrases, App B), T iterations. Two instantiations with an LLM executing the operators from a one-shot example of the algorithm: GA (roulette-wheel selection of two parents by dev score, LLM crossover then mutation, new N prompts merged with the old population and top-N kept) and DE (for each prompt: find differing parts of two random prompts, mutate only the differing parts, combine with the current best prompt as Prompt 3, then crossover with the basic prompt; keep the better of parent/child, population size constant). Archive = the population; no lineage tree, no failure-based edits (the LLM sees only prompts, not errors or scores).
- Feedback signal: scalar dev-set score only (accuracy / ROUGE / SARI).
- Task splits / held-out protocol: classification: dev set 200, full test sets (Table 7 p.16: SST-2 1,821; CR 2,000; MR 2,000; SST-5 2,210; AG's News 7,600; TREC 500; Subj 2,000); generation dev 100 (SAMSum test 819, ASSET test 359); BBH: dev 50 "sampled from the test set" (p.8, Table 11 p.19), so the dev set overlaps the evaluation data there. Best prompt by dev score is evaluated on test (p.6). Alpaca results are mean(std) over 3 seeds; GPT-3.5 results are a single seed "due to budget limitation" (p.6).
- Benchmarks and models: 31 datasets: 7 classification (SST-2, CR, MR, SST-5, AG's News, TREC, Subj), SAMSum, ASSET, 22 BBH tasks. Task LMs: Alpaca-7b and GPT-3.5 (text-davinci-003 per p.6; evolver GPT-3.5, temp 0.5, top-p 0.95; exact evolver checkpoint not stated in text read).
- Metrics: accuracy, ROUGE-1/2/L, SARI, BBH accuracy normalized against "Let's think step by step" 3-shot CoT.
- Budget / cost reporting: Table 11 (p.19): population 10, steps 10, dev 200 (classification, Alpaca), 100 (generation), 50 (BBH, 3-shot). That implies about 10 initial + 10x10 child evaluations = ~110 prompt evaluations x |dev| per run (my arithmetic). Population-size study (Fig.6, p.19): population 4-12. Same-size populations for APE baseline (p.6). No $ / tokens / wall-clock.
- Reported limitations: no limitations section in the PDF. Appendix F lists future work (other EAs, more DE variants); text notes single seed on GPT-3.5 for budget (p.6).
- Key quantitative results: Table 1 (p.7) Alpaca-7b accuracy avg over 7 datasets: manual instructions 71.07, APE 73.80, EvoPrompt GA 76.25, DE 77.05; per dataset e.g. Subj: MI 49.75, APE 64.18, GA 70.55, DE 75.55; SST-5 MI 42.90, GA 49.91, DE 49.89. Table 2 (p.7) SAMSum ROUGE-1 GPT-3.5: MI 43.95, APE 43.43, GA 45.22, DE 46.49; Alpaca: MI 35.92, DE 39.46. Table 3 ASSET SARI GPT-3.5: MI 43.80, APE 46.71, GA 47.36, DE 47.40. BBH (Fig.3 p.8, text): improvement on all 22 tasks; DE up to +25% (avg +3.5%), GA up to +15% (avg +2.5%). Ablations: GA selection roulette 48.17 > tournament 48.00 > random 47.50 (Table 4); DE best-as-Prompt-3 + diff-only mutation 75.55 vs 69.87/69.82/69.07 on Subj (Table 5).
- Candidate-evaluation allocation: every child fully evaluated on the dev set (200/100/50 examples); no racing or bandits.
- Task selection / curriculum: none (fixed dev sample).
- Merge/composition: crossover of two prompts by the LLM (GA) / DE-style combination with the best prompt; children are not verified beyond dev-score survival.
- Optimizer self-modification: none (operators are fixed templates).
- Overlap with CapEvolve: population-style multi-candidate search over prompt text and "keep the better of parent/child" rule.
- What it means for our claims: (a) "multiple candidates and crossover of prompts" are not new; the useful distinction is that EvoPrompt's operators are blind to failures and use only a score. (b) Population size is not a matched optimization budget; compare at equal total evaluations. (c) BBH dev drawn from test: do not cite its BBH numbers as clean held-out evidence. (d) OPRO (Fig.12) reports EvoPrompt GA/DE degrading on GSM8K from generic seeds, a counterpoint to EvoPrompt's gains. Reproduction feasibility: MED-HIGH (MIT repo, small datasets; text-davinci-003/Alpaca-7b era models differ).
- Discrepancies vs prior literature review / catalog: none found on venue (ICLR 2024 poster verified) or description. Notes: the review says "across language tasks" which is right; it does not flag that BBH dev examples were sampled from the test set, that GPT-3.5 results are single-seed, and the arXiv/proceedings title wording differs.
