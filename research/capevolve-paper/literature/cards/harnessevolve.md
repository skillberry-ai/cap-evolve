- Editable surface: whole harness: prompts, skill directories (skill.md, reference files, Python scripts), AGENTS.md/SOUL.md, tool descriptions/arguments, execution-logic code (Fig 3 p.14; Sec 4.1 p.7). Contrast: baselines GEPA (prompt), ACE (context), SkillOpt (skill.md only).
- Search method: batch-driven loop with 4 decoupled LLM agents (execute / evaluate / optimize / gate). Epoch: permute T_train, mini-batches of b=40; per batch: run, collect failures, optimizer clusters errors, proposes edits, quality gate, performance gate; accepted candidate becomes current and is stored in a snapshot pool V. Epoch end: all snapshots evaluated on T_val, best becomes A*. Up to E=20 epochs, early stop on batch patience P_batch=10 and epoch patience P_ep=5 (Alg.2 p.15, Sec 3.5-4.1). Single incumbent lineage + snapshot pool (no branching).
- Feedback signal: ground-truth answers. Reference trajectories are produced by re-running the execution agent WITH the ground-truth answer (up to T_att=5 attempts, verified by an evaluation agent as non-shortcut) and compared to failed trajectories to find the first divergence step (Sec 3.2-3.4 p.5). Requires labelled answers on all training tasks; tasks without verified reference fall back to failure-only analysis.
- Task splits / held-out protocol: T_train / T_val / T_test with "the same training, validation, and test split on each dataset" for all methods (p.7). SIZES NOT REPORTED in the PDF text read (UNVERIFIED which sizes); final A* evaluated once on T_test. Number of runs/seeds not reported; no CIs.
- Benchmarks and models: SearchQA, OfficeQA, SpreadsheetBench (open), CloudCoreNetwork-QA and Wireless-QA (in-house, not obtainable). Qwen3.6-27B (domain post-trained) and DeepSeek-V4-Flash; frameworks LAMAgent (in-house) and OpenClaw; transfer to Hermes, OpenCode, LAMAgent, DeepSeek Harness (Table 3).
- Metrics: accuracy (%).
- Budget / cost reporting: NONE (no rollouts, tokens, $ or wall-clock for search; no matched-budget comparison with GEPA/ACE/SkillOpt, only "identical environmental constraints and an initial harness", p.7).
- Reported limitations (authors' own): none found - the paper has no limitations section in the text read.
- Key quantitative results: Table 1 p.7 CloudCoreNetwork-QA Qwen/DeepSeek: base 43.4/47.5, GEPA 65.3/57.6, ACE 59.3/64.6, SkillOpt 61.9/65.3, HarnessEvolve 86.9/85.9; Wireless-QA Qwen/DeepSeek: base 79.0/85.9, best baseline 89.0/90.1 vs 89.7/92.8. Table 2 p.8: SearchQA 92.9 (base 86.5; ACE 90.0), OfficeQA 70.9 (base 62.8; ACE 68.9), SpreadsheetBench 76.4 (base 44.3; SkillOpt 74.6). Table 4 p.9 ablation (CloudCore, Qwen): full 86.9; w/o reference trajectory 57.8; w/o error clustering 68.6; w/o quality gate 80.1. Table 3 p.8: skills transferred to 4 other frameworks, e.g. OpenCode SpreadsheetBench 57.5 -> 87.9.
- Candidate-evaluation allocation: sequential gated acceptance, no triage. Each candidate is evaluated on the current mini-batch B_j (b=40) AND the R=2 most recent mini-batches; accept iff Acc(cand,B_j) - Acc(cur,B_j) >= delta (delta=0.0) and max over recent batches of drop <= epsilon (0.025) (Eq.1 p.6). So batch-level pair comparison on 40 tasks with zero improvement margin (noisy; 1 task = 0.025 = exactly epsilon). Snapshot pool then re-evaluated in full on T_val at epoch end and best chosen -> two-tier: cheap batch gate, full-val selection. Consecutive rejections count toward patience.
- Task selection / curriculum: random permutation of train set each epoch; replay buffer of last R=2 batches as regression guard; no difficulty-based selection.
- Merge/composition (verified?): none.
- Optimizer self-modification: none; optimizer, gate and evaluator agents are fixed and decoupled from the execution agent ("auditable, cannot be gamed by the execution agent", p.2).
- Overlap with CapEvolve: close mechanically: failure clustering, per-batch paired accept test with a regression (protect) buffer, quality gate against leakage/prompt bloat, held-out snapshot selection, whole-skill-package edits including scripts and tool descriptions.
- What it means for our claims: mechanism-level novelty of "gated paired acceptance + protect set + failure clusters" is already published; our contribution must rest on calibrated statistics (k*SE gate vs their delta=0 / epsilon=0.025 fixed thresholds), sealed test consumption, and cost-aware allocation. A fair comparison requires giving CapEvolve the same ground-truth answers (reference trajectories use labels; label-free feedback is not equivalent). Their large gains (+21.6 pts on in-house data) rest on non-public datasets, unreported split sizes and unreported search cost, so they cannot serve as a quantitative anchor. Reproduction feasibility: low (no code, in-house datasets, split sizes missing; SearchQA/OfficeQA/SpreadsheetBench could be reproduced only in spirit).
