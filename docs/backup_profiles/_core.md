# Backup profiles: values shared by every benchmark (from core)

Every profile in this folder builds on these values. A profile value written "as `_core.md`" is taken from here. Format: `docs/FULL_BACKUP.md` Appendix B.

| Key | Value |
|---|---|
| Bench names | not applicable: set by each profile |
| Code | core: `core/cap_evolve/` (`rundir.py`, `harness.py`, `types.py`, `splits.py`, `optimizer_cost.py`); optimizer registry `skills/optimizers/registry.yaml`; CI harness `ci/benchmarks/lib/run_suite.sh`, `ci/benchmarks/lib/ci_setup.sh`, workflow `.github/workflows/benchmarks.yml` |
| Reward | `Score.reward` in [0, 1], the mean over `trial_rewards`; `final.json` also holds `pass_k` and `pass_at_k`. Success and group metric: set by each profile |
| Infra rule | core drops errored trials from the mean by default (`errored_trial_policy: drop`, `harness.py`); flags `raw.errored`, `errored_trials`, `valid_trials`, `metadata.error_kind` |
| Telemetry | `Rollout.tokens` is one total (no prompt/completion split); no per-episode latency, steps or termination in core; per-evaluation `seconds` in `evaluate` events; per-step `optimizer_seconds`, `runner_seconds`, `opt_cost_usd`, `opt_tokens` in `step` events |
| Cost | agent: `Rollout.cost_usd` (default `0.0`, so `zero_means: unknown` unless the profile says otherwise); user simulator: `state.json` `spent.usersim_usd`, a list-price estimate **already inside** `spent.usd`; optimizer: `spent.optimizer_usd`/`optimizer_tokens`, from the CLI's `total_cost_usd` or from transcript tokens at list price (`optimizer_cost.py`, `optimizer_cost_seen.json`) |
| Splits | `<run>/splits.json` (`test_used`); without a split file, a seeded 0.5 / 0.25 / 0.25 shuffle (seed 0, `splits.py`); CI tiers without `split_ids.json`: train = val = test (no holdout); pooled mode: the full partition in the sealed dir (`splits_full.json`) |
| Baselines | the seed (`baseline.json`) |
| Capability | set by each profile (`capabilities` in `capevolve*.yaml`) |
| Gold | false-positive grep term `ao_focus_canary` (agent-optimize); the optimizer receives the best candidate's rollout files in `<run>/work/<cand>/trajectories/`, so gold inside rollout metadata reaches it |
| Isolation | none by default: `claude -p … --permission-mode acceptEdits --allowedTools Bash` (`registry.yaml`) |
| Agent evidence | set by each profile |
| Models as used | optimizer: the CLI transcripts (per model and role); agent: set by each profile |
| External state | **run dirs:** `<project>/.capevolve*/run_<name>/` (`state.json`, `splits.json`, `events.jsonl`, `graph.jsonl`, `eval_index.jsonl`, `history.jsonl`, `rejected.jsonl`, `baseline.json`, `final.json`, `candidates/`, `rollouts/<split>/`, `work/`, `report.md`, `dashboard.html`, `optimizer_sessions.json`, `optimizer_cost_seen.json`) and `<project>/.capevolve*/project/`; **sealed:** `<project>.sealed/<run>/` (`splits_full.json`, `rollouts/confirm/`, `private/`) or `$CAPEVOLVE_SEALED_DIR`; **optimizer sessions:** `~/.claude/projects/<slug of <run>/work/cand_NNNN>/*.jsonl` with `subagents/`, `<run>/work/<cid>.optimizer.stderr`, the file named by `$CAPEVOLVE_OPTIMIZER_TRANSCRIPT`, agent mode `<run>/host/transcript.jsonl` and conductor `*.transcript.jsonl`; other CLIs: their own session stores (`registry.yaml` rows); also `/tmp/claude-<uid>/`, `~/.claude/file-history/`, `~/.claude/session-env/`; **CI** (volatile, wiped by the next run of the same tier×bench): `ci/benchmarks/.work/suite_<tier>_<bench>_proj/.capevolve/run_suite/` and `ci/benchmarks/.work/suite_<tier>_<bench>/` (`runmeta.json`, `metrics.jsonl`, `steps.jsonl`, `report.md`, `reward_metric`), cache `${CAPEVOLVE_CI_CACHE:-~/.cache/capevolve-ci}`; **CI runner capture dirs** (made only for a run dispatched with `raw_data_location`, and removed once uploaded to the CI raw-data area and checked, so present only for legs whose upload failed; volatile: removed by the runner's admin to free disk once a backup recorded them as uploaded and checked; the leg is skipped when the runner has under 20 GB free) `~/capevolve-ci-capture/<run_id>__<tier>-<bench>[.a<N>]/` (`<name>.tar.zst` or `.tar.gz` holding `suite_<tier>_<bench>/`, `suite_<tier>_<bench>_proj/.capevolve/` and, when the run sealed data, `suite_<tier>_<bench>_proj.sealed/`; `members.sha256`, `symlinks.txt`, `unreadable.txt`, `backup.json`; an interrupted `*.partial/` dir is not a source; `ci/benchmarks/lib/backup_run.sh`), and the earlier runner archives `~/skillberry-runs-backup/user/<GitHub login>/<repo>/<run_id>__<tier>-<bench>.tar.zst` (2026-11-18 on; a source in CI's own layout, never copied into the backup location as is); unpack and verify both as `docs/FULL_BACKUP.md` §5.5 says; **CI optimizer transcripts** on the runner `~/.claude/projects/<slug of ci/benchmarks/.work/suite_<tier>_<bench>_proj/...>/` (shared by every run of that tier×bench); RITS proxy log `$RITS_PROXY_DIR/proxy.log` (a `mktemp -d`, volatile) |
| Sources | **CI raw-data area:** the rclone path given as the `raw_data_location` dispatch input (`.github/workflows/benchmarks.yml`), per leg `<path>/<run_id>__<tier>-<bench>[.a<N>]/` with the same files as a runner capture dir; the run's `ci_runs/<run_id>__<tier>-<bench>/backup.json` names the leg's dir in it (`staged`), not the path; path and read access: ask the user (`docs/FULL_BACKUP.md` §5.3(b)); a run dispatched without it keeps no raw data (its run dir is a `lost` gap); **CI runners:** the capture dirs (a leg whose upload failed: `kept_on_runner: true`) and earlier archives under External state, on every self-hosted runner (`RUNNER_NAME` in `backup.json`); **CI artifacts:** `benchmarks-<tier>-<bench>` on the workflow run (expire after 90 days; files cut to 256 KiB; often absent since 2026-11-18, when self-hosted uploads began to time out); **git** (snapshot by commit, `docs/FULL_BACKUP.md` §5.2): in the bench's `skillberry-runs/<repo>` (repo from `skillberry-runs/dashboard` `sections.json`) `ci_runs/<run_id>__<tier>-<bench>/` (README, `report.md`, the CI run record `runmeta.json`, `metrics.jsonl`, `steps.jsonl`, `final.json`, `capability.diff`, `optimized_capability/`, `recipe/`, the capture's `backup.json`) and `ci_ui/<run_id>__<tier>-<bench>/`; `skillberry-runs/dashboard` `records/<run_id>__<tier>-<bench>.json`; `skillberry-runs/live` branch `<run_id>__<tier>-<bench>` (volatile: deleted when the job ends); retired `benchmark-history` `records/<run_id>__<tier>-<bench>.json`, `runs/<run_id>__<tier>-<bench>/`, `live/<run_id>__<tier>-<bench>/data/`; **posts:** the benchmarks workflow's PR comments, tracking issues named in run docs; **ledgers:** model-gateway usage ledgers (RITS, `ibm-ete-int`, `ibm-ete`) are not stored in the repo: ask the owner where they are, else a gap with `may_exist_at` = the gateway |
| Reproduce | code: the run's commit (`runmeta.sha`, `state.json` start time); environments: the `CAPEVOLVE_PY` venv freeze, `python -V`, the optimizer CLI version (`claude --version`); inherited config: `~/.claude/settings.json` and project settings (redacted); unpinnable: model endpoint backends; smoke: `cap-evolve check` |
